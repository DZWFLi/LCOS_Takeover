# Policy: Layout Recipes（确定性坐标规范）

来源：huabu layout-recipes.md 借鉴（20260826 晚任务一）。
适用：Agent 创建多个画布节点时（Curator 整理、Run 产出、对话沉淀、批量导入）。目标：跑出来的节点**排列整齐**，不是散点。

## 坐标基线

- 标准节点约 **180×100**（LCOS 主画布标准卡），节点间距约 **50px**；纯文本/便签可窄。
- **`position` 必填**：Agent 建节点必须给显式 (x, y)。不给坐标 = 违规（引擎 fallback 会产生堆叠/跑出屏幕）。
- 坐标相对当前 Scope/画布原点；成组内容以组锚点为基准推算。

## 五种坐标模板（给死公式，Agent 照抄）

| 布局 | 公式 | 适用 |
|---|---|---|
| 层级自上而下 | `y = 0,150,300…`（层距 150）；层内 x 展开 | 组织架构/决策树/系统分层 |
| 左到右流程 | `x = 0,230,460…`（步距 230）；步内 y 展开 | 流水线/时序/剧本分集 |
| 网格 | `x = col*(180+50)`，`y = row*(100+50)` | 目录/对比/状态板 |
| 成对并排 grid | 同一 row 放配对项（左列=原件，右列=译文/答案/摘要），**无对应项的列跳过该 row** | 原件↔译文、问题↔答案、文献↔摘要 |
| 扇形径向 | 中心 (cx,cy)，N 子节点半径 r 环上均布 `θi = 2π·i/N` | 头脑风暴/主题发散 |

## 排布原则

1. **边是噪声**：能靠排布隐含关系就不画边。一列整齐节点本身就表达「这些是一组」；只有布局看不出的关系（跨组依赖）才连线。
2. **组名可缩读**：成组时给组一个清晰短 label（走 node-labeling 规范），保证缩小时认得出这是哪组。
3. **灰色弱化**：次要/参考材料用弱化样式，别和主线抢视觉。
4. **对齐后处理**：批量节点建完后做行/列对齐与均匀分布（≥3 节点才做 distribute）。

## 与既有 Curator 规则的衔接

- reorganize 默认 preservePinned=true 不变（destructive-layout.md 仍生效）——本规范管**新建**节点的落位，不管重排已有。
- 位置冲突时让位顺序：manual pins > 本规范模板 > 引擎默认。
