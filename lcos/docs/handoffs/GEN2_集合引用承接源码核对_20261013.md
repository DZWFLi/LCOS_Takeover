## Scope 误认的具体失败场景

同 Project 同时有 Collection(id=X) 与 legacy Scope(id=X)，其成员不同。前端放开 `{kind:'collection',id:X}` 后，当前 Assembly 的两个 aggregate 分支会 `getScopes().find(id===X)`，从而往目标 Presentation 写 `{type:'scope',id:X}` 或写 conversation_context 的 Scope endpoint；真实集合及其成员没有被承接，UI 却可能收到 applied。若没有同 ID Scope，则所有真实集合引用失败。普通 typed Collection 分支、项目归属校验和测试足够挡住，不需新 hash/baseline/gate。

## 最小改造步骤

1. **真实空间身份先行**：Presentation entity union 增加 collection；原 Curation 归属验证查 getCollection；Assembly Collection 单独查该实体。worksiteProjectionInput 从原 Presentation 得 collectionIds，原 reconciliation 投影明确收到的集合，继续 nodeProjector/binding/body。保留原 ChangeSet/Undo、placement 和来源位置。不放开前端先跑错误 Scope 分支。
2. **临时与长期分开**：临时引用在原 RunReference / parser / toRunReference 增加 `{type:'collection',collectionId}`，保留单个集合 chip 和原草稿顺序/移除/项目隔离。库与原 Canvas 接同一地址，不展开 Selection、不切 Receiver。长期映射在原 Relation 增加 Collection endpoint，原 Assembly 写 conversation_context，原 readBound/merge 派生该 ref，继续原 ConversationSession 身份桥。
3. **两发送 owner 共用成员解析**：Core 从 getCollection/listCollectionMemberships 派生有序内容；保持 caller Collection identity 和每条成员来源路径。同 Project 验证、nested collection、重复与循环在解析层处理；缺失/不可读/未实现类型整体明确失败，不静默传支持子集。成员七种类型没有全部内容 owner 已验证，不能先宣称全部可发。
4. **重试复用已有证据**：Collection 成员本身无 revision locator，不能假装知道用户过去见过的版本。首次发送在原 manifest/message journal 中记录实际成员、确切 revision；同 messageId 重试用首次证据，不从最新 membership/currentRevision 重算。ProviderContextResolutionEvidence 用普通 union/成员数组表达聚合来源，旧 artifact/view evidence 保持兼容。保留既有 hash/文件校验，不新增 hash、冻结或门禁。
5. **最后接 UX 并撤错误兼容**：完整 producer/consumer 测过后才能放开集合携带与引用。保留未接类型的失败、原输入、恢复入口；不能删除披露算完工。仅改一条链不能关闭 D02。

## 必测断点

- 同字符串 ID 的 Collection/Scope 不混淆；空间 membership、临时 ref、长期 Relation 都指真集合。
- Collection → Main/Context/Workflow 重读/重启同 identity、原 body；Undo 撤目标会员而不删集合及成员，来源保留。
- 库、原 Canvas 右携带、Ctrl 点取加入同一集合地址；不展开 Selection、不换 Receiver，混合整组不丢其中集合。
- Composer 只动本次草稿；Conversation body 写长期映射且重复幂等；Project 切换后旧异步结果不污染新草稿。
- 含两个文本成员实际发送包含两者内容和来源；不复制内容 Artifact、不只选首成员、不新建 membership 真值。
- 历史显式材料优先；nested、重复路径、空集合、循环处理有一致可重放规则。
- 任一缺失/foreign/不可读/未实现类型/超额度时不 create Run、不 attach、不 send；原草稿/选择保留，明确错误。
- attach 后改 membership/currentRevision，同 messageId 重试仍是首次成员/版本；不可取时停止，不重复创建外部会话。
- 移除 chip 只移草稿；删 projection 不删实体或长期 relation；旧 artifact/view/scope/workspace 无回归。
- 实际 Core HTTP + SQLite 重开、两实际发送 owner、原 Canvas 操作及整页刷新；isolated mock/types/接口 green 不能证明整个 D02 完成。
