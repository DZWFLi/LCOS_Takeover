## 验证与实际边界

147 个不同用例通过：原相关组件回归 121 项，来源操作 4 项，协作投影 22 项。来源改动后另外重跑了原 Reader 的 35 项；没有把重复运行累计成新覆盖。

- GUI 与 web-gen2 两处类型检查通过；`git diff --check` 通过。
- 桌面原组件：32px 行、24px 独立选择区、24px 缩略图、28px 更多按钮；实测选择区右端 x=64，缩略图左端 x=72，彼此分离。
- 触屏原组件：44px 行与操作区；选择区右端 x=80，缩略图左端 x=88，彼此分离。
- 浏览器真实操作：缩略图双击、标题双击、Enter 共 3 次阅读回调，单次勾选只触发 1 次选择；菜单阅读及确切候选版本打开通过。
- 896px 下助手被阅读页隐藏后，入口 `aria-expanded` 从 false 变 true；复用同一个助手窗口，没有新增副本。
- 原 Reader HTTP 只读样例：分别读取 `file-current`、`file-old` 的正文，版本菜单展开、切换、收起、Esc 均通过；请求全部为 GET。
- 浏览器实测导航及 Pin 为浅色 22px 磨砂；Dock 为 M2 11px 磨砂，光波区域 64px。检查覆盖 1200、896、480px 和触屏媒体条件。
- 最终组件验证没有 JavaScript 页面异常。缺少真实后端时仍有项目事件连接的网络错误；不把它写成控制台全无错误。

浏览器测试加载的是生产源码、生产控制器和既有状态 owner，以本地只读样例隔离后端。样例不是新的产品壳，也不是正式项目验收。验证中补齐了 Router、受控选择、Vite 精确模块地址和测试项目已保存窗口清理；这些样例问题修正后才计入通过。
