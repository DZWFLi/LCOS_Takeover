# GEN2 Wave 10：原会话续聊产品闭环

## 结论

Conversation Work View 里的“继续当前会话”已接入真实产品链路。它复用同一个 Composer，把提示词送回已绑定的 Huabu / ACP 原会话，不会退化成新建 Run；Provider 返回的 user / assistant 两条消息写入 Core 唯一 Conversation 消息表，并进入现有 Collaboration Timeline。

## 变更前

```text
Conversation Work View
  → Composer
  → delegate
  → 新建 Run

Continuation sendPrompt
  → 已能到 Huabu / ACP
  → responseText 没有产品 HTTP caller
  → 没有写回 Core Conversation
```

## 变更后

```text
Conversation Work View / Conversation Action Arc
  → 同一个 Composer（intent = continue）
  → CoreCollaborationClient.send
  → POST /connected-conversations/:id/collaboration-send
  → 校验 exact continuation operation + canonical session
  → 预留 caller-owned messageId
  → ConversationContinuationService.sendPrompt
  → Huabu Host / canonical ACP owner
  → ConversationImportService 完成 user + assistant turn
  → conversation_messages
  → Collaboration Timeline / SSE refresh
```

`intent = delegate` 仍走 canonical Run，两条产品动作不互相 fallback。

## 实际范围

- Contracts：发送命令增加 `messageId` 与 `continuationOperationId`。
- Local Core：新增产品 send route、消息预留/完成/失败释放、Timeline 消息投影、会话级 `canSend`。
- Web Gen2：`CoreCollaborationClient.send()` 接真实 Core HTTP。
- Huabu Web：统一 Composer 支持 `delegate | continue`；Work View 提供继续与委托两个明确入口；conversation Action Arc 不再把继续伪装成 Run。
- Context references 尚未接 continuation attach；存在 refs 时 UI 与 Core 都会诚实阻止，不会静默丢失。

## 幂等与失败语义

- 每条提示词使用 caller-owned `messageId`。
- 重复提交已完成 turn：直接返回既有消息，不再次调用 Provider。
- Provider 明确失败：释放 pending reservation，允许安全重试。
- timeout / `outcome_unknown` / `unresolved`：保留 pending reservation，禁止盲目重发。
- Provider 已报告 sent 但 assistant text 缺失：视为结果不完整，保留 pending，禁止重复发送。
- Composer 成功后继续保持打开，并轮换到新 `messageId`；失败时保留原 ID 和草稿。
