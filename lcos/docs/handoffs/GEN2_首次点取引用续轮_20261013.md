# GN2 首次点取引用续轮

更新：2026-10-13。目标继续施工；本轮不是整机验收。

## 结论

未登记的原生图片、文本现在可在有效 Ctrl／Cmd 点取松手后，直接走原材料认领与引用流程，不必先拖一次。没有删除不支持提示来冒充功能完善。

本轮同时修了三处实际流程问题：

- 引用准备期间不能抢先发送；发送期间不能再修改点取引用。
- 连续点取按用户次序交付，较慢材料不会排到后面；不同输入分别排队。
- 取消、关闭再重开、切项目／画布／输入、续聊滚到下一条消息后，旧请求不向新草稿投递。已经保存的材料保留。

## 六字段施工记录

- READ_SOURCE：原 lcosRecognizers、nativeCanvasDropGeometry、resolveNativeMaterialSources、registerNativeMaterialSources、projectTextCreation、referenceSnapshot、referenceController、lcosReferenceState、LcosComposerHost／lcosShellStore；原参考与材料认领调用均逐项查看。
- ADOPTED：有效显式点取 → 同一 source producer → 精确原载体引用 → 原 ordered draft；共享输入 owner 的临时 preparing／sending → 原 canSubmit 和即时 submit；原 finally 释放，不另建发送流程。
- VISUAL_SOURCE：本轮承接现有浅色界面，仅在准备阶段显示「正在准备材料引用…」；没有换深色，也没有把材料故障提示隐藏。
- RETIRED：未登记图片／文本只返回未保存提示、必须先拖一次的缺失接缝；准备期间抢先发送、按网络速度排序、取消后弹文本编辑焦点。未支持类型和实际失败仍有反馈。
- VERIFIED：下表范围内验证通过；实际用户后端和整页 writer 未挂载，不扩张成整机完成。
- UNRESOLVED：D01-C 整页实际后端验证、集合／Capture／来源引用、非文本 Run、完整模型／语音、原数据库运行承接和总 GUI 清单继续在册。
