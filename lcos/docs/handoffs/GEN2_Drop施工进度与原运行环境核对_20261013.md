## 这一批已接入的代码

- 外部多文件导入：原 Import Copy 保存后，将真实 View 加入捕获的当前 Workspace，解决 Context/Workflow 的材料遗漏和已有材料复用问题。
- 部分失败：后续导入失败仍刷新已保存材料，并报告准确保存数量；不会把整批说成全失败或全成功。
- 页面切换：读取后校对捕获的项目/现场；上传已经发生时只完成原目标的成员登记，不把后续文件写进新现场。
- 外部纯文本与剪贴板文件：复用现有 canonical text/file producer；无法读取的 OS 文件保持原入口，不能拿文件名制造文本节点。
- 项目库勾选的多个文件：整组接入原 Semantic Drop payload、resolver 和 pointer transport，保留每份材料的 View/已显示版本；缺失或身份模糊时整组不启动。
- 一次指针只有一个驱动入口：库携带的临时 transport owner 避免画布 observer 再次推进/提交同一组材料，退出/失败清理后不影响下一次画布拖动。
- 单件未固定版本 View：补全原 Artifact 地址和文件类型，仍然保留 View 地址，不猜最新版；错误的父材料地址拒绝取用。
- Reader 摘录拖入／粘贴到 Composer：复用原 MIME、草稿和引用 owner，插入当前输入位置，保留前后文和原接收者，引用固定在正在阅读的版本。错误、跨项目和已切换输入不修改草稿。
- 普通摘录呈现只显示材料标题和选中文字；精确身份留在结构化引用与可展开来源详情。「带来源复制」这个明确的跨应用动作仍携带版本地址。
- 成员回执按真实 `WorkspaceMembership.artifactViewId` 校验，避免把请求字段 `viewIds` 和响应字段混用。为此追加了真实 Core HTTP 测试。
- Capture／来源库多选：沿用原 `capture`／`resource` 身份和既有 materialize producer，整组进入原 Drop；Composer 不支持的来源整组拒绝，未用可支持的单件替代整组，也未宣称这些来源已经可供 Run 读取。
- 库卡片按内容分配高度：图片、视频保留实际比例；文本与非媒体占位使用自然高度。相同样例的文本卡片从 222px 减到 183px，正文从 11px/17px 调到 13px/19px。触屏上重复的快捷预览按钮收起，但同一阅读回调保留在材料行双击／Enter 和更多菜单，不能计作新增阅读能力。
- W03 普通连续阅读：新材料加入已有 Reader 阅读组；三个材料使用一个区域的三个页签。精确版本、阅读位置和原窗口几何保留；已有主动分屏、拆窗保持独立。
- W05 分屏管理：先把左右／上下分屏、合并与拆出当前组接到同一个窗口顶部菜单，再删除正文底部旧管理区。复用原窗口命令、原 DropdownMenu 和 Esc 栈；两侧阅读组都可拆出，窄屏仍可合并恢复，Esc 只关菜单并归还焦点。
- 来源文件失联仍显示明确提示和真实正文读取错误；只把「Reader／Core 回执／revision」话术改为原文件、已保存版本等用户可理解的表达。
- F02 助手历史保存：选好已有项目会话后，一次点击依次读取原线程历史、完成原导入、核对目标、关联并打开会话。仅保存项目历史的原能力继续保留。关联失败可复用已保存记录重试；中途切换现场不继续关联；错误回执不打开其它会话。重载后也可选择待关联的已保存历史：原 listSessions → 原 originMeta.nativeThread 精确地址，不按标题／时间猜，不自动覆盖当前新历史，不重复导入。
