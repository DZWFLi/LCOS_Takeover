# 原生组件与设计语言逐状态接回表

2026-10-26。只读研究报告。本轮没有改产品、重建 UI、启动服务、提交表单、发送模型或写业务数据。

## 结论

当前问题不是缺少设计原件，而是**TapNow 原容器、LCOS 后接的业务 leaf、自有光效没有接成同一套可见状态**。原 Composer／侧栏／库的大框架确实在用；但 task、权限、恢复、续聊选项和 Scope 成员分别来自不同 leaf，字体、边界、间距和失败反馈没有共同的呈现规范。

**彩色光波目前没有在当前常用界面生效。**浅色变换只是 paint 映射，不会自动挂光波。Glyth 形体有真实动效；光波思考气泡没有进当前 bundle。Dock 只用了静态玻璃表面；语音胶囊的下沿光入包，但语音能力未接，常态看不到。

**通用 GUI 标记／高亮／光环不绑定阶段、Run、版本、方法或工作流。**它们应服务任意节点的查看、选择、强调与导航。全部工作 loop 放 Workflow；常用基础 GUI 独立可用。持久领域 Color Pin 的身份／事务保护继续保留，不能把它等同于通用视觉强调，也不能为一圈光先造任务。
