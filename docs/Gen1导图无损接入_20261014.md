# Gen1 导图无损接入

## 结论

已新增一个按编辑器实例绑定的 Markdown source-map codec，复用现有 MindMapEditor 的 `OutlineNode[]` 和保存回调，不加第二正文 store。旧 `outlineTree.serializeOutline(parseOutline(source))` 会把标题、粗体/高光、空行与代码围栏压平或丢掉；新 session 在 no-op 时逐字节原样返回，编辑时只改对应可见行，未映射的完整源片段仍留在原文。

现在 codec 与两份 copied-source 的 in-memory transform 都已准备好；copied `lcos/` 文件本身仍未改。Root 还需在 `buildPilotEntry` 的 `sourceTransforms` 同时映射 `MindMapEditor.tsx` 和 `LcosTextFaces.tsx`，然后才能算进 UI bundle。转换结果会开放 fenced-document map editor，但不代表浏览器/Core 写回已验收。

## 新增文件与接口

- `lab/pilot/native-outline-source.ts` 导出 `createOutlineSourceSession(source)`。每个 editor 实例各持一份只读原文映射；接口为 `parseOutline()`、`serializeOutline(roots)`、`serializeBranch(branches)`、`cloneBranches(branches)`。
- `scripts/native-outline-source.test.mjs` 先实际调用当前 `outlineTree.ts` 重现旧序列化损失，再验证 session 的 no-op、行编辑、层级、复制/剪切语义、fence 与混合 CRLF。
- 测试命令：`node --experimental-strip-types --test scripts/native-outline-source.test.mjs`；当前 10/10 通过。
- `lab/native-outline-transform.mjs` 导出 `transformNativeOutlineEditor(source,{sourcePath})` 与 `transformNativeTextFaces(source,{sourcePath})`。它们只返回内存中的 TSX，不写 source；sourceMap helper import 用 `path.relative(dirname(sourcePath), workspace/lab/pilot/native-outline-source.ts)` 生成。
- `scripts/native-outline-transform.test.mjs` 验证两个 source transform、sourcePath/相对 helper resolve、exact-once anchors、幂等重复调用、部分/重复安装与 source drift 拒绝；并用现有 esbuild 对变换后 TSX 解析、bundle helper。
- transform 测试命令：`node --test scripts/native-outline-transform.test.mjs`；当前 3/3 通过。

节点源映射挂在 enumerable symbol 上，现有 `{ ...node }` 的 `updateText/addChild/addSibling/removeNode/liftNode` spread 会继续携带它；数组级属性不会被依赖。`cloneBranches` 会为整棵子树分配新的 editor-local `id` 并保留源行 provenance。它们只是导图解析身份，不是 Core Artifact、View 或任何材料 ID。

## 精确接线 seam

1. Root 在 `buildPilotEntry` 中为两个 copied-relative paths 配置 `sourceTransforms`：`lcos/huabu/apps/web/src/lcos/nodes/text/MindMapEditor.tsx` → `transformNativeOutlineEditor`，`.../LcosTextFaces.tsx` → `transformNativeTextFaces`。build 插件按真实 `sourcePath` 内存变换；不可与同路径 source override 并用。
2. MindMapEditor transform 用 mount-scoped lazy state 创建 `createOutlineSourceSession(outline)`，初始 roots 从同一 session 解析。这里使用 lazy `useState` 而非随 `outline` prop 变化重建 session，避免外部 prop 刷新时旧 roots 配新映射、误写错源；草稿由原组件 state 保留。
3. 保存调用同一 session 的 `serializeOutline(nextRoots)`；原 clipboard 使用 `serializeBranch([branch])`，paste 使用 session `cloneBranches(clipboard)`。原 MindMapEditor state、callbacks、history 与 canonical `onSave` 均保留，不新建历史栈或正文副本。
4. `LcosTextFaces` 拖出分支在 `startBranch` 内为当前 markdown 建 source session，以既有 outline 临时 `id` 找 branch 后调用 `serializeBranch([branch])`；创建的新文本不携带文档级游离 fence。
5. 原 copied `LcosTextFaces.tsx` guard 仍保留；只在两个 transforms 一起配置、session 三条 MindMapEditor serializer 路径都在测试 bundle 中、fenced source 测试通过后，in-memory transform 才把 guard 收敛为 `Boolean(onSaveText)`。保留现有 `onSaveText`、`disabled` 与其它入口保护，不改 Core 写入/CAS。

现有真实 owner 位置：`MindMapEditor.tsx` 原始初始 roots、clipboard、paste、canonical save 在此前列出的 useState/callback/save seams；fenced guard、拖出提取和 `onSaveText` 在 `LcosTextFaces.tsx`。本轮未改这些 copied `lcos/` 文件；Root 负责把两 transform 注册进 build sourceTransforms。

## 保真和边界

- 不改树形时，原文直接逐字节返回；验证包含 heading、粗体、高光、标签、空行、fenced code 与混合 CRLF/LF。
- 有实际修改时，未改的 heading/list 前缀、原行换行符、inline 标记与行内容保留；新增行使用源文件首个换行符。对已映射的粗体/高光节点标签做最小文本 diff，并把未变化字符的格式映射到新文本。
- 空行、fence、代码内容、纯标签行等不显示为树节点的行保存在 session 的 opaque chunks。若相邻节点删除，按最近原始可见行锚定；所有可见节点都删除时仍按原顺序输出所有 opaque chunks。
- 复制分支只序列化所选子树，不会把同文档内的代码块/空白段一起复制成新项目文本。
- 新节点不能表达当前 editor 未提供的 tags 编辑；无效 tags、新文本中会被解析成 tag/强调标记的写法会明确报错，不静默改字。未实现的 inline Markdown（链接、行内代码、HTML、删除线、引用/表格符号等）在原样或无关行改动时完整保留；直接编辑该类节点标签时 fail closed，提示回正文视图。
- 这不是完整 CommonMark parser。未识别的行仍由现有 Gen1/GN2 outline parser 投影成可见节点；session 只保证保留未改源片段，并对无法安全映射的节点文字拒绝保存。用户显式删除可见节点会删除该源行，未显示的 fence/opaque 内容不会被导图删除操作带走。

## 验证结果与未覆盖项

当前 codec 测试由 node 直接导入实际 GN2 `outlineTree.ts` 作旧行为对照，10 组均通过：旧损失复现、no-op bytes、标题/inline mark/标签/空行/fence/混合 CRLF 编辑、层级提升、标签变更、新增子/同级、子树 clone/branch serialization、原节点移除后的 cut-paste、全删后保留 fence、不可映射 Markdown fail-closed。source transform 测试 3 组通过：包括双路径组合的接线检查与 esbuild TSX parse/bundle helper；它不是整应用 browser bundle 或真实 UI/Core 证据。

本轮没有运行浏览器、服务、Core 写入，也没有改 copied `lcos/`。仍需 Root 注册双 transform 并做真实宿主 Main UI 与 canonical Core save 验收；测试通过只证明 codec/transform source logic，不冒充 end-to-end。
