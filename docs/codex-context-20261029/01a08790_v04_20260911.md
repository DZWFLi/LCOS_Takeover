标准协作链是：

`​``text
Figma Variables / Tokens
+ Components / Variants
+ Auto Layout / Constraints
+ Prototype 连线
+ Assets
+ 响应式与异常状态说明
↓
前端映射现有代码组件
↓
接真实业务状态和交互 Intent
↓
视觉 Diff + 行为 E2E + 无障碍验收
`​``

前端通常通过 Figma Dev Mode/Inspect 读取：

- 组件层级与 Component Set；
- Variant 属性和全部状态；
- padding、gap、尺寸约束、Auto Layout；
- 字体、颜色、圆角、阴影对应的 Variables；
- Prototype 的点击、浮层、切换和动效；
- SVG、图片等正式资产；
- 具体 node ID，方便设计与代码逐项对照。

但 Dev Mode 给出的 CSS 也只是参考，不能整段复制。前端仍要结合 React 组件、响应式、Canvas transform、业务状态和现有设计系统实现。

在 GEN2 这里，我们已经不只是看截图了：

- Figma 有 **16 个 Component Sets、153 variants 和 node ID**；
- `components.json` 提供状态、尺寸、文案、动作索引；
- `qa.json` 提供断链、溢出和组件检查；
- T5 V4 已建立  
  `Figma node → producer → mapper → container/caller → intent → receipt`；
- T1–T7 已分别核过宿主、导航、交互、容器、Core 状态和 Adapter。

正式施工时还要补：

1. 直接读取 Figma Variables，并映射现有 Gen2/Oreo tokens，不能截图吸色。
2. 实现每个 body 时查看对应 Component Set、Auto Layout、variants 和 prototype。
3. 在真实 Huabu 页面渲染后，与 Figma node 做 overlay/pixel diff。
4. 另外跑键盘、Esc、权限拒绝、网络失败、迟到回包、响应式和读屏测试。

所以截图的正确用途是：

> **实现完成后的视觉回归证据。**

它不能承担组件规格、状态来源、响应式和交互契约。

[GEN2_Figma与前端标准协作方式_20260911.md](</E:/Codex 项目/OS开发/docs/audit/GEN2_Figma与前端标准协作方式_20260911.md>)
