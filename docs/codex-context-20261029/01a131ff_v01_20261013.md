**Codex：**

```text
\# TapNow“去云留肉”判断

\## 结论

**能去，但不能简单把所有云端请求一刀断掉。**

你的“杀鱼放血、去内脏、留鱼肉”比喻基本对。只是 TapNow 这条鱼有点赛博：部分血管已经长进鱼肉里了。

正确做法是：

> **先阻断它对 TapNow 云端的写入，再给必要接口接临时假血泵，让界面活着；最后逐块切出不依赖云端的 UI 肉，接到 LCOS。**

如果直接拔网线式处理，前端很可能卡在登录、初始化、功能开关或加载状态，连肉长什么样都看不到。

\## 哪些东西比较容易去掉

这些大多是独立路由或外围服务，切除难度不高：

- 支付、Tapies、订阅、账单
- 社区、学院、营销活动
- 官方首页与推广内容
- TapNow 自动更新
- Sentry、Statsig 等统计和功能实验
- TapNow 品牌、登录推广
- App Store 中 LCOS 不需要的部分
- TapNow 云端网络诊断
- Google/SSO 登录回调
- `tapnow://` 深链

处理方式主要是：

1. 不注册对应路由。
2. 删除导航入口。
3. 停止动态加载相关 chunk。
4. 把遥测初始化改为空实现。
5. 用 LCOS Desktop 更新机制代替 TapNow updater。

这部分属于“鱼鳞和内脏”，比较好清。

\## 中等难度

这些看着像 UI，实际上已经连着 TapNow 数据：

- 个人库、团队库
- 文件上传和 CDN 缩略图
- 模型选择器
- 技能、插件列表
- 用户、组织和权限
- 收藏、文件夹、搜索和分页
- 图片、视频的版本与生成候选
- Feature Flag 控制的隐藏功能

不能只删除请求，因为组件通
……（省略 2194 字）……
ader 等页面需要换数据管；Canvas、Conversation、Generation 不能靠删除云端继续活。**

所以不要尝试把整条鱼洗干净后原封不动端上桌。最省力的方法是：

> **沿功能边界切鱼排：留下成熟 UI，剔除 TapNow store/API，再逐块接入 LCOS。**

这样我们能拿到大部分 TapNow 的实际体验完成度，同时不会把 GN2 变成一套永远追着 TapNow 更新补洞的寄生前端。
```
