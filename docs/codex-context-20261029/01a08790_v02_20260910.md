\## 能否做到“效果完全一致”

界面体验可以统一成同一个“续工”动作，但四种执行结果有细微区别：

| 模式 | 用户得到的效果 | 底层实际行为 |
|---|---|---|
| 继续当前对话 | 原会话继续工作 | 向现有 session 发消息 |
| 完整分支 | 新 Glyth 保留完整对话历史 | Agent 原生 Fork，例如 Codex `fork_thread` |
| 精选上下文续工 | 新 Glyth 带着指定材料和摘要开始 | 新建 session，再注入 Handoff / Context Snapshot |
| 空白新建 | 新 Glyth 从零开始 | 创建空 session |

如果 Agent 原生支持 Fork，效果最接近真正的对话分支。  
如果不支持，我们可以用“新建会话＋结构化上下文注入”实现几乎相同的**工作连续性**，但它并没有复制供应商内部的完整隐藏状态，例如缓存、内部摘要、工具调用状态和未完成 turn。

因此准确结论是：

> **产品层可以高度一致；会话历史和模型内部状态无法保证字节级一致。**

\## 大部分 Agent 产品能否适配

**可以。大多数本地或 API Agent 都能接入基础版，原生 Fork 只是增强能力。**

最低只需要 Adapter 提供四项能力：

`​``ts
interface ConversationContinuationAdapter {
  createSession(options): Promise<ExternalSessionRef>
  sendContext(session, handoff): Promise<void>
  sendMessage(session, message): Promise<void>
  getStatus(session): Promise<SessionStatus>
}
`​``

更完整的产品可以额外提供：

`​``ts
forkSession()
attachWorkspace()
createWorktree()
cancel()
resume()
streamEvents()
requestUserInput()
`​``

可以按能力分三级：

| 适配等级 | Agent 要求 | GEN2 能提供 |
|---|---|---|
| L1 基础 | 能新建会话并发送 Prompt | 精选上下文续工、空白新建 |
| L2 标准 | 有稳定 session ID、状态和恢复接口 | Glyth 绑定、导航、Run 状态、断线恢复 |
| L3 原生 | 支持 Fork、工作目录或 Worktree | 完整历史分支、并行施工、可靠来源链 |

Codex、Claude Code、OpenAI Agents SDK 类产品通常可以做到 L2–L3。普通聊天 API、Ollama 或轻量 Agent 至少可以做到 L1–L2。只支持一次性 Prompt、没有稳定会话 ID 的工具也能接，但 Glyth 只能表示一次执行端点，不能宣称为可恢复
