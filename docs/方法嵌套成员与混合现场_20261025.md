## 集合卡实拖修复与存量归位

存量两颗 pile 首轮都在原点，不能靠删掉重建掩盖。实际拖动又复现一个产品错误：原 `wFe/Xh` 围绕 canonical 中心放大显示框，但 `jVe` 把显示左上角当成保存位置，松手后再次减去显示偏移，造成跳位。当前两种真实偏移分别为 `(0,-52)`、`(-35,-51.444…)`，不是保存坐标损坏。

修复沿原 `jVe → O8/r6`：`LCOSNativePileCanonicalChanges` 第三参数接原 `BVe` 函数，只有精确 Core pile 的有效 position 事件才按批惰性求一次显示投影；用同批 raw－display 差换回原本地坐标。连续帧和带 position 的松手同样转换，只有 dragging 状态的结束事件原样；positionAbsolute 用相同差值，父容器偏移不重复加。普通 pile、不匹配的完整身份、重复／缺失显示行等不接管；原被动尺寸保护与明确 resize 路径保留。

纯 helper 与 source-executed 原 `BVe/wFe/Xh/Ir` 测试均通过：连续三帧、两次松手、父坐标／absolute、按批只求一次、普通及异常身份回退、原尺寸保护。未改原件、另设位置 owner 或另建历史。

真实鼠标先把原 outer 拖到 `(0,360.26)`，再把同一 inner 拖到 `(339.27,362.23)`。目标为 `(0,360)`／`(340,360)`；原屏幕缩放约 0.392，每 CSS 像素相当于 2.55 世界单位，落点按这一实际像素精度核对，没有用位置 setter。两颗原节点 ID、数据、尺寸、Core 关系／绑定不变，其余七节点几何不变。实际 wFe 显示矩形逐对检查 `displayOverlaps=[]`；随后原 Gallery 重进与刷新保持所有九节点和位置。
