# 普通颜色组独立命名：前端接线

日期：2026-10-28。本文记录本批原颜色组命名接线；不把受控源码专项当真实页面通过。产品源码已交 Root 统一构建，本文归档时未开启或修改活动浏览器、未发模型请求。

## 结论

普通节点不再为了给颜色组命名而需要先有 Core 成员。首次命名只创建同项目、同色的真实颜色 definition 和 label；没有 targetRef、membership、ArtifactView、Run 或 Workflow。以后沿原 definition ID、label、updatedAt 做原 CAS 改名。

GUI 继续使用 TapNow 原顶部颜色组 `w7 → y7 → m7` 的 inline 输入。原改名入口、原菜单、原取消/Escape、原保存焦点路径保留；新增窗口、Popover、可见按钮入口、project stream、名称 store 均为 0。原菜单说明“项目共享”，输入语义为“颜色组名称（本项目）”。同项目同颜色仍使用同一个名称；普通节点的颜色本身继续留在原 `data.color_pins`。

## 原件与保存 owner

- 原 TapNow `page-Da_DfwiK.js` 的 `u7` 将名称保存到原云端 Canvas config：`pin.color_groups[color].name`，由 `getCanvasConfig/updateCanvasConfig` 读写 `/:canvas/config`。该云端配置并没有在当前本地项目 owner 中接通，也不适合再复制成与 Core definition 冲突的第二份名字。
- 当前 raw-only 组没有 definition 是原分层的正常结果：它只有 Huabu 空间字段 `color_pins`。Core 原本仅在 assign canonical membership 时顺带创建 definition，因此不能借伪造成员来命名。
- 本轮 Core owner 由独立 Workflow agent 扩原颜色定义表、原事务/ChangeSet 和 typed client：`createDefinition(projectId,{color,label,expectedDefinitionId:null}) → {definition,changeSetId?}`。已有同色严格 409，不覆盖现名；existing definition 仍沿原 `renameDefinition`。没有新增表、hash 或 frozen contract。
- 原 definition-add 的 Undo 不能只检查“存在”：表的 FK 有 `ON DELETE CASCADE`，可能误删后来添加的成员。此真实边界由 Core owner 的独立专项处理，本前端不另写 Undo owner，也不凭 UI 通过替代该证明。

## 前端如何接

| owner | 实际行为 |
|---|---|
| `lab/pilot/native-colorpin-controller.ts` | 新 `createDefinition` 复用原 rename attempt、busy、ACK 和 unknown 队列；读到已存在同色时 adoption 最新事实并拒绝覆盖；已知 ID 的改名仍原 CAS |
| `lab/pilot/native-colorpin-port.tsx` | 只有原 client 实际提供该方法才传入 controller；参数仅 project/color/label/observed absence，不伪造 target 或 member |
| `lab/pilot/native-colorpin-menu.tsx` | 开始编辑时捕获准确项目、Canvas、API、颜色、当时的 definition ID/null 与 label/updatedAt；提交及结果回程仍核这个 owner |
| `lab/native-colorpin-page-transform.mjs` | 原 y7 保留可选观察参数，原 m7 inline 编辑把观察一直传到原 u7 adapter；cancel/reopen/unmount 使旧回调失效，晚到成功不关闭新输入 |

关键语义：用户在 raw-only 状态开始编辑后，别人先创建 definition，新的 render **不会**悄悄把预期缺失换成“已读新 definition 的 CAS”再覆盖名字。反过来，用户开始编辑已知名称后，别人改名，提交也仍带编辑开始时读到的旧 label/updatedAt，让原 CAS 拒绝并显示最新名称。

有准确新 definition ACK 时，controller 保留准确 ID；随后读失败或被其他人改名，原 GET 核对可以显示“刚有变化”并解除该已知 attempt。没有 ACK 或错误项目/颜色/名称的 ACK 不提供可信新 ID：保留 unknown，核对只 GET，不重发 create、不造临时成员。原组若已不在准确现场，或原 Canvas/API 已切换，不提交迟到命名。

首次命名没有 definition 且结果 unknown 时，原菜单仍有唯一“核对标记结果”行；读取失败仍用原“重新读取”行，不能只放一段要求核对的文案却没有入口。原 error/unknown 保留，拒绝保存时原输入与文字保留。

## 同批修正的原定位接缝

前轮 helper 已给 raw-only 组增加 scene/身份保护，但原 `p7` 调用者只在 `definitionId` 存在时调用 guard，导致 raw-only 跳过。此次调用者条件也扩为 `definitionId || rawNodeIds`。实际原 `p7` 负例证明拒绝后 0 `fitView`，正例证明合法 raw 原定位仍能执行，没有删功能掩盖问题。
