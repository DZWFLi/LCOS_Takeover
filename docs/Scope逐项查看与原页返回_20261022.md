# Scope 逐项查看与原页返回 · 2026-10-22

这批已接通：**原 Library 搜索行 → 原 TS 预览 → 关联 Scope → 每份图片／文字 → 原 Viewer → 返回同一 Scope／原成员**。继续接了“查看后加入当前输入”，保留原草稿、光标和确版引用。

没有新增 Stage 窗口、阅读弹窗或第二套路由。范围是 Context／Workflow 与其材料；集合、附注、对话等作为 Scope 成员时尚未全部接通，见后面的账。

## 现在能怎么用

1. 在原素材库搜索并打开已保存上下文。原来“另有 N 项关联内容”改为逐项入口。
2. 点材料，进入现有单一 Viewer；点关联 Workflow，在同一张原 TS 预览内进入它的方法和材料列表。
3. 阅读后可用原返回键或 Esc 回到刚才的成员；图片仍遵循原来的“先退出放大，再退出阅读”。
4. 关联 Scope 顶部的返回键回到父 Scope，恢复原成员焦点与搜索。没有独立 Workspace 时直接在原预览查看，不伪造现场。
5. 点“加入当前输入”，沿原引用流程回到同一 Composer。草稿和原光标保留，所选 ArtifactView／Revision 一起带回，消息不发送。

## 实际施工

| 断点 | 这次怎么接 |
|---|---|
| Context 关联 Scope 只显示数量 | 直接读取真实成员；关联 Scope 保持整体身份，进入后再读取其成员，不展平写回 |
| Workflow 只显示方法文字 | 同一原预览增加材料行，覆盖成员、步骤附件和分支目标；结构标记不冒充材料 |
| 材料阅读后返回地址丢失 | 原 Viewer 请求附带临时来源；返回原 Scope、原项和原输入，不新建持久窗口或草稿副本 |
| Esc 被底层原 Popover 消费 | 只给当前来源 Viewer 交接这次 Esc；放大／嵌套菜单／全屏仍由原 Viewer 处理，下一次普通关闭正常 |
| 入场／退场与快速重开竞争 | 旧画面的动画回调仅作用于它自己的当前 session；过期返回不抢新阅读焦点 |
| 进入子 Scope 后拖放目标仍按根行判断 | 仍走原 Drop registry，使用同一 TS 当前真实注册的 Scope 目标 |
| “加入输入”仍按普通返回走 | 明确区分浏览返回与取用返回；取用关闭当前预览并恢复原输入 |
| 确版取用只带回 Revision、漏掉 View | 补回已核验的 ArtifactView 身份，不更换所选版本 |
| 原来指向不存在现场的提示 | 改为准确的逐项查看指引；不支持的成员保留不可读说明 |

主要改动位于 `lab/pilot/native-library-contexts.tsx`、`native-library-scope-members.ts`、`native-library-reading-return.ts`、`native-library-preview-retain.ts`、`native-material-viewer.tsx` 及两个原组件转换接缝。继续使用原 Zp／TS／IQe／wa／c2／d2、原 Ke 与原 Composer journey。样式仍落在原 TS 的内容槽，延续浅色材质、原宽度与原滚动容器。
