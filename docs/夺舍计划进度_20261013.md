## 为什么路线成立，又为什么不能一刀切

前端确实包含大量可独立运行的界面与交互。此前实测调色工具能改变像素、按住比较原图、刷新恢复参数、切换分页与重置。这次继续证明原版 Canvas 和 Library 的部分界面能够吃本地协议。

困难在业务耦合，不在“画面完全拿不出来”：身份、组织、订阅、画布写入、素材文件、Agent、协作和 Desktop IPC 都有独立接口与状态。只改一个后端地址不足以交付完整产品。

安装包是编译 JS/CSS/HTML，没有原始 TSX 工程或 source map。此前整包以独立 runtime 对照；最新实验将少量原定义逐字提取，使用宿主同一份 React 和既有 Markdown/编辑器依赖，已经验证局部采用。仍需按模块厘清依赖，不能把整包直接当作可维护源码。

最新承接关系是：TapNow 节点呈现 → 现有 Huabu body seam → 原 CoreArtifactClient → 真实临时 Core。Core 继续是领域真值 owner，Huabu 管空间，未另造项目/素材真值。以下首轮记录为历史阶段，不代表新入口仍停在 fixture。

## 实际改了什么

- 增加仅绑定 127.0.0.1 的 Node 宿主，无外部代理。
- 启动接管在内存中修改返回给浏览器的主 bundle；reference/ 原件不改。
- 绑定本地合成身份与单个测试画布；不使用真实 token，不改旧浏览器存储。
- 只替换明确的 VITE_API_BASE_URL 为当前 loopback origin；其它上传与服务域名不作泛化转发。
- billing 初始化明确标记未连接：空订阅、模拟计数零。没有真实余额、付费或赠送权益。
- 实现 Canvas 目录、Library 文件夹、素材元数据及搜索的只读协议适配。当前服务必须明确启用 fixture；Core 未配置时不会偷偷回退假数据或探测旧端口。
- 已承接命名空间的写入返回 501，未知 API 返回 404；不假报保存成功。

## 网络与测量边界

最终冷启动使用全新无登录浏览器，service worker 禁用。BrowserContext 只允许精确的 http://127.0.0.1:17874，其余 HTTP 中止，WebSocket 全部关闭。页面 fetch 包装、CSP、外部 window.open 和普通链接点击也进行阻断。

这次测量窗口记录 8 次远端 fetch 尝试并对应 8 次阻断、3 次 CSP 阻断、3 次导航阻断；包含显式安全探针。没有观察到外部请求成功。context route 的 blockedHttp/blockedWs 为零并不代表没有尝试，因为页面包装和 CSP 会先拦住；报告已经包含这些逐条事件。

没有测试或实现 direct location.href/assign 的自定义协议保护。window.open/普通链接探针成功不能外推成任意协议都安全。也不能把专用测量浏览器的 route 保护外推到用户随手打开的普通浏览器。这里是私有本地实验入口，不是正式发布边界已验收。
