## 同址换阅读目标后的原焦点交接：只读复核

问题：More 选择 A/B 后同 id/type 的 c2 不重挂，原 root-only `onKeyDown` 可能因旧控件卸载后焦点落 BODY 而收不到 Escape。原 c2 第一个 focus useLayoutEffect 依赖 `[]`，负责首次捕获 h.current、focus原 root、关闭时恢复原 h.current。

不宜直接把该 effect 改成 requestKey 依赖：React 会先执行旧 cleanup，再跑新 setup。执行从只读原件 AST 提取的真实回调（只使用受控 focus target，没有浏览器或 Core）得到：原来源 inputA，更新前用户当前 inputB → 旧 cleanup focus inputA → 新 setup focus Viewer 并重新捕获 inputA → 最终关闭再 focus inputA。新增目标 ready 会主动抢 inputB，而且中间 focus inputA 可以进入原 Composer/Popover 失焦链。当前 Viewer owner 判断只核项目/画布/API/恢复帧，同项目同画布换输入不自动使此请求失效，不能靠该 owner 判断排除反例。

最小建议：保持原 mount-only 捕获/关闭回焦原逻辑；新增 controlled-only 的 requestKey 交接，仅当前 activeElement 仍在原 root，或是 BODY（旧控件卸载）时 focus 原 root。若用户已选择另一个真实输入/按钮则不迟到抢焦。不重新捕获 h.current，不触发旧 cleanup 的中间跳转。是否需要等原 phase=open 的真实交接点，依据 canvas 正在记录的实际焦点/key trace 决定；不先引入盲延迟或全局 Escape。

此项只读独立评估，未改原件、transform、产品或服务；是否实施与最终原页证据由 root 统一负责。
