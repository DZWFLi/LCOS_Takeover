# 导航游标与固定锚接回方案

日期：2026-10-26。范围：下一批施工设计；本轮只读产品源码，只新增本文档。没有启动服务、写业务数据或运行导航验收。

## 结论

建议接回三件彼此独立的东西：**Color Pin 管颜色分类，固定大头钉管长期记住目标，屏边游标管现在往哪走。** 外观沿当前 TapNow 原节点浮条、色组 Popover、小地图和浅色材质重新整合。旧 GEN1/GN2/HTML 样机不作为视觉答案；它们只提供已存在的目标解析、投影和返回行为证据。

最小完整链是：**从原入口选目标 → 固定／取消固定 → 随原节点显示 → 接近屏边渐变为方向提示 → 同方向拥挤时聚合 → 明确点击后沿原相机抵达 → 短暂光环反馈 → 可主动返回出发视角。** 相机不因 hover、固定、取消固定、关闭 Popover 或光环结束自动移动。

分两批施工：第一批完成当前现场的整条闭环，第二批完成跨现场、多个出现位置和高密度场景。不能把按钮亮起来、画一个箭头或沿用旧 HTML 壳当作完成。

## 1. 三件东西各管什么

| 能力 | 用户得到什么 | 真值与保存位置 | 不负责什么 |
| --- | --- | --- | --- |
| Color Pin | 给内容分颜色，按原色组查找和定位 | 当前 Core 的颜色定义与成员关系；仍从 TapNow 原圆点、色组菜单和组条操作 | 不自动等于固定大头钉；改颜色不改变导航范围 |
| 固定大头钉／空间锚 | 离开后还记得这个目标，重开后可找回 | 已有 canonical 目标使用 `SpatialMarkerIntentV0` 的 targetRef、scope、sourceSurfaceRef；Core 保存意图，Huabu 保存实际空间布局 | 不存屏幕坐标、箭头方向、相机缩放或 Run 状态；不因同名对象出现而重绑 |
| 屏边方向游标 | 不用缩小全图也知道已固定／明确选中的目标在哪边 | 由当前现场、原节点实测边界、原相机和安全视域即时计算；不持久化投影 | 不创建固定记录，不在后台偷偷换现场，不代替小地图 |

当前颜色分类已经沿原组件接入，但不等于完整的 LCOS 固定锚／屏边导航扩展已经接入。当前 host 挂载列表未包含旧 `LcosPersistentLocatorOverlay` 或全局导航岛；下一批需要的是小型适配与投影，不是再挂一套旧 HUD。[当前挂载入口](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-agent-ui.tsx:63>)、[Color Pin 原组件适配](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/native-colorpin-course-transform.mjs:13>)、[当前颜色能力来源](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-colorpin-port.tsx:81>)。

已有 marker target 仅支持 `view / entity / surface`，**没有任意空白坐标 target**。因此“把大头钉插在空白画布某一点”不能冒充已支持；本轮先完成“固定真实目标”的链。空白点若后续确实需要，先核对原 Huabu 是否已有可保存的锚节点，再用原节点的真实身份接入，不能写一个新坐标表绕开原空间 owner。[现有目标与意图](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/packages/contracts/src/navigation-marker.ts:17>)。

## 3. 身份、空间坐标和相机的单一归属

### 3.1 Core 负责“固定的是谁”

沿用现有读取、创建、删除和 resolve 路径；写入仍走现有 mutation safety。不直接读写 SQLite，不新建 marker 存储，不增加 hash、contract 或 gate。创建中仅显示 pending；服务确认后才显示已固定；失败保留选择，并在原菜单／列表中给出可重试反馈。[已有路由](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/routes/navigation-markers.ts:19>)、[GEN1 实际 reader/writer](<E:/TRAE项目/LCOS0.1收口/review/LCOS_前端按功能推进_20261003/sources/Gen1_3e99769/apps/web/src/features/spatial/ProjectSpatialMarkerContext.tsx:31>)。

`local` 对应来源现场范围，`cross-surface` 对应项目内可跨现场找回的固定目标。现有保护中的项目一致、准确身份和来源现场校验必须保留；这些是避免固定到另一个对象的必要条件，并非要求用户先创建任务。**Run、阶段、工作流、某次执行是否完成都不是导航和强调的前提。**

### 3.2 Huabu 负责“现在实际画在哪里”

当前 resolver 仍可能返回旧的 `ArtifactView.position`，Workspace 仍可能返回 `frameBounds` 中心；它们不能直接替换夺舍后原 Huabu 的实时布局。[view 分支](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/navigation-marker-service.ts:51>)、[Workspace 分支](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/navigation-marker-service.ts:118>)。

接入顺序必须是：

1. 每次导航重新 resolve，确认项目、目标是否存在与可进入的现场。
2. 从当前已有 binding／位置枚举中找到准确出现位置，接回原 `canvasId + nodeId + ref`；不可仅按标题或外观命中。
3. 等原现场和原 API 就绪，再读取当前节点、父级变换、实测尺寸及展示边界。组合／集合成员需使用实际展示位置，不能把 Core 语义成员关系当成物理父子关系。
4. 用原 API 做坐标投影、相机移动与返回；不把结果再写回另一套 Core 布局。

特别注意：Artifact entity 的 resolver 当前返回 `main` 和 anchorRef，只做身份解析，注释明确把实际 occurrence 留给既有 Focus／Where；不能把这个 `main` 直接当成实际出现现场。[Artifact 分支](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/navigation-marker-service.ts:132>)。同一内容多处出现时，在原小列表列出准确位置，由用户明确选择；无匹配时说明“尚未放到可定位的画布”，不偷偷创建投影、不跳到相似内容。

对于只有 surface 身份而没有节点坐标的目标：进入已有原现场，沿该现场原本恢复视角；没有节点就不伪造节点方向、边缘距离或抵达节点光环。Note 等无唯一空间坐标的 entity 也遵循此规则。[无坐标 Note 解析](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/navigation-marker-service.ts:150>)。

### 3.3 普通原节点的 GUI 不受 Core 接入进度牵连

原生节点的选中、强调、当前位置提示仍直接沿原 node 状态和原相机工作。瞬时强调不写 Core；持久强调使用原节点的窄范围呈现偏好，经原 `updateNodeData`、原 O8 保存／Undo，不拿 Color Pin 的 canonical 身份准入当作强调准入。

未建立 canonical ref 的普通原节点，目前不能冒用 `SpatialMarkerIntentV0` 伪造目标；若要提供持久本地大头钉，应以准确原 node.id 的呈现偏好经 O8 保存，只承诺“这张原画布中的这个节点”。它与 Core marker 不同时写入同一份固定意图，不自动升级成项目级语义目标。第二批需把这类原节点作为单独验收项；接不通就明确在册，不能顺手禁掉其选中／强调／定位。

当前 facade 对任意额外 `node.data` 写入有限制。施工只开放明确的视觉字段通道，继续保护内容、领域引用、版本和权限；不能为一个光环放开整份 data。[现有呈现写入边界](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/surface-core-facade.ts:1445>)。

## 4. 完整状态与操作

| 状态 | 画面与动效 | 点击／键盘结果 | 退出与保存 |
| --- | --- | --- | --- |
| 目标未固定 | 原节点与原选中外框 | 原更多菜单可固定；当前选择可出现临时方向提示 | 切换选择只清临时提示，不移动相机 |
| 固定请求中 | 原动作小型 pending，尺寸不跳 | 阻止同一目标重复提交；其他原操作可继续 | 请求失败不显示假成功；不反复重放 |
| 已固定且在近场 | 原节点角落轻巧大头钉，与 Color Pin 圆点分辨清楚 | 点击可打开同一原小列表或定位；取消固定保持节点和颜色 | 持久保存的是意图／原节点呈现偏好，不是屏幕点 |
| 接近可见区边缘 | 大头钉随节点向边缘连续过渡，透明度和朝向连贯 | hover 显示标签，点击才导航 | 不出现一枚节点钉加一枚完全重复的屏边钉；预览不驱动相机 |
| 目标在屏外 | 安全边界上的方向标，标签按可用空间显隐 | 定位前重新核对目标；保留现有选择 | 相机、窗口尺寸和左右栏变化时重算，不保存边缘坐标 |
| 同方向拥挤 | 数量聚合点；当前明确选中目标优先可辨认 | 原风格 Popover 列出成员，选一个再定位 | 合并仅限同现场、同边、投影相邻；不能把不同方向伪造成一个箭头 |
| 解析／跨现场进入中 | 发起入口显示短暂 pending，目标现场仍用原加载呈现 | 新请求替代旧请求；用户另切现场中止旧请求 | 不在背景追加相机操作；失败保持真实所在现场 |
| 抵达 | 节点外围短暂浅色光环，保持正文、图片可读 | 可立即拖动、编辑；原返回可用 | 光环自行结束只清 GUI；不写“完成／确认／accept”，不自动返回 |
| 可返回出发位置 | 同现场用原轻量返回动作，跨现场走原页头返回 | 明确点击才恢复捕获的现场与 viewport | 不恢复旧内容，不撤销用户刚做的编辑；有效返回后消费该次记录 |
| 目标删除／绑定过期 | 原列表保留“目标不可用”与取消固定，旧方向标不再指路 | 可移除记录；重试时重新解析原目标 | 不按同名对象重绑，不自动删除证据掩盖问题 |
| API／数据尚未接通 | 原入口就地显示具体缺口与重试 | 不承诺已固定／已抵达 | 记录原目标、断点与最近可复现路径；不另开调试窗口给用户 |

近场／屏边切换需使用节点外接矩形到安全视域的连续关系，并加入小幅滞回，避免临界点一像素滚动就闪烁。阈值以真实页面测量调定，旧代码的 `26 / 72`、密度半径等只作算法起点，不视为设计规范。旧投影已经把 local 留给节点、near-edge／edge 交给 overlay，可复用这种责任划分。[旧投影算法调用](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/navigation/LcosPersistentLocatorOverlay.tsx:61>)、[旧同向聚合约束](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/navigation/locatorDensity.ts:12>)。

## 5. 不遮栏、不抢相机、不误返回

**安全视域只有一个测量来源。** 复用当前 `visibleCanvas()` 对原画布、资料库、右侧对话和底部控件的真实测量，再补当前页确实可见的小地图、节点浮条、页头和打开的 Popover。读 DOM 可见性与实际矩形，不能沿用旧 HUD selector 后假装覆盖了新页面。Resize／显示状态／拖动变化合并到原渲染节奏；不额外常驻轮询。[当前安全视域](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-placement-client.ts:47>)、[现有屏幕避让](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/surface-dock-ui.js:157>)。

屏边标被工具遮挡时，沿同一条边让位，方向仍按真实目标计算；空间不足就聚合并用原小列表，不压进 Composer、不遮小地图、不让三个 HUD 互相追着挪。命中区域仅覆盖可点击标记，整层不拦画布拖动、框选、文件 Drop。

**所有相机操作只由明确导航／返回触发。** 当前 material locator 已有单次请求替换、取消、二次核对及“用户切往第三现场就不拉回”行为；扩到 marker 时复用这些行为，不照搬其中仅针对 Artifact 版本的准入条件。相机抵达必须用最新原 API 与当前准确节点，而不是异步开始时缓存的旧 API。[现有导航生命周期](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-navigation.ts:42>)。

原定位 helper 已会依据可见区域居中，并调用原 `setViewport`／`fitView`；接回时统一用这一能力，跨现场导航现有分支直接 fitView 的部分也要适配同一实际安全视域。用户手动拖动画布、滚轮缩放、开始拖节点、新定位或切项目后，旧导航不再追加移动。[当前原相机定位](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-placement-client.ts:95>)。

返回记录只捕获出发 `project / 原现场身份 / viewport`，并附原返回链的必要上下文；仅存在当前导航交互中。跨现场用原 `enterNativeWorkspaceWithReturn` 与原页头返回；已有 Composer 的输入、引用、caret 恢复保护继续保留，不能把旧输入塞回新消息。切项目、出发现场失效时不跨项目回跳；来源场景被删则保留当前现场并给原入口反馈。[原跨现场返回桥](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-library-contexts.tsx:750>)、[原输入返回捕获](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-library-contexts.tsx:83>)。

## 6. 光效与材质如何用

保留 TapNow 原节点与菜单的尺寸、密度、圆角、焦点和展开节奏；叠加自有语言中适合浅色的轻微光波／形变与抵达光环。不是给全部控件裹同一层玻璃。固定钉是静息可识别的锚，屏边是有方向的提示，抵达是短暂强调，三态共享一套轮廓与色彩逻辑。

| 状态 | 规则 |
| --- | --- |
| 静息 | 主体清晰、低对比材质；不持续大幅呼吸占注意力；不拿颜色分类承担选中态 |
| hover | 小幅轮廓／亮度变化与原 Tooltip，不能先定位再解释 |
| press | 沿原按钮反馈，保持命中区域与布局不跳 |
| focus-visible | 明确独立焦点环，键盘操作不依赖 hover 或颜色 |
| selected／固定 | 选中、颜色、固定可同时辨认；不互相覆盖数据或轮廓 |
| loading | 仅发起动作表现 pending，不把整个画布变 loading，不触发循环相机 |
| error／missing | 小范围就地反馈，保留取消／重试能力；不只用红色提示 |
| arrival | 浅色短暂光环；动画结束不改变固定、选择、颜色或业务状态 |
| reduced-motion／强制色彩 | 以静态轮廓、文字与明确状态替代移动／形变；仍保留反馈，不是直接消失 |
| 后台／卸载 | 暂停非必要动画，清理 observer 与回调；回到前台按实时节点重新投影 |

原件与当前材质覆盖证据已独立归档，施工无需再次无穷扩查包。[原件与当前覆盖审查](<E:/Codex 项目/LCOS夺舍计划_20261013/docs/自有光效语言原件与当前覆盖审查_20261026.md>)。

## 7. 取用／不取用

| 来源 | 取用 | 不取用／原因 |
| --- | --- | --- |
| 当前 TapNow 原节点浮条、色组 Popover、小地图、原页头 | 入口、排版、信息密度、展开退出、焦点、键盘与原相机 API | 不把原颜色操作改成不可区分的混合 Pin 语义 |
| 当前 LCOS Color Pin 桥 | 真实定义／成员关系、准确目标准入、错误回显 | 不把它当作固定锚已经完成；不要求普通视觉强调必须有 Artifact revision |
| GEN1 Core marker provider 与实际 rail 调用 | Core 持久意图、准确创建／删除／重新 resolve | 不搬旧 rail、旧全局岛和旧边缘壳；不照用旧世界坐标做当前相机位置 |
| 旧 GN2 locatorGeometry／density／layout | local→near-edge→edge 的几何、同现场同方向聚合、占位避让思路 | 不沿用旧全部 DOM selector、尺寸常数、扇出外观与三根现场的假设 |
| 当前 material navigation／library return | 取消、最新 API、准确位置确认、用户主动离开不拉回、原输入返回保护 | 不把仅针对材料身份的字段硬塞给所有通用节点 |

## 8. 两批施工与可验证完成标准

### 第一批：一个当前现场内完整可用

施工范围：原节点入口、现有 canonical marker 读写、实时节点几何、近场／边缘过渡、原相机抵达、短暂光环、主动返回；原色组维持现有操作。先用单目标闭环确定体验，再接同向聚合。

| 必跑真实页面场景 | 完成标准 |
| --- | --- |
| 节点固定、重载、取消固定 | Core 读取与写入有真实结果；固定重载后仍在、取消后不复活；节点内容、颜色和布局不变；失败不显示成功 |
| 目标拖动、父组移动、集合成员显示、缩放 | 固定钉与方向跟随当前原节点；不退回旧 Core 坐标；不阻止原拖动和布局保存 |
| 四边与四角连续拖动、左右栏开关 | 近场／边缘没有双影和临界闪烁；方向正确；不覆盖真实输入、浮条和小地图 |
| 点定位、手动缩放中断、连续点不同目标 | 只有明确动作改变原相机；旧请求不追加移动、不把用户拉回；最后一个有效目标获反馈 |
| 抵达、光环结束、主动返回 | 光环不写业务状态；结束不自动回跳；返回恢复出发视角，用户中间编辑仍保留 |
| 删除／替换目标、断开 marker 服务 | 不按标题重绑；原列表可说明不可用并取消；接口失败有原入口反馈，未接点继续记账 |
| 鼠标、键盘、reduced-motion | 原 Esc／外点／focus 行为正常；无动画时仍能分辨固定、方向与抵达；没有新增窗口 |

第一批通过才可以称“本现场链已通”；跨现场与普通无 canonical ref 节点未测就不能一起报完成。

### 第二批：跨现场与所有常用 GUI 目标收口

施工范围：实际 occurrence 选择、原现场进入／返回、同向聚合、已固定列表，以及无 canonical ref 原节点的本地固定。继续沿原 Popover 和原页面，不恢复旧全局岛。

| 必跑真实页面场景 | 完成标准 |
| --- | --- |
| Main→集合／嵌套 Scope／对话现场→返回 | 精确进入原现场；返回原来源、原视角和已有输入上下文；不拍扁成三个根、不另开窗口 |
| 同一内容多个 view／多个现场 | 原列表能区分真实位置；选哪处就去哪处；没有静默 main／第一条／最新版本兜底 |
| 密集同向目标、反方向目标、选中目标 | 同向正确聚合，反向不混组；成员可逐项选；展开不改变相机；目标数和列表数一致 |
| 导航途中切第三现场／切项目／目标被删 | 原请求停止，不回拉，不跨项目操作；保留清楚的原入口反馈 |
| 普通原节点无 Core／Run | 选中、强调、当前位置导航照常；本地固定经原 O8 保存、Undo／Redo／重载可恢复；不伪装成 canonical marker |
| 原节点变绑定、同名节点、原节点被复制／删除 | 本地标记只跟随它原本的准确节点身份；复制与删除规则明确实测，不按名称迁移；同一意图不双写两个 owner |
| 原视角返回目标过期／来源现场被删 | 不造来源、不恢复旧内容、不无限重试；当前真实现场仍可操作 |
| Drop、节点拖动、框选、撤销、色组、Composer | 叠层不抢事件；原操作、布局保存和 Undo／Redo 回归通过 |

测试先用本地既有材料与可控目标，不发送模型任务。自动测试覆盖投影、身份与取消分支；真实页面检查原入口、鼠标命中、动画过渡、遮挡、相机抵达和返回。两类证据分开记录，不能用截图替代动态验证，也不能用源码存在代替真实可用。
