# TapNow 承载 LCOS 能力：架构确认

## 结论

方向成立：借用 TapNow 已经打磨好的画布交互与图文节点呈现，把我们华布已有的画布 Agent、上下文和工作流能力接进去。对使用者来说，它可以像一组新增功能；实现上是能力扩展与接口映射，不是重写整套前端，也不是只换皮。

这里讨论的是本地已经拆解的 TapNow 副本，不是另外一个 Typebot 项目。结论不外推到未检查的其他版本，也不据此断言 TapNow 所有版本都没有某项能力。

## 为什么值得做

TapNow 的价值是成熟的交互底座；LCOS 的价值是材料、Agent、上下文、工作方法与产出之间的组织关系。它们可以分工，而不必互相替换。

| 能力 | 借用的入口或机制 | 由 LCOS 提供的内容 |
| --- | --- | --- |
| 画布 Agent | 原节点注册、选择、移动、缩放与画布对象呈现 | 会话身份、上下文材料、执行状态、工作视图与产出关联 |
| Main / Context / Workflow | 原空间切换与各自画布布局 | 三现场职责、同一项目材料的不同投影、上下文与工作方法 |
| 图文材料 | 原图文节点外壳、工具栏与交互 | 本地文件、材料身份、版本与已有 Gen1 文本能力 |
| 工作流 | 可借用节点、连线、卡片等呈现机制 | 方法、输入、Run、Review 与结果回投；不是把所有连线自动当成可执行流程 |

因此，画布上摆着的 Agent 不应只是一个头像或聊天按钮。目标是：给它材料，组织上下文，提出任务，查看执行与结果，再围绕结果继续发散。

## 怎么接

保持三层分工：

1. TapNow 原画布负责交互，包括原 ReactFlow、空间、选择与历史链，不再嵌套第二张华布。
2. 适配层利用原节点注册、空间入口、正文插槽与请求入口，做明确的身份和能力映射。已有华布组件在同一 React 环境中复用。
3. 现有 Core 继续负责项目、材料、版本、上下文、会话与执行记录；真实 Agent 执行由原执行体系承接，不让前端节点自己成为第二套后端。

能一一对应的能力直接映射；只有外观类似、业务含义不同的能力，复用呈现，不硬套语义。空间、集合、地图钉与工作流连线尤其需要逐项确认这一点。

## 施工重点

以“围绕画布 Agent 工作”的闭环组织后续施工：材料引用与整理 → 上下文 → 任务输入 → 执行/复核 → 产物落回画布 → 继续发散。完整接入目标不缩减；图文、文本编辑、空间管理与恢复能力仍按原执行计划推进，不把调色作为主线。

上轮架构确认仅做只读核查与说明；本轮已继续真实接入和 GUI 验证，不能把两个批次混为同一次只读操作。
