# TapNow 桌面壳能不能拆（2026-10-13）

## 结论

可以把 Electron、桌面更新器和全局系统桥从当前浏览器优先目标里拆掉。现有浏览器在 tapDesktop=false 时已跑起 Canvas 和 Library；核心画布不硬依赖桌面壳。

但这不是桌面版全功能平替。安装器、深链登录、路径授权、本地 Agent 文件工具、系统截图/录屏、命令审批、托盘通知等会消失。若要完整保留这些能力，得由 LCOS Local Core 选择性接管；不能留一组永远成功的空函数。

## 为什么

复制安装包 app.asar 的 package.json 写明 @tap/desktop 0.4.95、入口 dist/main.cjs。脚本在内存中读取 ASAR entry，并与 reference/desktop-shell 下的三个文件逐字节比较：main.cjs、preload.cjs、capture-preload.cjs 都匹配。没有把内容二次落盘，也没有运行 TapNow.exe、卸载器、updater 或其中任何 IPC。

Web bundle 区分 web_app 与 desktop_app。主应用对部分桌面状态采用可选访问；但 Agent Host 的本地文件、屏幕捕获和 Shell 命令直接依赖原生 bridge，缺能力时会报 Desktop native capability is not available。窗户能开，部分工具柜仍锁在 Electron 后面。

本轮 renderer 检查是编译后 JS 的词法扫描，不是完整 AST 调用图；bundle 没有 source map。Canvas / Library 可用来自当前已打开浏览器的现场观察，本轮未重开或操作浏览器。首次登录、浏览器通知、上传/导出等网页替代路径仍需分别验证。

## 能力分类

| 能力 | 通道量 | 浏览器可替代到哪 | 拆掉后的损失 | 重建复杂度 |
|---|---:|---|---|---|
| Canvas / Library 核心页 | 0 | 已现场看到 tapDesktop=false 时可运行 | 不影响这两个已观察页面；不能外推全站动作 | 无 |
| 安装、窗口、托盘、深链 | app 1 + shell 生命周期 | 标签页和 URL 路由可用；没有应用窗口、托盘和 tapnow:// 唤起 | 安装、窗口布局、托盘、深链和 preload 恢复提示 | 只做 Web：低；桌面发行：高 |
| 登录回调 | auth 3 | Web 登录路径存在；桌面 OAuth 回调走自定义协议和 loopback receiver | 系统浏览器拉起与回到桌面 App 的 state/token 回调 | Web-only：低；桌面 OAuth：中 |
| 应用更新 / Web bundle 更新 | updates 7 | Web 站点部署更新；浏览器不更新本机二进制 | 自动检查、下载、进度、安装重启和本地 bundle 生命周期 | 只做 Web：无；桌面更新器：高 |
| 本地文件与 path grants | local-files 16 | 普通网页可选文件、拖放和下载；不是 Agent 遍历目录的权限 | 目录树、元数据、授权内读写/整理/删除、grant 查看和撤销 | 中高 |
| 区域截图、屏幕源、剪贴板、录屏 | capture 13 + screen-capture 3 | 浏览器可让用户选屏或上传图片；不等价于区域遮罩、热键和录屏分块 | 原生捕获窗、屏幕源枚举、快捷键、截图复制和录屏 | 原生平替：高；仅上传：低 |
| 麦克风 | media 2 | Web Media API 可请求浏览器授权 | 不能读取 OS 麦克风状态或直接打开系统隐私设置 | 录音入口：低；OS 状态：中 |
| 下载 | downloads 5 | 普通文件链接走浏览器下载器 | 应用管理的目标路径、任务进度和保存队列 | 浏览器下载：低；队列平替：中 |
| 系统桥 | system 7（不含审批） | 普通 URL 可走网页；本机应用、窗口控制、系统设置没有网页等价物 | 应用发现/启动、窗口布局、系统权限设置、已授权文件的 OS 打开/定位 | 已注册路径：低；其余：中高 |
| Shell 命令审批 | system 4 | 没有安全等价网页回退 | 提案、命令+CWD+平台+shell 绑定、持久批准/撤销、风险与使用审计 | 高；或整组不交付 |
| 系统通知与导航事件 | notifications 3 + navigation 1 | 页面内通知和普通 URL 可用；浏览器通知需用户授权 | 托盘通知、点击通知后的桌面导航、协议深链唤起 | 页面内：低；系统通知/深链：中 |
| 桌面存储维护 | storage 9 + diagnostics 1 | 浏览器能清本站点数据；不能清 Desktop userData 或导出同类诊断包 | 缓存、日志、临时文件、测试文件和诊断报告入口 | 不做支持工具：低；保留诊断：中 |
| 网络路由 | network 2 | Web 使用当前 origin 与服务端路由 | 桌面代理 origin、线路状态和诊断 | hosted Web：低；保留本地代理：中 |

总计 77 个 IPC channel。表按能力解释，不复抄名单；逐前缀统计在 evidence/desktop-boundaries.json。

## LCOS 已有的可复用部分

- apps/local-core/src/path-guard.ts:35 已把选中文件规范化并限制在允许项目根内。这是路径安全底座，不是 TapNow 持久 grant 系统的替代品。
- apps/local-core/src/native-directory-picker.ts:26 已有 Windows 原生目录选择器。
- apps/local-core/src/os-integration.ts:16、41 已能打开或定位 LCOS 已注册路径；调用方必须拿到注册路径，不能扩成任意路径入口。
- apps/local-core/src/capture-gateway-service.ts:108、122 已能接收截图数据，并要求本地文件捕获走 trusted Runtime Host。它接收图像，不负责截屏。
- apps/local-core/src/agentlet-runtime-service.ts:203 有受限 argv 执行机制，但未发现与 TapNow proposal/approval/revoke/audit 对等的完整接口；不能把它说成现成替身。

## 怎么拆比较稳

1. 当前阶段直接以浏览器承载 Canvas / Library，Electron、桌面 updater 和两个全局 preload bridge 都不进入交付主路径。
2. Web 运行时按能力显示入口。没有的能力就隐藏、禁用或明确报 unsupported，不要返回空结果或成功回执。
3. 普通上传、下载、录音优先用浏览器原生交互；不要暗示它们拥有任意本地路径权限。
4. 如果保留 Local Core 文件能力，沿用显式用户选择、path containment、grant 范围/时效/撤销和审计语义。不要为了移除 Electron 把限制改成任意路径读写。
5. 如果保留命令执行，由 Local Core 接住提案、明确授权、范围绑定、撤销和审计。暂时不做就把 UI 与 handler 一起删掉，不留“点了就成功”的空桥。
6. 桌面版本以后若要回归，再单独接入安装、深链、系统桥和 updater；保留原有 bundle 兼容性与完整性检查，不用“没有 Electron”冒充这些能力还存在。
