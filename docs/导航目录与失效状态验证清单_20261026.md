# 导航目录、可发现性与失效状态：最小验证清单

2026-10-26。本轮只读当前源码、原安装包 AST 与已保存真实截图；没有启动真实页面写测试，没有创建/取消固定，没有改产品。当前读到的 UI 还没有独立“已固定目录”，只有屏边/本地钉和聚合 Popover；以下是待实现后应跑的最小清单，不能当作现已通过。

## 结论

1. 当前列表从“当前现场已有且未 hidden 的真实节点”反查固定记录，因此其他现场、尚未投影、隐藏表征、失效目标都无法从这些钉发现。目录必须以真实 Core marker 记录为起点，把可定位和待核/失效区别展示，不能用“当前没有可见钉”推出“没有固定”。
2. 最新 360×820 图中的小箭头压到的是 Main 文本卡片 H1。当前避让有顶部 Chrome，却没有其他材料的标题/正文保护。把顶部项目标题排斥区扩大不能解决这处。
3. 可用原 Popover 与原按钮已接入；现有导出里没有通用 DirectoryRow。原库资产行、原项目目录都值得用其密度/布局，但不能伪造 asset/canvas 对象把它们的领域动作一起硬套。

## 必跑的最小真实验证

| 项 | 操作和 fixture 条件 | 应看到/必须保住 | 必留证据 |
|---|---|---|---|
| 1. 无固定/加载/读取失败 | 新隔离项目；目录首次读；受控断 GET 后重读 | 加载中不能显示“暂无固定”；失败有明确重读，不能清空真记录伪装0条。 | 原按钮、原 Popover、GET 路由/状态、0写请求。 |
| 2. Main 可发现性 | 在 Main 原更多固定真实材料，平移到屏外、刷新，再从目录找回 | 原位目录始终可发现；计数取真实记录；相机移动不写新 marker。 | marker GET/实体主键、原节点id、刷新前后与目录屏。 |
| 3. Context/Workflow 各自现场 | 同一实体在 Main、Context、Workflow 形成已有真实表征，分别固定 | 正确标明所在现场；local 记录不串成同一条；目标View/Revision不换成标题相同对象。 | 三组 workspace/canvas/sourceSurfaceRef、原页截图。 |
| 4. 方法子现场 | 原库进入真实方法子现场，固定其中集合/附注/对话等已有成员；返回根现场再开目录 | 地址为实际子 Workspace；原方法进入/返回沿原页；不能把子场景冒充 Workflow 根画布。 | 原库入口→子现场→目录→返回的连续截图及真实地址。 |
| 5. 跨现场进入/返回 | 从 A 目录选 B 中记录，再返回 A | 原页面导航/flush/preflight；准确原 API 接管后才定位；返回原 A/原视角；不额外建窗口/会话，不动草稿。 | 原导航链、两端 viewport、Canvas/API owner、窗口数/草稿对照。 |
| 6. 当前现场没节点 | 记录仍有效，目标在别处或尚未投影/隐藏了当前表征 | 目录仍有行；区分“在其他现场”“当前现场未显示”，不能说目标删除、不能默默创建新表征。 | 真 marker/目标仍存在、当前 node absent、0自动放置写。 |
| 7. 真目标移除/位置失效 | fixture 通过原 owner 移除对应表征或目标，再打开旧记录 | 保留可理解的失效行；不定位别的对象，不退而取第一 binding/同名对象。取消固定只删该记录。 | 前后 marker/entity/binding、原视角不动、准确移除回执。 |
| 8. Collection/Run 的旧 resolver 边界 | 真实 fresh entity/binding 已存在，但旧 resolver 返回 unsupported kind | 不能把“旧 resolver 不支持”写成“目标已删除”；能否按原精确 binding 接续要如实标状态。 | fresh graph/binding 与 resolver 原结果分别存证。 |
| 9. unknown/待核回执 | 固定或取消已提交但响应丢失；重新开目录/刷新 | “结果待核对”，核对只 GET；不自动重复 POST/DELETE，不先把行删掉演成功。 | 丢回执fixture、写计数、核对读回、状态屏。 |
| 10. 多条与同名 | 至少20条、同名异实体/异现场、不同方向聚合 | 列表滚动不挤出可见区；副文可区分现场/类型；点击精确主键；不把反向目标混一组。 | 目录滚动/键盘/点击、精确对象回执。 |
| 11. 窄屏与原内容保护 | 360×820，主标题旁/四边四角、原右栏开关、小地图/浮条/Popover开关 | 44px游标不盖原项目标题、材料H1、原工具；无槽时目录仍能找到，不删固定记录。 | 各控件rect、顶层hit-test、实屏及受限情形。 |
| 12. 中断/旧请求迟到 | 目录定位中手动拖画布或切到另一现场，再释放旧响应 | 手势停动画；旧响应不飞新现场、不改旁对象/新目录状态；Escape/关闭后focus回原入口。 | 前后 camera/API owner、受控延迟、菜单focus/窗口数。 |

这些是独立事实，不是只点亮一个按钮后截图即过关。普通材料、集合、附注、对话、Run 的成员身份与返回都应沿各原 owner 验证，不能用一类成功替代全部。

## 用户文案建议：区分事实，不暴露内部协议

| 真实状态 | 最小文案 | 不能写成 |
|---|---|---|
| 正在读取 | 正在读取已固定目标… | 暂无固定（尚未读完） |
| 读取失败 | 固定目标暂时无法读取，可重试。 | 记录已丢失 |
| 有效但当前没有表征 | 当前现场未显示，可前往所在现场。 | 目标已删除 |
| 目标实体确认已移除 | 目标已移除，原固定记录保留。 | 系统错误 / 自动删除整行 |
| 所在现场无法确认 | 所在现场暂不可用，未离开当前画布。 | 已定位 / 偷跳第一个现场 |
| 旧类型暂不能定位 | 暂时无法定位这类目标，原固定保留。 | 目标不存在 |
| 未确认写结果 | 固定结果待核对，未重复提交。 | 已固定/已取消（无回执） |
| 迟到或身份变了 | 这个位置已变化，未前往其他对象。 | 自动按标题搜索并打开别的对象 |

现有错误文案优先沿 [native-navigation-state](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-navigation-state.ts:47>)，目录仅补缺失状态。Main/Context/Workflow与方法名可作为用户语义，sourceSurfaceRef/Workspace/ProjectionBinding 等内部字段不应当目录正文。

后续接口稳定后可新增独立真实页面目录/跨现场验证脚本；本轮没有启动它，也不把已有单材料固定/定位/返回报告当作上述目录链已完成。
