# Scope／集合 Run 接入原任务栏 · 2026-10-22

本轮已接通 Scope 和集合里的 Run 成员：原库预览 → 原右侧任务详情 → 原头部返回 → 原成员。任务内部查看引用材料后先回同一任务，再回集合；原任务列表也保留原返回顺序。实屏验证通过，没有新增窗口、任务详情副本或路由所有者。

本轮只完成这条接线和相关退出／失败恢复，不能据此把整个 GEN2 或夺舍工作区标为完成。

## 接好了什么

| 用户操作 | 现在沿用的页面与动作 |
|---|---|
| Scope 中点击 Run | 原成员行 → `requestNativeTaskView` → 原右栏 `NativeTaskDetail`，读取同一个 Run |
| Scope → 外层集合 → 内层集合 → Run | 同一原 TS 逐层进入，再开原任务栏；返回恢复原内层集合、成员焦点、滚动、搜索和原输入 |
| 任务 → 使用的材料 | 原任务输入记录中的真实 manifest → 原确版 Viewer；Esc 回任务，原头部按钮再回库，避免跳过任务层 |
| 原任务列表 → 任务 → 列表 → 对话 | 原流程保持；后续任务仍沿已有任务返回栈，库返回只绑定入口那一层 |
| 原头部“返回库内预览” | 恢复同一原预览和原位置 |
| 原“收起对话”或主动选择另一个对话 | 结束旧预览，原库列表仍在；不让旧 TS 覆盖新对话，不残留 hidden 状态；可经原库行重新进入 |
| Run 列表读取失败 | 只保留该类成员的不可读说明，其他材料／附注／集合仍可用；原“重新读取”恢复 |
| 点击成员时重新读取失败 | 报告准确的任务读取原因，保留原入口；不误报成内容变化，不换到另一个任务 |
| 任务详情读取失败 | 在同一个原任务页使用已有“重试读取”，返回路径保留 |

Run 成员使用完整轻量 `execution-projection.runs`，没有把默认只返回 20 条的任务详情列表当成全集。解析按精确 ID 和项目归属，缺失、跨项目、重复或读取失败仍显示原成员；不按标题或“最近任务”替代。

## 实屏抓到并修好的问题

1. **窄窗原预览挡住任务返回键。** 进入 Run／对话阅读时暂时收起原 Popover 的显示，保留同一已挂载路径；返回先恢复显示再恢复焦点。取消时则调用原关闭动作结束旧预览。
2. **任务内材料 Esc 被吃掉。** 原库 Radix 为保留来源而拦截并标记 Esc，但原 Viewer 只接手直接来自库的材料。现在收到该原标记的当前受控 Viewer 处理自身退出；任务材料不继承“直接回库”的返回地址，因此退出仍回任务。
3. **失败提示要求重新读取，却没有按钮。** Run 依赖单独失败时，只在确有 Run 成员的原 actions 槽显示已有重读按钮，避免整份库预览失败或让用户关开绕过。
4. **点击时依赖读取失败被误报为内容变化。** 先处理真实不可读原因，再比较成员身份变化。
5. **切换对话后旧预览残留遮挡。** 区分返回恢复、主动取消及新阅读替换，原收起／换会话会关闭旧 TS；新阅读不会误关新来源。
6. 返回清理移出 React functional updater，避免恢复来源时在另一组件的状态更新函数里触发更新。最终真实页面未见跨组件更新警告。

以上没有通过删成员、放宽确版／归属检查或隐藏未完成操作来取得通过。

### 页面 QA 与边界

- 页面地址和原 Library／任务内容已实际渲染；截图未见框架报错覆盖层，最终 `pageErrors=[]`，没有 React 跨组件更新警告。
- 控制台不能称为全干净：原离线 config、canvas plugin、voice、Element 搜索仍有 501，被拦截的 Statsig 请求仍记录；测试注入了 3 次投影 GET 503 和 1 次详情 GET 503。
- 原图片自动同步有 **启动 1 次、浏览 2 次完全同值的 POST 尝试**。均被浏览器阻断，完整请求与逐字段比对保留为 `blockedNoOpCanvasWrites`，不是悄悄从报告删除。其他写入或任何非同值变更仍使测试失败。
- 所以本轮只证明 Core／Run 事实未变、没有派发或模型请求，**不声称全程零写请求，也不声称已经修好同值图片同步**。测试阻断这类 POST 会触发原“保存连接／云端”提示，不能把该提示误当 Run 读取失败。
- 没有执行开始、停止、恢复、采纳、重试等任务动作。没有为了测试后续任务返回而注入一个假导航；后续任务的深层返回本轮通过原独立路由测试，未做实际执行后的实屏验收。
- 仅验证这两个桌面尺寸及本机 Chrome；临时回程不承诺刷新／崩溃后持久恢复。
