# 原可视画布与右栏裁切审查

日期：2026-10-26。

## 结论

旧 Context 光环在图片中间被截断，原因是**导航层留在原 Canvas 的 `contain:paint` 容器内，却按整页坐标计算 clip inset**。不是 `visibleCanvas()` 重复扣除了右栏宽度。

本次审查只读旧截图、报告、源码，并执行隔离数值测试；未启动浏览器或操作当前会话、相机、业务数据。审查期间 root 已另行把同一个导航绘制层 portal 到 body；随后 workflow 产出新的真实页面 PASS 报告。下文分别记录旧证据、受控推导和新实测，不混写。

## 最小方案及风险

采用**只把既有导航 layer portal 到 body**的方案，保留同一组件、React 上下文、相机、状态与原 Popover。当前 root 候选源码见 [NativeNavigationHost](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-navigation-ui.tsx:60>)。沿 [原 ReactDOM 桥](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/native-react-dom.js:1>) 的 createPortal；[构建约束](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/build-pilot.mjs:137>) 已复用原 React/ReactDOM，并禁止为扩展再建 React root。不要顺手 portal 整个 ProfessionalHost 的其他 Drop/交互 children。

容器内方案也能做，但必须同时把 clip 和**全部** halo、marker、feedback 的屏幕坐标转换为该容器坐标；存在平移/缩放时还要继续转换。只把右 inset 改成 0 会留下其他错位。本轮 body portal 的改面更小。

Portal 后不再借原 `contain:paint` 隐式裁切，必须继续保原 safe、障碍、44px 热区及 pointer-events 规则。验证须读 **wrapper 的真实矩形**，再按 `wrapper.right−insetRight` 等求最终可见边界；不能只比 CSS inset 字符串。原 [checkHaloClip](<E:/Codex 项目/LCOS夺舍计划_20261013/scripts/native-navigation-browser.mjs:241>) 曾用同一 innerWidth 公式作 expected，且只要求正面积交集，不能证明整个图像边界都没被中截。
