## 1. 图片为什么拖不动，改了哪里

`surface-main-image` 是原画布上的独立图片，同时被三个 Core Collection 引用。它没有物理父级。显示适配已经把它放回原位置、允许看见；原 TapNow `Ri → jVe` 却仍按集合 `memberIds` 把它当作物理 Pile 内部成员，丢弃位置、选择和测量事件。这是显示与操作判断不一致。

修复只改变 `Ri` 读取的临时保护名单：准确 Artifact/View 引用、无父级的独立材料可以沿原节点链移动；原集合展开组的既有处理继续保留。没有删除 Collection 成员、复制图片或修改其身份。普通物理 Pile、未知父级、替换身份与版本仍维持原保护。

## 2. Pin、游标与光环分开完成

| 使用目的 | 当前状态 | 接入方向 |
| --- | --- | --- |
| 颜色 Pin：给对象分类、按组找回 | 原调色 Popover、色组和小地图主链已有桥接；方法子现场的准入仍有缺口 | 保留原色组菜单与领域身份；不能把这套分类当成全部导航。 |
| 固定空间大头钉：给一个准确位置留下长期路标 | 历史存在真实 SpatialMarkerIntent/解析链，当前原画布没有完整入口与呈现 | 原节点浮条/更多发起；Core 保存标记意图和目标，Huabu 提供真实位置。固定与取消不要求 Run。任意空白坐标落针的旧完整 producer 尚未证实，不能直接假装已有。 |
| 屏外导航游标：目标离开视口时仍知道方向 | 当前活跃 bundle 没挂完整 Locator | 基于当前目标、原相机与实际可用画布范围显示；同方向聚合、避让左右栏/底部工具，不永久铺满箭头。 |
| 抵达与返回：找到后看得懂，还能回原视角 | 目前有确版材料定位，完整通用回程仍待接 | 沿原相机到达，短暂 GUI 光环提示准确对象；同一条轻导航反馈提供返回。返回恢复视角，不挪节点、不改选择或输入。 |
| 通用强调/动效光环：轻量标记与视觉舒适 | 尚未完成通用入口和持久显示偏好链 | 原选区/浮条内切换，原空间显示偏好保存与撤销。瞬态 hover/selected/arrival 保持 GUI 状态，不写业务确认。 |

导航应完整覆盖：选定目标 → 近场提示 → 靠边/屏外方向 → 聚合与展开 → 前往 → 抵达反馈 → 返回。目标移除、现场切换、相机 API 更新和用户另行导航后，旧请求不能再拉回画面。

旧 Figma 有屏边目标、抵达和返回的真实结构；统一 HUD 主稿没有画全固定锚与 Locator 的组合态。GoalNeedle R2 是 Workflow 过程珠轴，样机里固定的是临时透镜，不能借它交付大头钉。用户已明确旧导航样机手感不对，后续只沿用途重做，不默认复活旧组件树。

## 3. Arc 接回哪些东西

Arc 的价值是对象附近的准确、少量动作。当前已有原节点浮条和更多菜单，应在这些位置接动作。当前没有挂旧 Arc 宿主，不能以包内存在 CSS、类型或路由转换声称已经融合。

| 保留/补回 | 原页面去向 |
| --- | --- |
| 已有打开、阅读、改名、Color Pin、任务详情 | 继续原浮条、原更多、原 Viewer 与任务栏，避免重复入口。 |
| “围绕此对象工作”准确带入修改目标 | 接同一个 Composer 的准确目标准备链；普通引用与修改目标分清，不再另开输入框。 |
| Glyth 按真实状态直达回答/恢复/进展 | 使用原对话栏已经存在的分区与恢复流程，节点近场只负责导航。 |
| 对象位置、方向与返回 | 接通用导航链，不把 Arc 做成另一张功能首页。 |
| 关系、隐藏表征等尚未核完整的动作 | 继续逐项查实际 owner；不从旧 union/switch 推定已交付。 |
