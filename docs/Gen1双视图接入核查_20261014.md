# Gen1 双视图接入核查（源码审计）

## 结论

Gen1 的两大文本视图是“文本块”和“大纲导图”，不是 `Gen1TextDocument` 阅读代理。当前 GN2 已把它们的主要交互接到原生文本节点链：`createLcosNodePresentationSeam → LcosCanvasTextBody → LcosTextFaces → MindMapEditor`。因此不需要另建 Canvas、正文 store 或专业窗口；应在现有节点 body 与 Core producer 上补齐缺口。

当前最明确的真实缺口有两个：

1. 大纲导图编辑保存调用 `serializeOutline`，会把标题、粗体/高光标记和空行规范化/丢弃；不能直接把这个结果当作对完整 Markdown 的无损编辑。
2. 真实 Core 有 canvas-text GET/PUT 和实体标题 producer，但隔离用 `CoreProtocolRouter` 目前只代理 canvas-text GET；PUT 正文、导图根标题改名会被代理层以 501 拒绝。

本次只读了计划、技能说明及实际源码；未运行浏览器/服务、未调用 Core、未写 `lcos/`、未执行测试。以下是源码接线审计，不代替实际交互验收。

## 正确接入入口

- 项目 URL 的既有入口为 `LcosAppRoutes.tsx:22-30` → `LcosProjectRoute.tsx:82-97` → `LcosProjectShell.tsx:313-318`。`LcosProjectShell` 已把唯一画布和 `ProfessionalWindowStage` 并置；Stage 是专业窗口宿主，不是文本节点的第二条业务路由。
- Stage 的 body 注册表在 `lcosShellStore.ts:135-153`，实际分派在 `ProfessionalWindowStage.tsx:888-980`。当前无文本编辑 body key；文本模式也不需要新增 key/URL：应保留原生卡片及唯一 body seam。只有产品明确要求独立专业窗口时，才复用该 store/body switch 扩展现有 Stage，不能另造窗口状态或 React root。
- 唯一节点呈现分流点是 `createLcosNodePresentationSeam.ts:38-65`，按真实 binding/descriptor 与 `usesCanvasTextEditor` 决定进入 `LcosCanvasTextBody`；不要按标题或外观猜文本身份。当前 owner 挂载点为 `LcosCanvasTextBody.tsx:37-47,268-271`。视图偏好和折叠态走原 Huabu node data/history：`LcosTextFaces.tsx:36-81,112-120`；切换脑图尺寸时也走 `beginNodeDataGesture / setNodeGeometry / endNodeDataGesture`，不应放入 Core 正文或另建 store。

## Core producer、身份与事务要求

| 动作 | 既有 producer / 条件 |
|---|---|
| 读正文 | `CoreArtifactClient.readCanvasText` 是 `GET /projects/:projectId/curation/canvas-text?canvasId=…&spatialId=…`（`lcos/apps/web-gen2/src/backend/artifacts.ts:51-58,106-109`）。`canvas-text-service.ts:18-56` 要求唯一 workspace/canvas、唯一 node `ProjectionBinding`、同项目受管 text/markdown Artifact、当前 Revision/FileRecord，以及当前现场对应 View；读取前后复核 revision 与 binding，缺 binding 返回 `null`，不是按预览正文推断身份。 |
| 新文本/初次认领 | `createProjectText` 先由 Huabu 创建原生 carrier，再经 `claimProjectText` 保存原画布、调用 Core `saveCanvasText`（`projectTextCreation.ts:16-48,61-86`）。Core 只接受 `expectedRevisionId:null` 且未绑定时初次认领；`createTextArtifact` 注册 FileRecord、Artifact、Revision、View、Workspace membership 与 `ProjectionBinding`（`text-artifact-service.ts:126-153`、`metadata-repository.ts:4634-4687`）于同一 metadata 事务；不应另行 create Artifact 后再手工补 binding。 |
| 正文更新 | `LcosCanvasTextBody.tsx:177-204` 用读取到的 `artifactId + expectedRevisionId` 调既有保存 producer；未绑定 carrier 先保存 Huabu 结构。Core `saveCanvasText` 校验 carrier binding 和 revision CAS，已绑定材料若身份消失/换绑不回退成新建（`canvas-text-service.ts:58-89`）。Revision/FileRecord/currentRevision/View revision 指针在 `commitManagedTextRevision` 的事务内一致更新（`text-artifact-service.ts:162-168,220-244`、`metadata-repository.ts:2680-2725`）。正文与空间几何各由 Core/Huabu 原 owner 管理，不构造跨系统“原子事务”假象。 |
| 导图根标题改名 | `MindMapEditor` save 回调在正文成功后调用 `renameCanvasNode`（`LcosTextFaces.tsx:158-165`）；绑定 artifact 时使用 `CoreArtifactClient.renameEntity` → `POST /entities/artifact/:id/title`（`nodes/nodeRename.ts:16-38`、`artifacts.ts:102-104`）。这是独立既有 title producer，不与正文 Revision 同事务；UI 应保留明确的部分成功/失败反馈，不能把 title 失败说成正文没保存。 |
| 拖出分支 | GN1 原意为“复制成新文本、原分支保留”（donor `MindMapNoteVisual.tsx:266-279`）；GN2 已调用 `createProjectText`（`LcosTextFaces.tsx:83-110`），所以应继续走新 Huabu carrier + Core canvas-text producer，不克隆原 Artifact binding。 |

### `CoreProtocolRouter` 的精确代理缺口

当前 allowlist 在 `lab/pilot/core-protocol-router.ts:3-29` 仅登记 `GET /projects/:id/curation/canvas-text`（第 16 行）。`CoreArtifactClient` 的实际正文写方法是 **`PUT /projects/:id/curation/canvas-text`**（`artifacts.ts:111-113`），因此缺 `canvas-text-write` 对应代理路由。该 Core owner 已在 `routes/curation.ts:42-74` 实现 GET/PUT，且写入严格验证 `canvasId`、`spatialId`、body、`expectedRevisionId` 与可选 `artifactId`；不是新增 Core producer。

完整导图还允许编辑根标题，实际 client 方法是 **`POST /entities/artifact/:id/title`**（非 `/projects/:id/...`，`artifacts.ts:102-104`；Core route 在 `apps/local-core/src/server.ts:1135-1168`）。它也未出现在当前 allowlist。最小代理补齐应各自显式登记 method/path/owner；正文按路由 projectId 限定，title 需通过已有 `isArtifactOwned(artifactId)` 验证同项目身份。不要用宽泛通配代理。

## 最小完整接入方案

1. 保持 `LcosProjectShell → ProfessionalWindowStage` 与 `createLcosNodePresentationSeam → LcosCanvasTextBody` 原入口；不再移植旧 Gen1 Canvas/相机/editor store。使用现有 Milkdown 正文编辑、`LcosTextFaces`、`MindMapEditor` 和 Huabu node data/history。
2. 先修复/限定 map 编辑写回：显示和折叠仍只读派生树；保存必须保留原 Markdown 的标题级别、inline mark、空行等未被编辑部分。当前 `outlineTree.ts:32-48,54-104,107-117` 去掉 heading/粗体/高光语法并统一序列化成 `-` 列表；`MindMapEditor.tsx:224-235` 把它直接交给 canonical `onSave`。需要可逆的 source-line/format 信息或对原文做最小行级变更；不能把纯展示 projection 覆盖回 Core。
3. 在 `core-protocol-router.ts` 只加上述两个精确映射，保留现有 `CoreArtifactClient` 和 Core 错误 envelope；验证 project/artifact 所有权。创建和正文保存仍使用同一个 carrier、CAS 与 binding 事务；title 仍按现有独立 Core title producer 报告部分失败。
4. 接线验收聚焦：正文块输入/格式/保存/取消；正文↔大纲导图往返和原 Markdown 未变；根标题/子节点改写、层级、子树复制剪切粘贴、删支、折叠、拖出；Huabu undo/redo、刷新重开后同 carrier/Core Artifact/View/Revision 身份；网络请求只走上述真实 Core producers。当前仅读审，不声称这些动作已在浏览器验证。已有组件用例位置：`LcosTextFaces.test.tsx`、`MindMapEditor.test.tsx`；存在用例不等于当前完整整机证据。
