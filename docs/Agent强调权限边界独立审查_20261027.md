## 待处理：同 ID 换材料后的 snapshot 强调串对象

文件：[native-canvas-sync.js](../lab/native-canvas-sync.js)，审查时第 86、107–117 行。

复现条件：本地仍显示 nodeId=N、Core ref=A、强调=false；GET-gap 期间远端将同一 N 换为 Core ref=B，返回 candidate 的强调=true。snapshot 分支只按 N 找 local，并核 parent/geometry/布尔类型，随后构造仅强调差值的 patch；没有比较 A/B。原 history 收到的 expectedNodes 仍是 A，但补丁已经丢掉远端 B 的身份，因而无法识别强调来自另一材料。

用户损失：B 的视觉表达会套到仍显示 A 的本地节点；这不应被算作正确的 Agent GUI 接回。最小方向是在现 candidate→local 接缝使用已有准确 material/typed reference 判断同一对象，变化则 deferred 给原内容 owner 核对。不要比较整段正文，避免破坏已保住的本地草稿；不要新增第二渲染器、字段同步器或全局 store。

已直接通知 workflow 施工代理。原始 SSE delta 可能不携带完整 canonical ref，因此也不能把“snapshot 补了检查”外推成所有增量路径已经核准；应按原事件实际提供的身份/原 owner 证据说明边界。
