# 原 TapNow 的“画布切换”是什么

## 结论

指你本机安装版副本里，画布页面左上角“当前画布名称”右侧的小下拉箭头。它打开其它画布的列表，可搜索/打开另一张画布，也有新建入口；不是 LCOS 新加的三现场按钮。

名字与箭头是不同点击目标：当前画布名称对应重命名入口，右侧箭头对应切换菜单。

## 切换的是哪种东西

从画布 A 打开画布 B；两张画布各有自己的节点和连线。类似从一份画布文档打开另一份，不是在同一张画布里切文本/导图，也不是 TapNow 原生就有 Main / Context / Workflow 的语义。

此前方案是“借原多画布导航和加载能力，把我们的三个真实 Workspace 投影成它可打开的画布条目”。三个现场的业务意义仍由 LCOS 和兼容层提供，不能因为有菜单就说三现场已实现。

## 原件证据

未修改安装包副本：Desktop 0.4.95，Web bundle 2026.10.10.38066889187.1。

- `reference/tapnow-installed/resources/web/assets/index-BAQXnPag.js` 有原中文翻译键：`canvas.headerSwitcher.switchCanvas` → 切换画布；同组包含搜索画布、新建画布、重命名画布。
- `reference/tapnow-installed/resources/web/assets/page-Da_DfwiK.js` 的原按钮实际调用上述键作为 aria-label/title，data-testid 为 `canvas-header-switcher-trigger`，aria-haspopup=menu；children 是原小箭头图标。
- 同文件的名称按钮 data-testid 为 `canvas-header-title-trigger`，调用 renameTitle 并打开重命名。
- `.playwright-cli/page-2026-10-13T06-11-58-988Z.yml:58` 的真实浏览器快照记录原“切换画布”按钮。
- `evidence/node-lab-interactive.json` 保存了 `canvas switch isolation + return` 的实际点击记录。
