## 结论

**当前仍是 TapNow 原壳与 GN2 旧页面混合的实验工程，不能按“GUI 已融合”认作完成的 GEN2 主线。** 可以继续在这里施工；值得保留的是原画布、原路由、原库、原右栏、Collection 主体及已接好的业务适配。不能把整个工作区打包当成已迁完。

## 建议施工顺序

1. **先收所有现行旧窗 caller。** 任务、结果、输入引用、异常核对、连接、重试都接同一原右栏/原 viewer。先迁打开和返回，再退役 Stage。任务状态、批准/拒绝、恢复不能缩水。
2. **统一阅读与编辑。** 原 viewer session 承接准确版本与 anchor；GN1 的查找/摘录/对照/PDF 等拆进内容和动作槽；普通/结果/引用/库的材料不再走不同壳。
3. **补原库真实动作。** 取用后恢复同一输入、普通库投放、原菜单、成员阅读/方法编辑、语义拖放、收件/来源/归档。同步修 TS 正文布局，不能只调圆角。
4. **收 Collection 二级链与全局 Drop。** 主体保留；工具、命名、成员回原位置；拖入、落区、取消、部分失败、刷新逐源测试。
5. **接动态子现场与 Agent 创建。** root 三键继续保留；child 由真实 Core 工作区生产者接原 Ke；Agent 在原创建菜单先选形象再拖放创建。
6. **贯穿修完整浅色、空间与动效。** 优先修当前无法读的创建菜单，再遍历所有二级容器；保留原布局/动效和用户要求的光波材质。三键、右栏、通知互相避让。
7. **最后迁旧恢复地址与更新能力账。** 仅在真实流程都转到原容器后清理不可达旧宿主；没有桥好的能力继续登记，不靠删除遮过去。
