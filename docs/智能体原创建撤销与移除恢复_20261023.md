## 改动和原因

| 原问题 | 本轮处理 |
| --- | --- |
| 智能体只是补进每一张历史画面，无法撤销创建 | 已确认的创建只向原 O8 追加一条操作；创建前的画面保持没有该智能体 |
| 后端撤销恢复只认识图文材料 | 沿原批量保存入口，用现有会话引用和 Core 投影绑定操作 Huabu 载体；不把会话伪装成材料，不调用会话创建／删除／重连 |
| 原重做会给载体分配新 ID | 会话历史复用原节点 ID、原 Core/native 身份、原形象和位置 |
| 后续刷新又会把智能体塞回创建前的历史 | 已有创建／删除记录的会话投影保留原历史中的“尚未存在／已移除”状态 |
| 原历史和网络保存各有一次坐标舍入 | 两处都沿原快照保留精确落点；普通图文保存的原规则不改 |
| 旧版会话投影没有新形象／引用回显 | 沿其原 Core 投影绑定确认身份，仍可删除和恢复，不要求重建智能体 |
| 旧撤销可能碰上后来重新放置的同一会话 | 发现新的位置绑定后停止旧操作，保留后来放置的节点；空间写入后也再次核对原绑定，避免覆盖并发新绑定 |

主要实现位于 `lab/pilot/native-conversation-lifecycle.ts`、原 `surface-core-facade.ts`、原历史接线脚本和原创建调用方。继续复用原 `CREATE_NODES`／`DELETE_NODES`、空间锁、Core `ProjectionBinding`、O8 记录器和原保存队列。没有增加领域协议、hash、baseline 或 gate。

## 真实验证

1. **新建智能体完整原流程**：原加号 → Enter 放置 → 两轮 Ctrl+Z／Ctrl+Shift+Z → Delete → 撤销删除 → 重做删除 → 再恢复 → 刷新 → 点形象回到同一原对话。八个历史动作均由原页面发出；每步核对后台和画布。形象、精确位置、节点／Core／native 身份保持，没有发送模型消息。
2. **有真实历史的旧智能体**：使用绿色智能体原有的四条真实消息，走原删除、撤销、重做、恢复和刷新，四条消息逐条保留。其他对话、所有原消息和其他画布节点也逐项比较，未被改写。
3. **本轮新建的空会话**：原供应商在零消息时已自动写出一条 `session_approval_mode` 系统记录。原 Host 真正断开该会话后，沿原页面恢复到同一 native，仍为零消息；没有补记录、占位消息或替代会话。这验证了前轮空会话修复在新会话上实际生效。
4. **原厂函数和真实 Core**：执行实际 TapNow O8、M8、r6 序列化代码；两轮撤销重做只产生原操作，没有多余历史帧。独立真实 Core/Huabu 验证了新旧智能体恢复、重复回执不重复写入、错误身份／旧位置拒绝、后续新放置保护，以及空间提交后的受控并发绑定变化。

原界面截图已查看：仍在同一个浅色画布、原左栏和原右侧对话中操作。选中框仍是原矩形、既有画布材料有重叠，整体视觉与 Rail 整理仍未完成，不把生命周期验证等同于 GUI 全部完成。
