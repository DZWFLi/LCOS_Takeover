| 部分 | 直接沿用 | 只补的差异 |
| --- | --- | --- |
| 左侧入口 | TapNow 原 Library 搜索、材料列表、原 Assembly 小详情 | 在同一详情内加来源／位置节，不并列挂另一整页 |

## 来源与使用位置怎样算

- 「版本来源」读**所选 Revision** 的 `source`／`runId`；「Core 登记」独立读 Artifact 的 source-path。路径未登记、读失败、文件已不可用分别显示，不按文件名推断。登记 URL 仅显示，不访问远端。
- 「收录」是 Workspace／Presentation 的领域成员，不等于画布有节点。UI 分开显示收录数、所选版本出现数、其他版本出现数。
- 物理位置要同时匹配同项目 Artifact／View／Revision／FileRecord、唯一 Workspace／Scope、ProjectionBinding 和真实 Canvas 节点 `lcos_ref`。图片和 Artifact-backed text／note 已支持；这里的 note 不是另一个 Core Note 实体。
- 坐标从真实 Canvas 节点与父级几何计算，尺寸来自 measured；不使用旧 ArtifactView.position 或猜测默认位置。缺父级、循环、歧义绑定、无效尺寸不会硬凑位置。
- 其他 Revision 可以告知「还有别的版本」，但不能拿它冒充当前选择定位；历史版本也不回退 Current。
- Peek 每次打开重读，关闭或现场／API／项目变化后丢弃迟到结果并释放 Blob；场景未含目标时明确报不可确认，不高亮其他节点冒充。
- 定位前后重读 Core，跨现场经原 Ke 只委托一次；只在当前 live API 也呈现精确材料引用时 fit。TapNow 在目标挂载期间会更新 API，旧到达句柄不能继续用。

## 真实失败与修复

1. **完整变换链首开 500**：原 Agent 与 Assembly 本来各有一条同源 import，新 Rail 变换误认为重复导入。修复为核对精确组件导入名，追加完整 serveStatic 顺序测试；没有删掉原 Agent import。
2. **位置行缩略图破图**：原 Zp 的图片 resizer 不支持 Blob URL。只把该行换成已核对的精确本地 FileRecord HTTP URL；TS 主预览继续用当前版本 Blob，没有换云端或 Current。
3. **已到 Context 却报定位失败**：目标页在第二次 Core 读取期间会刷新原相机 API。修复后再次核对当前 Canvas／精确 live ref，再用当前 API；源 API 在初读期间改变仍拒绝。真实 GUI 两次跨现场均观察到 API 更新，且只用新 API 成功定位。
4. **审查发现旧意图竞态**：新选材料／换版本／手动取消应取消待完成的旧定位，正常跨现场卸载不当作取消；同时原 12 秒到达等待不能让挂住的 Core 或 Ke 永远 pending。本轮收尾补上取消及全流程等待清理，保留原 Ke 已委托的切换逻辑，不回滚已接受的现场切换。
5. **重建后的首屏超时**：一次最终复跑在 30 秒内未出现 ReactFlow，尚未进入功能检查；没有捕获到页面异常或原包 500。单测并行结束后实测原 page 动态变换约 12.2 秒，后续无并行编译复跑的 Main／Context 冷启动约 20–25 秒。失败[报告保留](E:/AppMoved/.codex/visualizations/2026/10/16/native-material-rail-2026-10-16T02-48-42-245Z-57cce587/report.json)，没有靠放宽测试超时宣布通过。当前是实验宿主动态变换，不是正式性能验收；较慢首开仍是后续优化项。
