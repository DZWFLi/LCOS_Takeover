# 后端承接｜2026-10-13

结论：项目目录、画布目录和 Library 元数据的只读协议适配已实现；当前服务只启用显式合成数据，未连接真实 Core。真实 Canvas 节点、文件字节和所有写入仍未接通。

## 接口边界

createBackendCompat({ coreOrigin, fixtureMode }) 返回 async handler，入参 { method, pathname, url, body }，响应 { status, body } 或 null。只处理 /api/canvas/、/api/library/ 与 /api/compat/status。支持路径上的所有非 GET 请求返回 501；其它 API 交回 host server。

- /api/canvas/v1/canvases：把 Core /projects 投影为个人目录列表，标记 catalog_only；不提供节点、连线或导航能力。
- /api/library/v1/spaces/SPACE_TYPE_PRIVATE/folders：每个 Core project 映射成 Library 文件夹。
- /api/library/v1/folders/:folderId/assets：读取该 project 的 active artifacts 与 revisions，返回元数据。
- /api/library/v1/assets:search、assets:mention：跨 project 搜索元数据，分页上限 200。
- /api/compat/status：报告 fixture / Core / unavailable 状态和未连接能力。

主服务在后端 handler 前调用 handleStartupFixture；它接管单个合成 Canvas detail 与明确未连接的 billing 初始化。其余 Canvas detail 请求不会从 project 目录伪装成画布。

## 真值与缺失值

Core 的 /projects 返回 id、name、rootPath、可选 lastOpenedAt。投影只暴露目录 ID 和名称；lastOpenedAt 只用于展示排序，不冒充内容更新时间。Core Artifact 有 currentRevisionId，revision 有 fileRecordId，所以按 ID 查找当前 revision，不按时间猜。找不到当前 revision 时保留当前 ID 并明确 current_revision_available: false；不造下载 URL，content_available 始终为 false。

字段依据：lcos/apps/web-gen2/src/backend/projects.ts（GET /projects route item）、lcos/packages/domain/src/index.ts（Artifact 字段）、lcos/apps/web-gen2/src/backend/artifacts.ts（active artifacts 与 revisions 路径）。

## Core 连接

只有显式传入 http://127.0.0.1:PORT 或 http://[::1]:PORT 才会发 GET；默认没有 Core origin，状态标为 mode=unavailable、source=unconfigured，不会探测旧端口。Core 请求失败返回 503，不回退到 fixture。fixture 必须显式 fixtureMode: true，且与 coreOrigin 互斥。所有记录均标为合成数据，不代表真实 Core 写回。

## 验证

运行 node --test scripts/adapter-compat.test.mjs。测试覆盖 fixture 状态、目录映射、当前 revision 指针、元数据搜索分页、非 GET 拒绝、无关 API 放行、Core 缺席时的 503 以及 loopback origin 校验。

结果：9 项通过。只跑本地 fixture 与 Core 缺席分支，没有启动 Core，也没有连接旧端口或账户。

真实浏览器还验证了原版素材库能显示两个模拟项目文件夹，点击第一个文件夹后显示“合成图片条目”和“合成文档条目”。这证明所测列表协议形状可被 UI 消费；不代表真实文件内容、缩略图或 Core 已接通。
