## 本轮修复的实际问题

1. **会话返回丢光标。** 原受控 textarea 重挂载时默认光标为 0，抢先覆盖了已有记录。现在在布局阶段使用同一原输入所有者的既有光标记录；不复制草稿，不覆盖后来输入。
2. **跨现场回来后原预览被关掉。** 修复源现场尚未就绪的恢复时机，以及晚到 Composer 焦点造成的原 Popover 自动关闭。恢复稳定后即交还普通关闭行为，用户新操作优先。
3. **返回时重复点原行反而关闭预览。** 注册原行已有 `C(true)` 打开动作，回程直接调用该原动作，不合成点击来切换开关。
4. **附注错误页重试取消了自己的返回地址。** 同一阅读返回所有者的重试保持原位置；旧请求失去所有权后不再更新当前页。
5. **附注重试成功后 Esc 失效。** 错误页按钮被移除后焦点掉到背景；现在仅在焦点确实落空时移回当前原 Viewer。实屏验证重试后可以正常退出并返回原成员。
6. **跨现场失败没有清晰反馈。** 使用原模块实际导出的 toast，顶部原返回按钮保留重试。源现场已到达但库恢复失败时也保留原返回地址，不自动循环重试。

临时回程只保存导航地址、既有输入地址和相机等 UI 信息。Core 仍持有成员、材料、会话和 Workspace 真值，原输入器仍持有草稿；没有新增持久会话副本或第二套空间真值。
