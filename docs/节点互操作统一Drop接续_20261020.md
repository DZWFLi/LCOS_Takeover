## 同一条调用链

`原节点手势 / 原库行 → 原 Drop store → 原目标 registry / resolver → 原 DropCommitRouter → 各自已有业务 owner → 真实回执 → 原画布/输入器刷新`

- 集合成员、对话上下文、本次输入引用、空间呈现分别沿原业务 owner 写入；共用手势与分派不等于把四者写成同一种操作。
- 整体对象使用已有 `railwayAggregatePayload`；Collection 是 Collection，Context / Workflow 沿现有真实 sourceRef，不假扮文件。
- 原库之前对所有 `lcos_library_entry` 禁用了 `draggable`，现已恢复原列表拖动并接共享 producer。
- 原 aggregate payload 会冻结。原先事后 `defineProperty` 绑定反馈会失败；现在用原 payload 身份关联非序列化 origin metadata，不改 payload、不新增持久队列。
- 库项目身份解析提取为 `native-library-entry.ts`，预览和拖动共享同一函数。
- Collection 投放调用已有 `collections:project`；跨场只同步目标投影，不拿目标节点污染源 API。已经存在则只读复用；写成功丢回包通过 GET 核对，不自动重发 producer。
- 原生 Reader 的第二次 opening 曾吞 Escape；修复在原键盘 owner 调用原 close 排队机制，没有新增全局键盘监听。
