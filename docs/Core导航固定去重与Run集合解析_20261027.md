## Marker POST

原 input / 项目 / sourceSurfaceRef / MutationSafety guard 全部保留。guard 后、原 `addSpatialMarker` 同步事务前，按完整 `(target.projectId, kind, id, scope, sourceSurfaceRef)` 查现有原记录：

| 数量 | 行为 |
| --- | --- |
| 0 | 原 add / ChangeSet / 201 不动。 |

## 原 Entity resolver

`getCollection` / `getRun` 的 exact ID、同 project 候选纳入原 candidateCount。Collection / Run 与 Note / Conversation / Scope / Workspace / Artifact 同 ID 时，继续 unresolved；不按查询顺序挑“看起来像”的对象。

新 typed 对象按自身准确归属解析：

1. 有 workspaceId：原 workspace 同项目、未归档，并有同项目有效 Scope，返回 `workspace:<id>` + 原 entity anchor。
2. 无 workspace、有 scopeId：准确 Scope 对应原 surface；没有支持的 surface 则 unknown-surface。
3. 两者均无：main + 原 entity anchor。

给了但缺失/非法/归档的归属不会偷偷降成 main。新对象不复制 View/Workspace 坐标，也不根据 Run 的 created/running/failed 或阶段决定 GUI 可读性。Run 类型用现 `SqliteMetadataRepository['getRun']` 的真实参数类型。

当前 canonical Collection 没有 scope/workspace 字段，所以正常落 main；Run 已有 workspaceId，正常回原 Workspace。可选 scope 与 archived 字段的故障反例明确属于受控 repository read，不冒称当前 schema 已能保存这些扩展。
