## 本轮修改

| 问题 | 接法 |
|---|---|
| 实时消息没有完整来源归档 | 原 `ConversationImportService` 负责同 session 的 Core 实时 JSONL 归档；原 bind、send、inspect 和 sections/refresh 沿同一服务初始化、追加、补齐 |
| 旧实时记录不能放进 Scope | 原会话读取端口先由同服务补齐归档，再取稳定的原 session/source hash；原 Scope 完整性、附件和版本检查保留 |
| 文件／消息并发与失败 | 文件不原位覆盖；候选写入、同步读回后在原事务复读并 CAS 更新原来源指针。已提交源损坏则拒绝，不从规范化消息重新造一份掩饰 |
| 断线仍显示可发送 | 原会话投影针对该 canonical 只读核对真实 Host owner；断线降为不可发送，可信原恢复入口保留 |
| Host 缺少真实 owner 身份 | 原 daemon hello 不带 appId；原 Host 改为从同一个真实 connection 在原 registry 查唯一 live owner，不能把连接 id 猜成原会话身份 |
| 健康会话误弹恢复卡 | 默认只显示真实失败、unknown、未完成连接等待处理事项；原会话选项“查看会话请求”仍在同一栏保留原取消和恢复动作 |
| 同 ID 新连接误用旧 client | 原 ACP 缓存要求同一个真实 connection 对象且仍在线；关闭旧 client 后走原 prior native resume/load，不能 fallback 新建 |
| 原 facade 缺历史读取映射 | 补原 messages、sections GET 与 sections/refresh POST 精确映射；最终 A2/B 全走 facade，不绕内部 Core |

归档覆盖的是 **Core 实际保存的消息与原上下文回执**，明确标识 Core realtime 来源；不冒充供应商未回传的全部内部事件。保留原消息 ID、序号、角色、正文、工具／文件引用及原 Scope 取用来源，不递归展开过去的整个 Scope 造成自包含复制。
