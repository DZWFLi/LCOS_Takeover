# TapNow 主前端可拆分边界（2026-10-13）

## 结论

可以直接改编译后的组件逻辑，不必先还原原工程：Canvas 的 Agent 侧栏挂载函数 LF 已替换为对可编辑本地模块 startup-custom-panel.js 的调用；该模块使用原页面的 JSX runtime。Agentic Previs 自动介绍由 PB 启动，可单独停掉；遥测初始化也有窄切口。这样保留 Canvas、ReactFlow/Unlimited Mode 和 Library，不靠 CSS 假装删功能。

但 Agent host chunk 不能简单删文件或返回 404：Canvas 路由静态依赖它，模块加载失败会让整个页面停在 spinner。移除组件挂载与拆掉模块是两件事，别把这俩混为一锅。

## 依赖边界：什么可拆，什么只是可隐藏

- 安装目录共有 493 个 JS 文件；主入口 assets/index-BAQXnPag.js 为 13,141,204 bytes，文本扫描到 42 个直接字面动态 import。逐文件字面相对 import 扫描得到 1,139 条边、0 条缺失；从主入口沿这些边可达 491 个 JS 文件。
- Canvas 路由 page-Da_DfwiK.js 为 1,133,571 bytes、24 条直接边（20 static、4 dynamic）。它静态依赖 agent-host-provider-uVo_bky5.js；四个静态导入方共出现 21 个具名导入引用（Canvas 这页有 12 个）。这些是导入声明的计数，不等于每个符号都已证明必要，但 404 实测已证明整块不能删。
- UnlimitedModeToggle-D4wysAbz.js 是 Canvas 的直接静态依赖，含 ReactFlow 实现；Library 数据请求/载入则是独立路径。切 Agent 侧栏不会删除 ReactFlow，也不会替 Library 或 Canvas API 编造成功响应。
- 父任务已记录离线对照：control、断计费、仅 Canvas 详情 + Library GET 且其他 API 返回非成功，都显示 fixture 的 2 个节点；断 Canvas 数据为 0 节点；Agent host chunk 返回 404 后 Canvas 为 spinner/0 节点。Core 未连接。这证明首屏节点可由有限本地响应支撑，不证明拖拽写入或 Library 全部交互已可用；对应交互仍需单独实测。

因此当前最稳的边界是“在 Canvas 页不渲染 Agent panel，但保留它的模块文件和 ESM 链”；真要删除 Agent host 代码，需先把四个静态消费者逐个改成明确的本地 stub/惰性边界，并测完整页面生命周期，不是删一个 chunk 就完事。

根任务后续已完成交互实测：断计费与只留 Canvas/Library 两组都能真实拖拽并打开两条模拟素材记录。17876 组件改造版显示 2 个原版节点、1 个本地面板；面板 details 点击有效，原节点可拖拽、素材列表可打开。该测量窗口 Agent API、归因请求、Sentry 尝试均为 0，宣传弹窗为 0；Statsig 未切，节点内部模型 UI 等其它入口未全部移除。实际证据见 evidence/decomposition-verification.json；这仍不是完整源码工程化或真实 Core 接通。

## 图统计方法与源码还原边界

审计脚本用正则扫描 .js 文件里的字面 from "./..." / import("./...")，再以文件为节点运行 Tarjan SCC。它不是完整 AST：不捕获计算出来的 import、条件运行时可达性、绑定实际使用点或源码级模块边界。扫描把 static 和 dynamic 都纳入静态图；因此 322 个 SCC 中的 172 节点最大环，不能直接解释成 172 个强耦合业务组件，也不代表这 172 个 chunk 会在首屏加载。

包里出现的是压缩后的 jsx/jsxs runtime 调用，足以判断 JSX 已编译，但不能反推出源文件扩展名究竟是 .jsx 还是 .tsx。变量/组件名大量缩短，类型、注释和原始文件组织也不在 bundle 里。可复现的是当前被观察到的行为和组件边界；逐页恢复成可维护源码，需要另做调用链、API 合约和交互验证，不能把几条字符串切口误当作恢复了原工程，也不在证据不足时估工期。
