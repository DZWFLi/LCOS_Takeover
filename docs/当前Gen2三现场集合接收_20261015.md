### 发现并纠正的旧夹具偏差

当前 Gen2 原 `buildSurfaceCanvasMap` 与 Core seed 明确：一级三个 Workspace 共享项目 root Scope。Main／Context 共享 `presentation:context:<root>` 的成员真值；Workflow 是同 root 的 workflow capability。三个画布与几何仍各自独立，不能把「现场隔离」误写成三个 Presentation 全不相关。

旧实验 factory 把 Context／Workflow 两个一级 Workspace 改挂到合成 child Scope，是历史夹具偏差。本批仅修新合成 runtime 初始化：保留两份 Saved Context/Workflow Scope 供原会话/方法测试，但不再拿它们冒充一级导航；已持久化的旧 runtime 完全不迁移。

新宿主通过原 Core graph/workspaces 只读客户端取唯一 root，再调用原 `buildSurfaceCanvasMap`，不凭 preferredSurface/status 顺序认一级。原 `PortalDropWorkspaceProvider` 与 `surfaceDockDropSemantic` 直接复用；普通 child 留在原 Workspace 路径，Collection→child 当前仍不支持，不改 Core 支持矩阵。

显式资源清单由 39 扩到 42，新增的是三个原地址/Context owner。首次目标测试在旧数量断言 `42 !== 39` 处停止；这是测试清单需要同步，不是运行时通过。后续复跑结果另记。
