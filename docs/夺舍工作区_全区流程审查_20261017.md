## 结论

**问题不止 Assembly。这个工作区仍是 TapNow 原框架、GN2 旧页面和新写过渡组件的混合体，不能据此认定 GUI 已融合，也不能直接当作已经迁完的 GEN2 主线。** 原画布、库、右栏和 Collection 主体值得保留；需要纠正的是功能的归属和完整操作链。

- 第一层已换成原右栏，续聊子组件的“查看原请求／核对或恢复”仍会开旧 GN2 会话窗。

## 施工顺序与每项的验证方式

1. **先修断链和真实功能缺口**：续聊 child 旧窗、Collection merge/addMember、普通库投放生产 route/O8 发布、语义 Drag、动态子现场。不要继续增加外围管理窗。
2. **再统一查看与返回**：库/节点/结果/引用全部进入原 Viewer；处理 source/locator/旧返回地址，实接更多动作和各格式。随后迁旧状态恢复，不能先删 Stage。
3. **再收原容器内部硬搬布局**：原标题历史、任务行、等待回答/结果卡、Collection 标题/成员/工具，保留数据和 controller，换回原页面的层级与操作位置。
4. **补能力与视觉完整性**：来源/收件/Skills/归档、方法编辑、Agent 创建槽、History/模板；贯穿校正浅色、密度、光效和动效。

每项用普通测试与真实隔离 GUI 记录：从哪个原入口进、开在何处、一次动作改变什么、成功/失败/unknown 怎么继续、最终回哪里、已有能力和保护是否还在。正常、空、慢、失败、换现场分别核对。没有新增 hash、冻结 contract、baseline 或 gate。
