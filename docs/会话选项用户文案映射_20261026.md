# 原会话选项：用户文案映射与原功能保护

日期：2026-10-26。状态：lab 实现及实际 TSX / 原 handler 专项 **7 组 PASS**；最终Core81248真实原页完整范围已通过，含四模式、W1、原加号图片确版点选 / 取消 / 移除、360确认滚动可达。未执行连接、确认或模型。早先失败报告保留。

## 结论

原会话选项仍是同一个组件、同一原页面。四模式的 action、capability、Icon、选中值、确认禁用条件、原提交/回执校验/重试/请求身份与归属保护不变。只在这个组件的呈现位置将已知产品语义转换为用户文案，不改后端数据，也不使用字符串黑名单清洗原证据。

## 实际披露点与处理

| 原位置 | 问题 | 本轮处理 |
| --- | --- | --- |
| capabilityReason | 直接显示 capabilityReasons；真实 canFork=false 的原因包含 authoritative native fork probe / Agenetes.fork | 依据选中 action、真实能力布尔值与读取状态描述“这项现在能否做”。能力 true 仍无阻塞原因；false 不暗换方式。原 capabilityReasons 对象完整保留 |
| request.error.userMessage | 原产品错误可能含 Core、HTTP、operation 或协议细节 | 只在原错误段按既有产品 code/action/retryable 解释；原 error、diagnosticsRef、retryable、intent、operationId 不变。未知可重试错误仍有原重试 |
| 继承 / 精选等模式名 | 不容易理解开始方式与携带范围 | 原 fieldset 改“开始方式”；保原布局和四 radio，完善各自历史/材料说明 |
| 本次提交 · 只读快照 | 内部快照术语 | 改为“本次确认的材料”；原提交引用快照依旧不可被后续草稿编辑改写 |
| 请求已提交，等待外部确认 | 接受 journal 与连接确认需分清 | 改“已提交，等待连接结果确认。你可以继续编辑草稿。”；仍不把 accepted 当已连接 |
| 会话工作窗 / 核对或恢复原操作 | 旧窗口用语和内部操作称呼 | 改为查看原请求与核对连接结果；原精确请求回路和 handler 保留 |
| imports / data-error-code / operation 字段 | 它们不是用户可见文案 | 不删除、不泛替换，保留实际控制器、调试定位与身份信息 |

## 原四种方式

| 原 action / capability | 原布局短名 | 解释与继承边界 |
| --- | --- | --- |
| continue_existing / canResume | 接着聊 | 继续当前对话，保留历史，沿用原上下文，不附加这次草稿中的材料 |
| selected_context / canSelectedContext | 带材料 | 用下方确认的材料新建，不带入原对话历史 |
| blank_new / canBlankNew | 空白 | 新建空白对话，不带入原历史、当前材料或草稿 |
| native_full_fork / canFork | 历史分支 | 从历史创建分支，仅带入已完成且协作者支持分支的历史；原对话保留，不自动附加这次草稿 |

当前真实 canFork=false 对应原因与确认按钮 title：**“目前不能从完整历史创建分支；原对话和历史保留。”** 该项保持 native_full_fork 选中，确认仍不可用；不会自动退成 selected_context。

支持某项不等于忽略其它原要求。例如 selected_context 没有材料时，仍由原 referenceReason 提醒先加入材料，确认继续禁用。canSend=false 不代表独立 canResume/canSelectedContext/canBlankNew 也为 false。
