## 最小施工建议（本次不实施）

1. **先移出请求线程。** 抽出 server 已有原顺序为同一纯变换函数，由[现 start-full-integration 构建:54](<E:/Codex 项目/LCOS夺舍计划_20261013/scripts/start-full-integration.mjs:54>) 调用，随本轮 native UI 构建在同 runtime 的产物目录写原名 vendor 输出；server 读这些已生成文本，其他 vendor 仍原路径。保持现所有 seam 校验、先后顺序与网络隔离，不引入 hash、第二套变换或缓存协议。当前 `--build-ui-only` 并未预处理这些 vendor，`--reuse-native-ui` 也不会复用进程 Map。
2. **预编译解决的是浏览期间阻塞，不会凭空降低总 CPU。** 下一轮记录现构建 stage 的用时、每资产转换用时与首开 ready 时间，便能区分“成本前移”和“成本减少”。不靠增大 ready timeout 宣称修复。
3. **低风险消重先动同一个 owner 内部。** Dock 对完全同一 source 连 parse 两次，可复用第一次 program，保安装前/后的完整检查。Library contexts 输出验证后的 AST 随即被 viewport 再 parse，Pile 安装输出 AST 随即被 gallery paint 再 parse，也可以让内部 helper 复用对应同文本的 program。只复用精确当前文本；任何字符串改写后不能继续拿旧 offset AST。不要先做全局 AST 缓存或删输出验证。

后续必要验证：同现 profile 预编译输出与原链逐字一致；原入口、Viewer/Composer、Scope Back、摘录 Undo/Redo 的既有专项不退；新进程首开与同进程 warm 各测一次。当前记 **P1 未施工/未实测优化收益**，不挤占本轮摘录真实闭环。
