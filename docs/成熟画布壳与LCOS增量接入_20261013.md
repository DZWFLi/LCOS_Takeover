# 成熟画布壳与 LCOS 增量接入

## 结论

路线成立：不是重新打磨一套画布，而是保留 TapNow 成熟的画布/节点交互，让 LCOS Core 承接内容、上下文和执行，把我们独有的 Agent 画布对象、Context 与 Workflow 作为增量能力接入。

这不只是换皮，也不要求恢复全部原 TSX。通用画布操作尽量沿用；涉及我们自己的业务对象和行为时，用窄适配与自有组件。不是把所有云 API 一比一仿造，而是只翻译实际需要的协议，舍弃厂商云账户、权益与业务体系。

本文件讨论的是 TapNow，本机 Desktop 0.4.95 / Web bundle 2026.10.10.38066889187.1，不是开源 Typebot。

## LCOS 到底负责什么

LCOS 不是单独一张漂亮画布。它是项目、材料/版本、上下文、会话、Run 和成果复核的工作系统；画布是这些对象的空间呈现与操作界面。

当前独立实验采用：原 TapNow 是唯一前端画布；原 Core 管内容与领域身份；原 Huabu 的无头 storage/executor 管空间几何。facade 只翻译请求，不另存一份画布 JSON 真值。正式 GN2 仍使用原 Huabu 前端，本轮没有改其生产架构约束。

## 哪些借，哪些加

| 用户能力 | 成熟壳可借的部分 | LCOS 必须保留的部分 | 目前证据 |
| --- | --- | --- | --- |
| Main / Context / Workflow | 原多画布的切换、flush、preflight 与加载 | 同 Project 的三个 Workspace / 独立 canvasId | 本轮真实 Core 实现；原 UI 验证记录见下 |
| 图片与文本 | 原节点卡面、富文本编辑、拖动和缩放 | Artifact、Revision、FileRecord、正文/版本冲突 | 本轮支持文件读取、正文和几何保存 |
| 节点堆叠/集合 | 空间父子布局与对应交互机制 | 材料集合 membership，与“是否叠在一起”分开 | 已确认 donor group 是空间父组、collection 是画布目录；折叠/堆叠完整闭环仍未测 |
| Color Pin / 游标 / 地图钉 | 导航入口、标记呈现与交互值得复用 | Core 成员关系、对象定位与我们的导航语义 | donor Pin 当前只确认入口，不把同名当成相同机制 |
| Agent 摆在画布上 | 节点容器、坐标、选区、连接与产物排布 | Conversation/Glyth、上下文投放、运行状态、Run 和结果归属 | LCOS 原代码已有；尚未挂入本轮 TapNow 新模式 |
| Context | 原画布材料选择与工具挂载点 | Warehouse / Assembly / Saved Context，已有读取与 apply | 已审源；当前 Context 场景只有真实图片文本，不是全套 Context 工具接好 |
| Workflow | 画布节点排布、卡面和选区 | 方法草稿、Composer、Run/Review 及真实执行路由 | 已审源；方法转未发送草稿不等于任意流程图自动执行分支 |

“已有”只表示复制源码中存在该能力，不表示已在新壳完成端到端测试。也不据此断言所有更新版本的 TapNow 都没有这些能力。

## Agent 的巧接方式

把 Agent 当有身份的会话节点，而不是固定侧栏：节点绑定现有 Conversation；材料投放沿用已有 Assembly；指令沿用 Composer/Run；产物由 Core 登记后投影回 Agent 周围。

现有 GlythNodeBody 已有会话实体绑定、双击打开会话工作视图、状态呈现和上下文 drop。可以复用它的业务能力，但整个 Huabu 宿主组件树不能盲目 import 到 TapNow：路由、store、drop 注册、密度与宿主窗口有依赖。更适合用当前 canvasId/选区 → 持久 binding → Core refs 的窄桥，再挂自有节点呈现与工具窗口，不再挂第二张 Canvas。

这类能力接入比重做全部成熟节点交互更聚焦，但不是“改按钮文字”级别。复制/撤销身份、跨现场引用、结果落点与冲突恢复仍需要真实测试。

## 未接范围与下一步
