## 原因与改法

原方法 builder 只追加 Artifact 引用：步骤文字能进入输入，`memberEntityRefs` 中的集合、附注、对话和 Run 却未跟随整份方法发送。共享 Scope reader 又只取第一份 Workflow Presentation，可能丢掉第二组。View 身份和 operator 键相同时，真实材料也可能被当作结构标记过滤。

本轮保留原材料存在性和版本校验，改为完整方法 Scope 引用，再由原发送读取链解析全部内容，没有在前端手写另一份成员快照。

| 位置 | 本轮接线 |
| --- | --- |
| 原 Gallery／原资料库／原 Drop | 共用原 builder；通过校验后追加完整 workflow Scope 与可编辑步骤，保留原稿、已有引用、接收者、消息及续聊身份；同方法重复取用不重复追加 |
| 原 Gallery 取用前检查 | 重新读取并比较真实 Presentation 全行，成员变化不会被同一 Scope 地址掩盖；取消、切输入、迟到结果不能误写新稿 |
| 原 Composer 引用查看 | 按 project＋kind＋Scope 身份打开原库精确方法行；同名不同方法不串行，返回同一份未发送输入 |
| 原共享 reader | 读取全部合法 Workflow 方法组，保留各组版本、步骤、连线、条件、成员；显式指定单组时仍只读该组，空 ID 不退回整份；同 ID 的真实 View 不再丢失 |
| 原普通任务 | 完整内容进入原 ContextManifest 与 Run recipe，沿原创建／待执行流程 |
| 原续聊 | 完整内容沿原 context attach、Host transport、ACP 资源与 send 发送，由原实时归档保存问答 |
| 原库窄屏预览 | 修复 Popover 翻到左侧屏幕外；复用原弹层，窄屏上下放置并提供四边碰撞留白，原桌面和供应商普通材料行定位保持 |

取用保存方法地址，**发送时读取完整内容**。输入里的步骤正文仍由用户编辑，不是取用时锁版副本。多组的兼容主锚仍是第一份真实 Presentation，`source.presentations` 才是全部真实组，主锚不代表只读第一组。

缺员、不可读、不支持的内容或读取期间变化，仍整份失败并保留输入；不能静默跳过或截断后发送。未新增冻结协议、hash、baseline、gate，也未删除已有保护。
