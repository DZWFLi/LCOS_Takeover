## 已证明范围

| 检查 | 实际结果 |
| --- | --- |
| 准确摘录准入 | project/artifact/revision/View/FileRecord 和 payload quote 必须吻合；错误 content kind、quote 或非法 Range 均在入稿/close 前拒绝 |
| 原输入 | 实际原 caret 中间插入来源摘录，前后原文保留；原引用携准确版本和本次位置；明确“尚未发送” |
| 无关全局 Selection | 故意选中正文之外的文本，实际 Host 只使用局部传来的确版 payload，不把外部文本塞进输入 |
| 旧 owner | 同 inputKey 换 message/op、换 Canvas API/项目、卸载后调用旧回调，均不入新稿；同原页面消息/操作变化不误关阅读 |
| 原 More 多位置 | A/B 均无默认；点击 B 再 A，仍是 r1，正文 source 收到正确 selected；同版新 operation 的 actions key 变化，旧 busy 不遗留 |
| 显式换版本 | 原 select 切 r1→r2，准确打开 r2，清旧 locator，不套旧 offset |
| 来源二跳与返回 | 原 action 先复核 canonical evidence，进入 parent-r1 的准确位置；原 Back 返回 r1 的完整 A/B 组及已选 B，不改用 Current |
| 导图保存回调 | 执行实际 JSX 上 `onSaved`，进入所确认 r3/v3，清旧 locator；未调用编辑器保存 producer |
| 普通整份引用 | delegate 原“加入当前输入”无选区 payload 仍可用；引用与位置入原稿，原文字保留，不发送 |
| 无确版位置 | sourceLocator 存在但无显式 revision/View 时，在同一原 Viewer 给出具名错误，0 GET、稿不变；无 locator 仍可续读记忆 r2 |
| 准入后换输入 | 实际 ReferenceStore 订阅在 admission 发布时切 message，新稿不被旧摘录写入、不误关阅读；实际 Shell 订阅在 prompt 发布时切 operation，新稿/caret 亦保持 |
| 发送中 | 原 referenceInputOperations 的 sending owner 拒绝写草稿，原正文继续可读；解除该确切操作后整份引用可正常使用 |
