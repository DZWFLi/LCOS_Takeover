## 为什么这条路成立

Core 本来就是本地 HTTP server，不用假装厂商服务器。接入只翻译节点的内容身份和动作，不把 Core 改成 TapNow 的业务模型。LCOS 仍是本地创作项目总导演台，不变成厂商云服务的仿制后台。

| 内容 | 本轮实际使用 |
| --- | --- |
| 项目、图片、正文、版本 | 复制源码启动的原 Local Core，真实 HTTP / SQLite / 文件 |
| 坐标、尺寸、连线、保存 | 原 Huabu storage、executor 与 Canvas store |
| 图片显示与过渡 | 原 TapNow vT / ZY 定义 |
| 文本正文呈现与双击入口 | 原 TapNow e4 / CT 定义 |
| 标题呈现 | 原 TapNow _ie 的只读分支 |
| Markdown 解析、文本编辑 | LCOS 已有 Milkdown，非原厂完整编辑器 |

只保留一个原 Huabu Canvas 和一份宿主 React。没有加载厂商主 bundle、厂商 ReactFlow 或厂商节点 store，也没有重新实现画布。

## 复用了多少，没复用什么

从 Desktop 0.4.95 的 `course-api-base-url-CifxI1ia.js` 按 AST 精确边界提取 11 个定义；生成模块 4,378 字节，另提取 38 条原正文 CSS。定义内容保留，依赖通过工厂参数接宿主 React、jsx、翻译、Markdown 等；来源偏移保存在 `evidence/recovered-node-leaves.json`。

这 4.4 KB 是本轮采用的呈现 leaf，不是整个前端，也不是原始 TSX 已反编译回来。原整包 JS 约 41.35 MB，不能拿这个体积推算业务代码重建量或工时。

本轮没有采用原整套 Tiptap 编辑器、节点工具栏、生成历史、上传/下载任务、登录、积分、协作、Desktop IPC 或更新器。厂商许可尚未确认；原件及提取物只用于私有本地研究，未上传或再分发。

## 怎么接的

1. 新合成项目 `disposable-mvp-sample`、新 Core DB，绑定实验画布 `takeover-pilot-canvas`。
2. 本地合成图片经原 `importCopiedFile` 登记为 Artifact / Revision / FileRecord；原 vT 读取 FileRecord 内容地址。没有模型生成任务。
3. 文本双击后用原 Milkdown 编辑，沿原 `saveCanvasText` 保存同一 Artifact 的新 Revision，保留过期版本 409 检查。
4. 保存确认后读取 Core 当前正文，再用原 `MERGE_NODE_DATA` 更新 Huabu 预览 sidecar；body 是投影缓存，不是第二份正文真值。
5. 浏览器通过原空 delta 回执路径确认 Huabu `toVersion`，再更新既有 store 投影；不增加独立 store，不移除冲突保护，不为预览创造正文 undo 历史。

Core 已保存、投影失败时，界面单独提示并提供“重试同步预览”，不会误报正文未保存。跨标签竞争、断网重试和文本版本 undo 仍需后续专门验证。
