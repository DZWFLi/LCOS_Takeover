# REA 静态对照实测

日期：2026-10-13（Asia/Shanghai）。工作区：LCOS-DSH-03。

## 先说结论

试完了：REA 有真实的依赖索引增量，但在当前 TapNow 编译包、Windows 与本轮资源预算下，深层语义恢复明显受限。不建议现在把它接成夺舍主线，也没必要先改 MCP。

最有用的发现是 Vite 预加载依赖展开；最重要的限制是 IPC 常量没打通、HTML 内联代码没进 AST、Canvas 语义分析耗尽堆内存。没有恢复可维护 TSX 工程，也没有因此多拿到可直接使用的组件。

这修正了上一轮只看资料的乐观预期：能力清单确实存在，但当前这包的实测效果更有限。不是判定 REA 无用，也不是证明提高资源预算没有帮助；后者本轮未测。

## 实际怎么跑的

固定 npm 包 rea-agents@6.4.0，实际 CLI 版本返回 6.4.0；Node v22.22.3。通过 npm 临时缓存取得工具，禁用 npm 安装脚本，没有全局安装、rea setup、MCP 注册或 provider 安装。

目标只读复制材料：三份 desktop-shell JS、复制包 Web 目录及其 apps 工具目录。随后另复制五个原始 ESM 资产做局部试验，逐字节比对一致；原 reference 文件不改。

执行的是 REA 分析器及其自有 helper，不是 TapNow 代码。没有启动 EXE/updater、页面、IPC、Core 或云端业务，也没改数据库、账户、原工作区或现有离线服务。

每个源的分析器 V8 old-space 预算为 1024 MiB；整包 Web 单源时限 30 秒，桌面壳/Canvas 局部为 60 秒；另有独立整体时间上限。本轮没有触发整体强制终止，Web 的失败来自 REA 单源时限。

工作集是每 5 秒采样的 REA 自有进程树之和，不是精确峰值 RSS，也不是源分析器单进程堆占用。HTML 的原始测量写了 0，是未采到活进程；汇总已转为 null，不能说它不占内存。耗时包括启动、结果输出及少量测量开销，不是纯 Babel 解析时间。

退出 0 不等于语义恢复完整。各组 parse_failures 为 0 也不意味着没有资源失败或未知。REA statistics.modules=0 不能解释成未读取 ESM；实际 parsed_javascript_files、imports 和图节点需要分别看。

小型汇总：[rea-static-comparison.json](<E:/Codex 项目/LCOS夺舍计划_20261013/evidence/rea-static-comparison.json>)。原始结果仅留 .runtime/rea-static-20261013/，不进 Git：桌面约 4.92 MB、HTML 74.5 KB、整包错误/部分结果约 57.34 MB、Canvas 局部约 29.83 MB。报告大，不等于源码回收得多。

## 桌面 IPC：找到局部证据，没有打通链

已有专项核对：77 个唯一 channel 字符串、14 组；2 个 bridge global、76 个 callable 方法与 5 个标量属性。

REA 的输出：

- 命中 tapDesktop 和 tapCapture 两个 global，但 exposed_api_members=0，没有枚举出方法树。
- 139 个 IPC operation observations：68 transmissions、8 listeners、63 main handlers。这个单位不是唯一通道数。
- literal_channels=0、dynamic_channel_operations=139、paired_renderer_transmissions=0。
- 两份 preload 的 semantic graph 各保留 77 个通道字面值；154 个 literal 节点去重仍是 77。常量在图里，不代表已经绑定到调用。
- IPC 观察仍停在 o.openDirectory、G.openDirectory 一类成员表达式，channel=null / dynamic。main.cjs 的语义图还受 parent result budget 限制。

目录授权/文件读取、区域捕获、Shell proposal/执行三条链，都能找到各自调用点或注册点，但没有完整 renderer → preload → literal channel → main handler 配对。不能把未配对写成能力不存在，也不能写成已验证授权安全。

额外真正运行了 trace-javascript-semantics：以 tap-desktop:local-files:open-directory 字面值做 forward-influence 查询。耗时 3.75 秒，返回 ambiguous、partial；2 个种子、5 个节点、3 条关系、1 个函数、2 个模块。没有打通端到端调用链。

因此，这一轮 REA 没超过已有的 77 通道专项审计；局部图可供辅助查询，但不能用它的通道统计替换原口径。

## Canvas：有预加载增量，但组件语义没恢复

五个原样资产：page-Da_DfwiK.js、agent-host-provider-uVo_bky5.js、CanvasDevTools-Ca0vASx7.js、index-D3gYo15G.js、page-D__yp7hl.js。没有复制 13 MB shared main 或其它 imports，也没有伪造 stub，所以不是整应用覆盖。

有效增量：

- 原专项扫描的 Canvas 20 个 static import，REA 同口径也找到 20 个。
- 原扫描有 4 个字面 import() 调用；REA 展开为 90 条 dynamic-import 关系。
- 按精确 specifier + source range 去重仍是 90 对，但只有 8 个源码范围：4 个导入目标 + 4 组 Vite preload 数组，后者分别含 27、2、37、20 条关系，共 86 条。
- 这是预加载依赖索引增量，不是新增 86 个组件、功能或运行时已加载模块。可用于后续确认懒加载功能需要携带哪些资产。

未完成的部分：

- 已有审计确认 provider 有 4 个消费者、21 个 named binding references，其中 Canvas 占 12 个。
- REA binding-level 图只恢复另外 3 个消费者的 9 个 alias（5 + 1 + 3），Canvas 的 12 个未恢复；没有形成完整绑定闭环。
- Canvas semantic worker 报 exhausted heap；Agent host 和另一个 page 报 parent remaining result budget 限制。
- Canvas 归属的 function nodes 为 0。因此 LF、PB、DB 的语义状态是未知，而不是函数不存在。它们此前在原文件的字面锚点都能唯一定位。

这说明静态导入提取能用；“谁调用谁、如何取出组件”的更深层分析，本轮还没有成功覆盖我们最关心的 Canvas。

## HTML 与整包：两个明确边界

HTML：工具目录读入 17,934,975 B，relevant_files=25，但 parsed_javascript_files、visited_ast_nodes、findings 都是 0。semantic graph 只有 unavailable root，0 relations，coverage unknown。确认本轮没有对 24 个工具的内联脚本做 JS AST/语义分析。文件清单完整不等于理解了工具行为，findings=0 也不等于无风险。

整包：扫描到 524 个相关文本文件，已完成 211 个 JS；最后进度停在第 212 个、assets/index-BAQXnPag.js。30 秒单源预算到期，返回 provider_timeout 和可解析的 partial_observation。Canvas 未被独立处理，不能拿之前模块指向 Canvas 的 incoming edge 冒充 Canvas 自身的 24 个 outgoing imports。

这只是固定版本、固定预算下的结果。增加堆或时限可能改变结果，不能从这一轮外推“永远跑不了”；但不应把未跑完的整包图用于声明依赖完整、某功能不存在或可以安全删除。

## 下一步建议

REA 先保持一次性 CLI 辅助工具，不注册成常驻 MCP，不为了完成工具接入而耽误真正组件回收。

主线继续使用已证有效的窄 AST/字面分析、原挂载点替换与真实离线操作。要复用组件，就围绕一个已定位接缝提取、改名、模块化、接自己的数据；不要把完整语义图当开工条件。

只有遇到明确需要函数关系图的问题，再选更小的纯逻辑片段做 REA 定点分析，或单独安排更高资源预算的复测。本轮未调整至更高堆预算，也未调用 Linux-only Wakaru 源码恢复路线。

## 复跑与归档

实验脚本只从固定版本缓存运行，不自行下载、setup 或启动产品。获取工具和跑静态实验是分开的：

```powershell
npm exec --yes --ignore-scripts --package=rea-agents@6.4.0 -- rea --version
node scripts/rea-static-probe.mjs --label desktop-shell --input reference/desktop-shell --source-ms 60000 --overall-ms 180000
node scripts/rea-static-probe.mjs --label html-tools --input reference/tapnow-installed/resources/web/usercontent-proxy/apps --source-ms 30000 --overall-ms 90000
node scripts/rea-static-probe.mjs --label web-full --input reference/tapnow-installed/resources/web --source-ms 30000 --overall-ms 240000
node scripts/rea-static-probe.mjs --label canvas-slice --canvas-slice --source-ms 60000 --overall-ms 180000
```

每次创建新的唯一输出目录，不覆盖既有原始结果。rea-trace-probe.mjs 接受已完成实验目录；rea-static-summary.mjs 接受四个实验目录及可选 --trace 查询目录，再生成小型汇总。重跑使用新目录，不把旧查询混成新结果。

本轮新增三个测量/汇总脚本、一份 JSON 证据和本报告；另在前期调研报告加入实测链接。没有提交、push、删除材料，也没有给 LCOS 新增 hash、contract、baseline 或 gate。REA 自身已有的 Evidence 哈希字段保持原样，没升级为我们的新门禁。
