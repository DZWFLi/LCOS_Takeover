## 从哪里使用

1. 在原画布选中图片／文本／集合等已有原浮条的节点，打开原“更多”。
2. “强调”给对象加一圈轻光和下沿彩色光场；再次选择“取消强调”关闭。原撤销／重做可恢复。
3. “固定到导航”留下独立于颜色分类的空间大头钉。目标移到视口外时，同一标记变成方向提示。
4. 点击标记或原“定位”，沿原相机前往目标，出现短暂抵达光环。点击“返回原视角”恢复出发相机位置。
5. 原“取消固定”仅移除这条导航意图，保留内容、节点、颜色和布局。

原更多菜单本来不可用的状态仍保留其权限，不解禁旧动作，也不另外叠第二个更多菜单。当前没有原浮条的节点家族，不能由适配器支持推定已有可见入口。

## 关键边界与修复

- 固定目标先核项目、现场、binding 和准确引用。Run 使用真实 `lcos_execution_ref`，不拿另一种人工 fixture 形状代替。旧 resolver 尚不支持的实体解析仍照实保留；本现场定位由准确原节点证据完成。
- 固定写入丢回执时保留待核对状态，只读核对，不自动再创建。离开现场再返回，核对入口仍可用。
- 定位等待过程中切现场、换引用、换 binding 或主动平移，会中止旧请求。解析后再次读取绑定，避免指向已经换对象的节点。
- 返回也受同一原相机取消机制控制；返回途中手动平移／缩放可中断，旧回调不会清掉新导航的返回记录。
- 屏边几何保留 44px 命中区、连续过渡、临界滞回、同方向聚合与原控件避让；原画布可拖动，整层不拦 Drop、框选或输入。
- Lucide Navigation2 的真实 SVG 默认朝上，按这一原方向校准旋转补偿。不能只证明“有箭头”就当方向准确。
- 窄屏首测发现返回按钮只有 28px 高，已补到最少 44px，后续真实页面结果另列。
- 新显示字段会随原复制／历史序列化透传；原生命周期曾不认识它，导致正常复制／删除恢复误拒。已沿原生命周期补窄布尔偏好通道，保留内容、身份、像素和未知字段保护；专项结果另列。
- 光环按当前真实可见画布裁切，避免节点移到侧栏底下时，装饰线和光场透到原库或对话栏上；命中区和相机不受裁切层影响。

没有新增 hash、冻结 contract、baseline 或 gate；没有用删除已有保护换取通过。

### 抵达后白闪的补查

最终截图复核发现，19:42 的第10张窄屏抵达图只有白内容框。该轮证明了导航操作、相机、命中区和光环，并没有检查主图解码，不能扩写成“窄屏媒体呈现也完整通过”。

随后用原中键做只读快速离屏／回屏，在 `.648` 缩放下记录真实 DOM：回屏约11ms时节点已在视野内但主图尚未挂载；约224ms及600／1200ms主图均已挂载且解码成功，原缩略图URL返回200。原节点、连线、领域图、标记没有改动。问题是短白闪，不是永久缺图。[只读观察与分时截图](<E:/Codex 项目/LCOS夺舍计划_20261013/output/原生导航与强调_20261026/只读快速回屏-2026-10-25T19-58-55-460Z/report.json>)。

源头是原 `gw` 可见性 hook：按真实节点和原相机判断相交，首次之后的入屏延迟500ms，离屏保留1000ms，再控制原主图挂载。修复只针对明确导航到、且实际已入屏的准确目标，让它沿原首次入屏分支立即显示；保留普通节点的500／1000ms策略和原 `vT` 图片组件，不增加第二套可见性存储，不靠推迟截图通过。

Core88096 首轮补验在原220ms取样处被测试误拒：原 `vT` 以 small／thumbnail 双缓冲切换清晰度，旧缓冲层虽 `aria-hidden=true`，实际仍以opacity=1显示完整原图；新缓冲已解码，正在原180ms淡入。`aria-hidden`是读屏语义，不能当作视觉不可见。原取样及失败截图保留；测试改为检查同一准确原媒体任一实际可见、完整解码的原缓冲层，不改产品、不增加等待。[误拒原证据](<E:/Codex 项目/LCOS夺舍计划_20261013/output/原生导航与强调_20261026/2026-10-25T20-17-49-972Z/report.json>)。随后只用原菜单取消本轮确证创建的标记，未删其他记录。[原UI清理证据](<E:/Codex 项目/LCOS夺舍计划_20261013/output/原生导航与强调_20261026/2026-10-25T20-19-35-166Z/report.json>)。

本轮复核还看到窄屏右下助手球和帮助按钮重叠。已沿原MF wrapper的bottom变量接入同一单向布局观察器，按原底行→Dock→MF避让，不让两个浮层互相追着抬升；原帮助、助手按钮及600ms形变保留。最后整页结果另列。
