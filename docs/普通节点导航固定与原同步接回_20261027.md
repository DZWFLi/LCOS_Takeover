## 第四轮 Collection 目录前往失败的只读归因

证据：`output/非材料导航与颜色_20261027/真实原页/2026-10-27T15-32-59-081Z/report.json`。

原 More 固定、同开目录内真实 MCP 删除/重加已有准确回执；目录候选确实 ready。但原导航预读 `POST /api/lcos/core/projects/:project/navigation/resolve` 被该轮 harness 记为 `allowed:false` 并 abort。`native-navigation-directory-state.ts:254` 先 await 这条只读语义请求，之后才关目录、确认原现场并调相机，因此异常在真实相机调用前已进入原 catch。这是明确拦截原因，不是增加等待能解决的问题，也不能据此误修 pile 相机。

该报告其他被拦请求仅 23 笔遥测和 4 笔确实写投影的 execution reconcile；没有其他误拦读取，`routeErrors=[]`、`unknownWrite=false`。同项目事件与准确 Canvas SSE 都已放行。Root 已交 Canvas agent 仅为 fixture 已知 targetRef 放行原 resolve；本代理没有改产品或现场。

源层只读核对：原 `createOriginalNodeApi.getNodesBounds(ids)` 先把 id 转为实际原节点，再调用原 ReactFlow getter；未发现把 pile 的字符串 id 当 Node 传入的特例错误。真实 pile 定位/返回仍待该轮继续验证，本档不把未执行的相机链写成通过。
