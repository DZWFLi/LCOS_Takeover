## 实屏抓到并修好的问题

1. 旧 Scope 取用展平为材料，混合成员被拒绝或遗漏：现在保留单个原 Scope，由原提交所有者完整解析。
2. 同一个输入键可能续到另一条消息：查看请求和报错同时核对 message、operation、项目和原画布 API，旧失败不落新输入。
3. 用户改看另一个引用，慢请求仍可能弹回旧 Scope：沿原 inspection 取消信号终止，库关闭、替换请求和期限也结束旧请求；真实 graph GET 收到取消信号。
4. 返回输入失败被静默吞掉：原返回地址保留，沿原 Toast 给“再试返回”，旧重试不能操作新消息。
5. 原 manifest 的锁定要求被 JSON 包裹挡住：按各成员原正文继续使用原提取，不漏“保留／锁定”行，仍保留原非指令包裹。
6. 对话归档和附件只传 metadata 会造成假完整：调用原归档所有者检查，附件需可核原版本并真正读取正文，不能用 Current 替历史附件。
7. 新的未打开工作集暴露导航假设：启动、原三现场状态和 Canvas 列表不再把无画布工作集当画布路径；Core 原对象、Scope 成员和工作集内容全部保留。修复前真实409和错误状态已存“未打开工作集投影”报告目录。
8. 图片 Scope 被泛化成“状态变化”：原路由仅保留明确类型不支持的结构码，原 Composer 显示准确说明；没有新预检页面、隐藏按钮或直接透传内部术语。

测试中还修正了旧 harness：原 full 模式允许省略、原库退场需等实际 hidden、PNG 应走原提交验证而非假设取用即预检；集合放置 harness 跟进真实函数迁移与 host 身份。没有 force 点击、删原断言或用新窗口绕开。

## 没接通的继续记账

| 情况 | 目前处理与后续 |
|---|---|
| Scope 含图片、PDF、音视频或不支持文本文件 | 整份失败并保留引用和输入；尚未建立多模态完整附加通路，不能只发标题或丢掉附件 |
| 历史附件只有文件路径／Artifact，没有可核原版本 | 整份明确拒绝；原通用 fileRef 结构缺原 Revision，需要后续补归档版本来源，不能拿 Current 顶替历史附件 |
| 对话没有完整原归档、身份未链接或含不可读媒体 | 整份明确拒绝；不能改读另一会话或只取规范化文字 |
| 当前隔离导入对话的发送 owner 离线 | 真实 GUI 可验证原续聊输入与 Scope 引用；不能据此声称已经真实发送模型。续聊正文附加与发送以本地受控原链路验证 |
| 新合成工作集尚未打开过画布 | 真实成员可读取，没有伪造 canvasId；本次取用不代替跨现场创建／打开能力 |
