# 普通 Frame 子文字：准确正文与只读呈现

日期：2026-10-28。本批只交付普通 Huabu note 的准确只读呈现；不把编辑、导图、生成或入库说成已接通。

## 结论

此前子节点并非没有正文：原 Huabu 的 `Space.nodes.read(id).record` 保存 label/content，而 facade 的普通 fallback 只读空间几何里的 `node.data.content`，拆分存储后就会读空。另一个问题是原 TapNow `o4` 没有 `data.type` 时默认走生成节点；仅补文字字段还不够。

现在沿原 `o4 → r4 → e4` 纯文字支路显示，普通标题与正文来自准确原节点记录。没有创建 Artifact、View、membership、Run 或 Workflow，没有第二份正文存储。原 parent、位置、尺寸、锁和颜色/固定字段仍走原保存者。

## 后端独立纯模块

文件：`lab/pilot/native-ordinary-node-content.ts`。

```ts
projectNativeOrdinaryNodeContent({
  projectId, canvasId, node, nodes, workspaces, bindings,
  content: { canvasId, record: saved.record }, // 原 space(canvasId).nodes.read(node.id)
})
```

返回 `{nodeId, canvasId, workspaceId, data}`，其中 data 仅有准确 `id/title/text/content`、原 `type:'pure'` 以及派生只读标记 `lcos_ordinary_text_readonly:true`。几何、parent 和 GUI 字段不在返回值内，避免在正文读桥里另写它们。

准入是当前唯一 Workspace、当前唯一空间节点、原 record 的准确 nodeId/type。普通 note 才进入此分支；已有绑定或任何 reserved reference 字段（含 null、undefined 的自有字段）都不降级成普通节点。错项目/现场、重复/替换 id、缺失记录、错 record id/type、非字符串正文/标题或 source-backed record 明确失败，不猜首句、不强制 stringify、不借其他节点内容补空。

原 `label:null` 保持空标题，真正空白正文逐字保留。正文中的换行、emoji、Markdown、尾部空格都不 trim。`isNativeOrdinaryTextReadonly` 还核准确 nodeId、pure 分支、标题/正文类型和 text/content 一致，损坏的 canonical 引用不借派生标记变成普通节点。

Facade 整合由 Root 负责：先沿原 Space 读 record，取得纯投影后并入原 text DTO。普通 fallback 不能调用 Core 材料编辑或生成；绑定材料继续原 canonicalText/ref/revision 路径。本 agent 没有编辑 facade。
