## 接入路径

```text
TapNow 原 Composer（发送时捕获现场）
  → 原 Core 会话与发送去重
  → 原 Host / ACP native 会话
  → 当前会话固定的四项 MCP 工具
  → 同一 Huabu 内核与 Core
  → 原画布实时更新 / 原 Undo、Redo

工具需要确认 → 原 ACP pending request → 原对话内 PermissionTray
```

- 原发送票据捕获 canvas/workspace；重试保留本条消息原现场，不读取后来切换的现场。
- facade 校验项目、工作区、canonical 会话、continuation 和实际连接。已完成／pending 消息先交原去重流程，不再次挂工具或发送。
- 同一 native 会话只挂一个固定自有 MCP；Main／Context 随下一条发送替换目标，无现场发送移除自己的服务。页面不能传任意 command、URL、环境变量。
- 工具进程读取本隔离运行区自己的内核连接文件；入口剔除不需要的模型及 Host 环境凭据，未读取或输出用户密钥。
- 权限仍由原 ACP client Map 持有，原选项、超时与拒绝保留。展示改为节点名称和具体动作，回答成功后才收起，不乐观伪造完成。
- 健康发送不再重复展示整块“原消息正在发送”恢复卡；发送状态保留，未知结果仍保留核对／重试功能。浅色对话内的行内代码颜色已修正。

准备工具与整条发送共用原连接上的短期并发保护。具体失败场景是 A 挂 Main 后、开始 prompt 前，B 把同会话换成 Context；原 prompt 锁尚未开始，Git、版本号、主键、单库事务等不能覆盖这个跨进程空档。忙时明确拒绝，不自动排队或重发。没有新增领域协议、hash、baseline 或 gate。

## 实际踩到的断点与修复

| 断点 | 实际处理 |
|---|---|
| 四工具发现成功，但模型说不可用 | 原供应商 session runtime-add 只更新 MCP 注册，未刷新已初始化模型的声明；隔离副本调用其原 `setTools()` 刷新，add/remove 都处理 |
| 工具出现在注册表，仍未进模型声明 | 原 context_usage 排除 deferred tools；固定四工具使用原 `alwaysLoadTools` 发现选项，不设 trust，不跳权限 |
| 模型工具名无法辨认操作 | 太长的 server name 被供应商整体改写，操作后缀丢失；改用原 native UUID 去标点，保留四项操作后缀，不新增 hash |
| 隔离 Python MCP 启动失败 | mcp 依赖的 typing_extensions 只在原用户 site；只复制已安装依赖到本隔离目录，不恢复真实用户 profile |
| 无 Run 的续聊 permission 被取消 | 沿原 client 的 pending request 接原对话内确认，未造 Run、未全局 auto-allow |
| 首次真实 Main 查询验证脚本误判 | 原 toolCall.title 是 JSON，工具名在原选项中；原 pending message 通过原确认继续，0 新提交，没有重放 |
| 第一次模型移动后验证脚本未找到资料库开关 | 移动已成功，原报告仍记失败；改走资料库原返回箭头，发送前先实际核对收起 |
| 第二次移动已撤销，重做没有发请求 | 截图显示测试再次点击原空白处后出现添加节点菜单；改为只聚焦画布一次，并等待原同步空闲后操作快捷键。未修改原快捷键或菜单，最终原重做通过 |
| 后续验证发现会话断开 | 按原页面恢复同 native；0 模型提交，20 条消息逐项一致、原位置和正文保留。断开根因尚未证实，不能假称已修 |

供应商修改只落本工作区忽略的隔离 provider 副本，并保留原件备份；已安装软件和 `lcos/`、`reference/` 原件未改。临时网络请求诊断未捕获实际请求，未用作证据，已移除。
