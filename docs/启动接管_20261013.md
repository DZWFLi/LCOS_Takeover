# 启动接管 · 2026-10-13

## 结论

17874 的 takeover 模式已接入 TapNow 原版 renderer，并在内存中把启动态切到明确标记的本地 Canvas fixture。原安装文件不改；fixture 不是真实账户，也不属于 LCOS Core。

## 启动与入口

    node lab/server.mjs --takeover --port 17874

打开 http://127.0.0.1:17874/takeover/。页面使用原版 Canvas 工作界面，路由为 /canvas/offline-fixture-canvas；右下角常驻 LOCAL FIXTURE · READ ONLY · BILLING NOT CONNECTED 标识。

安装版主 bundle 只在返回给浏览器前做内存文本变换：保留原 React 与 store，在原有 hFl() 启动前绑定 Cr auth store 和 Canvas 路由；只把 VITE_API_BASE_URL 指向当前 loopback origin。其它服务域名与文件上传配置不改，其它 .js 资源原样通过。17873 的原 renderer 对照不走该变换。

## 数据与边界

- GET /api/canvas/v1/canvases/offline-fixture-canvas 返回本地合成节点与连线，不读写真实 Canvas。
- GET /api/bff/billing/init 返回明确标记的未连接状态：subscription 为空，wallet 计数为 0；这是 fixture 响应，不表示任何真实账户余额。checkout、订阅和付款动作不会返回成功。
- 页面身份仅存在当前渲染进程内；访问 token 与 refresh token 的读取被屏蔽，不删除浏览器存储，也不写入 token。
- 同源兼容层可提供明确标记的 catalog 投影；这不代表真实 Core Canvas owner。
- 写入、生成、删除、付费、文件和 Shell 动作没有接入，必须以明确错误结束，不回报成功。
- CSP 只允许同源连接；被拦截的媒体不会伪装成可用素材。WebSocket 拦截结果另行记录，不由本次 Canvas 画面推断。
- 新数据目录为 .runtime/offline-takeover/。reference/ 原件保持只读。

## 浏览器实测

- 原版 Canvas 工作界面已在 /canvas/offline-fixture-canvas 渲染出 2 个 React Flow 节点和离线标识；详情 GET 命中本地 fixture，返回 200。
- LCOS Core 未连接，window.tapDesktop 不存在。自动触发的 nodes:batchActions 写请求返回 501，没有假装保存成功。
- 原厂页面首次显示“智能预演”和“赠送 Tapies 权益”弹窗；这是编译前端默认宣传 UI，不代表真实预演或实际权益，本地不会产生付费或赠送结果。
- 图片/媒体仍被离线 CSP 拦截；这轮只确认 Canvas fixture 可见，不把离线媒体描述成已接通。
