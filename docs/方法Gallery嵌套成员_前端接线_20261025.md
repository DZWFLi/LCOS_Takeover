## 实屏发现与定点修复

首次实屏只打开了原 Library 搜索列表，详情没有留下来。浏览器只读 trace 确认：原 Library 页面打开会卸载来源 Gallery，Gallery 的清理随后才取消 controller；精确行在 Gallery 卸载后才首次注册，并没有先打开旧查询行。

把同一事件改为原 `wt.open()` 的浏览器内对照仍会卸载 Gallery，说明不能靠强留失效来源或改合成点击来解决。

修复是在成员核对完成后、打开原 Library 的那个交接点，把已验证的临时来源地址交给目的页面。目的读取此后按唯一来源地址和 project/Canvas/API 判断当前性；原 Gallery 的正常卸载不再取消它。根 Back 通过原 Gallery owner 恢复准确方法及成员；初始读取期间的关闭、同方法重开和取消仍由序号／AbortSignal 拒绝。

另外补上目标查询已完成的检查，避免既有行属于上一次搜索却提前被打开。

最终根因结论：来源票据原先仍依赖即将卸载的 Gallery 和它的读取 controller，导致原页面正常切换被误判为取消。现在由原资料库接管票据和返回路径，子阅读继续使用原 Viewer lease，跨现场继续使用原 LibraryNavigation；最终六组真实导航证明这条所有权交接已接完整。
