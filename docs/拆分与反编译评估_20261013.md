# TapNow 拆分、反编译与组件复用评估

日期：2026-10-13（Asia/Shanghai）；工作区：LCOS-DSH-03。

## 先说结论

它不是只能供我们截图参考的黑盒。当前包能读、能改、部分模块能独立用；原 Canvas 页面也已经接入我们自己的可编辑组件，原节点与素材库继续工作。

但不是“反编译一下就拿回原 TSX 工程”。目前做到的是编译 JS 的分析、窄修改、独立工具接管和组件挂载替换；整个原前端还没有整理成可长期维护的源码工程。这个差别决定夺舍是否真的有价值。

推荐走“按业务回收组件、接自己的领域数据、逐步工程化”，不先投入整包原样恢复，也不把永远靠字符串补丁的黑盒当最终交付。

## 代码到底有多大

按用户说的“不算 Electron 包装”理解：只统计复制安装版的 resources/web，不包含 Electron 可执行文件、Chromium/Node、app.asar 桌面壳，也不包含我们新增 lab 或格式化输出。

| 统计口径 | 原安装文件量 | 十进制 MB | 二进制 MiB |
| --- | ---: | ---: | ---: |
| JavaScript | 493 文件 | 41.35 | 39.44 |
| CSS | 10 文件 | 0.84 | 0.80 |
| JS + CSS | 503 文件 | **42.19** | **40.24** |
| HTML（包括内嵌 JS/CSS 的工具） | 29 文件 | 17.98 | 17.14 |
| JS + CSS + HTML 代码载体 | 532 文件 | **60.17** | **57.38** |
| 含图片、字体、音视频、模型等的整个 Web 目录 | 956 文件 | **113.46** | **108.21** |

所以“30 兆还是 40 兆”：仅 JS/CSS 更接近 40 兆，具体 42,192,997 bytes。加独立工具 HTML 后是约 60MB。主入口单文件 13.14MB（13,141,204 bytes）。

这些不是 TapNow 自写业务代码的净体积：还包含 React、Three.js、SDK 等第三方代码，以及重复嵌入工具 HTML 的运行库。当前没有原始构建归属元数据，不能可靠减出“纯 TapNow 业务净字节”。数字也是原安装文件字节，不是 gzip/brotli 下载体积，更不适合直接换算成人天。

逐扩展统计与字节原值：evidence/code-volume.json。可复跑：node scripts/code-volume.mjs。

## 能反编译到什么程度

严格说它是打包、压缩后的 JavaScript，我们主要做解析、格式化、定位绑定、拆依赖和重构，不是把机器码还原成 C++。

当前主包机械还原已实测：

- 输入 13,141,204 bytes；原文件 7,213 行。
- Babel AST 解析约 1.71 秒；代码格式化约 12.40 秒。
- 输出可读 JS 16,811,624 bytes、451,268 行；约 244.76 万个 AST 节点、5,826 个顶层 function 声明。
- 格式化输出通过 node --check；没有执行该输出，没有证明它单独可启动或运行等价。
- 此行数大量包含第三方库，并不代表 45 万行原创业务源码。

可读输出在 lab/decompiled/index-readable.js，已被 Git 忽略，仍只用于私有本地分析。计时与统计在 evidence/decompile-probe.json。可复跑：node --expose-gc scripts/decompile-probe.cjs。使用的是已缓存 Babel 工具，没有下载依赖或运行产品 bundle。

格式化能还原可读排版，不能猜回已经丢掉的业务变量名、原始目录、类型和设计意图。压缩器会改写语法与缩短标识符；source map 本来用于映射回原始输入，但随包没有可用的原工程 map。参考：[esbuild 压缩与 source map 文档](https://esbuild.github.io/api/#minify)。

如果原工程采用 TypeScript，其类型通常已经从 JS 里擦除，不能从产物原样找回。当前 JSX runtime 调用也不能确定原文件究竟是 .jsx 还是 .tsx；可重写出新的可维护组件，不应声称恢复了作者原文件。参考：[TypeScript 类型擦除说明](https://www.typescriptlang.org/docs/handbook/2/basic-types.html#erased-types)。

另外，服务端模型调用、协作和计费的实现不在客户端包里。客户端有接口和请求形状，不等于有后端源码；这一部分必须由我们的系统实现，不属于反编译可以拿回的东西。

## 五组切断实验：哪些依赖是真硬骨头

每组用全新无登录 BrowserContext，service worker 禁用，HTTP 只允许精确 loopback origin，WebSocket 关闭。所有异常接口明确非成功响应，不制造付费、生成或写入成功。

| 切断组 | 原节点 | 真实拖拽 | 素材目录/两条记录 | 解释 |
| --- | ---: | --- | --- | --- |
| 原离线对照 | 2 | 成功 | 成功 | 明确 fixture，无真实 Core |
| 计费接口全部失败 | 2 | 成功 | 成功 | 计费服务不是这些交互的硬依赖 |
| 只留单画布详情与 Library GET，其它业务 API 失败 | 2 | 成功 | 成功 | 选定基础交互可以只依赖很小的数据接口集合 |
| Canvas 数据接口失败 | 0 | 不适用 | 不适用 | 返回项目页；画布数据必须有人承接 |
| Agent host JS 文件模拟 404 | 0，延长等待仍 0 | 不适用 | 不适用 | ESM import 链断裂，页面停在 spinner；不能删文件了事 |

原对照首屏实际加载 38 个 JS 文件、约 19.60MB JS；它不是全站最小依赖包或全部运行覆盖。Agent host 有四个静态消费者，仅 Canvas 页就导入它 12 个 named exports。改组件挂载点能工作，删除它的共享 chunk 则不行。

依赖审计：493 JS、1,139 个字面相对 import 边、0 missing、主入口 42 个字面动态 import；沿字面边可达 491 个 JS。static 和 dynamic 混合图中的循环不能直接当成业务耦合或首屏下载量。详见 evidence/dependency-cuts.json。

实际 ablation 报告：evidence/ablation-verification.json。

## 独立工具能拆出的“鱼肉”

24 个 MCP App HTML 入口都把 JS/CSS 放在 HTML 内；这是静态独立性，不代表 24 个功能都已完整运行。它们通过 parent.postMessage 的 JSON-RPC 与宿主衔接。

本地已实测三个工具：

- Color Adjust：原件 Canvas 像素随曝光变化、比较原图、分页/重置、参数刷新恢复；Apply 未接 Core。
- Director Markup：真实键盘选择 0–7 字符，创建镜头批注、填写内容；控件状态落本地文件并刷新恢复。确认发 ui/message，宿主明确拒绝，没有启动 Agent。
- Platform Resize：读取本地 960×540 合成图，真实拖动使取景框 left 从 21.9% 变到 36%；输出 crops {x:360,y:0,w:563,h:1000}，resize_for_platform_apply 明确拒绝。裁切几何已可用，最终位图与写回未实现。

这些工具不需要加载 13MB 主入口、账户、Agent 或 Electron，适合优先收成我们的可编辑模块。Layer Composer、Ad Review、Cutlist 等还有可用的本地编辑部分，但本轮没有全部操作验证；涉及生成/变体的页面只有 UI，不含后端模型能力。

主题也可以走 SDK 的允许变量。原白底/浅字问题通过白名单浅色主题修正，握手成功、标题为 rgb(29,35,41)，原图仍载入；不注入未允许的私有变量，也不称完整厂商主题已恢复。

逐页审计：docs/工具可拆分_20261013.md、evidence/tool-islands.json。独立宿主：lab/island-host.html；入口 http://127.0.0.1:17875/islands/。

## Electron 与云端到底能去掉多少

- Electron、安装器、桌面更新器、全局 preload 可以不进入当前 Web 画布/素材库路线；实际 tapDesktop=false 已运行。
- 但本地文件 grants、Agent 遍历/读写目录、截图录屏、系统应用和 Shell 审批不会随之自动保留。77 个 IPC 中，这些能力必须选择性重建或明确不交付。
- 普通浏览器选文件/下载可以替代一部分；不是任意路径授权、后台目录管理或 OS 权限的平替。
- LCOS 已有路径保护、目录选择、注册路径打开/定位、截图数据接收等底座；没有找到对等的完整 Shell 提案/授权/撤销/审计接口。不能为了省事删已有安全限制。
- 我们自己的 Core 仍是领域真值 owner。当前没启动或接它，没有改真实项目、数据库、watcher、schema 或原生权限。

完整分类：docs/桌面壳可拆分_20261013.md。本轮只读解析 ASAR，三个 shell entry 与保存原件逐字节一致；没有执行 EXE、updater、IPC 或 Shell。

## 时间和成本：哪部分便宜，哪部分贵

下面是基于当前包的工程工作量级判断，不是固定交付承诺。假设一位熟悉 React 与逆向工程的工程师、AI 辅助，目标为 Web 前端，不包括重建 TapNow 云端或完整原生桌面能力。

| 目标 | 量级 | 当前依据 |
| --- | --- | --- |
| 把主 JS 展开可读并做 AST 分析 | 已实测约 15 秒总过程 | 不恢复原命名/类型/源码组织 |
| 定位几个接缝、做局部组件/文案/布局改造 | 小时到几个工作日 | 这轮已改原挂载点并回归画布/素材库 |
| 将一个已定位的工具整理成模块，接本地宿主并验证 | 粗估半天到 3 个工作日/简单工具 | 不适用于 3D、视频生成等复杂工具 |
| 回收 Canvas + Library 成可维护模块、整理 stores 与读写适配 | 按周安排 | 仍要追共享依赖、持久化与生命周期；未给定完整验收范围 |
| 把整个前端重建成干净源码工程并覆盖各路线 | 数周至数月 | 不保证恢复原工程；第三方代码可复用，业务关联仍需人工/测试梳理 |
| 原样恢复作者的原 TSX/类型/注释、或拿回未打包的云端源码 | 不能承诺 | 产物缺的信息不是多跑一个反编译器就能得到 |

所以贵的不是电脑处理 40MB，而是工程师确认每个组件的语义、依赖、领域 owner 和回归行为。AI 可以加速解释与重构，但不能补出不存在的源码或替代实测。

如果我们的目标是“复用原交互，做自己的编辑器”，优先回收 Canvas/Library 和已证独立工具是有价值的；如果最后只能继续永久修压缩字符串，仍没有达到可维护组件工程的目标。这是本轮确认的技术债，不把它藏起来。

工具孤岛实测由同一专用浏览器在 17875 完成，选择工具后按真实标签操作；状态、RPC 和未执行回执保存到独立运行目录。两个 SecurityError 是 Playwright 的 service-worker 注入碰到 opaque sandbox，不是工具主动申请原生能力；没有为消除它们放松 sandbox。

重要边界：专用浏览器对所有非指定 loopback HTTP/WS 拦截，页面也有 CSP/fetch 拦截；direct location 自定义协议保护尚未实现或测试，不把这些结果外推成任意浏览器的完整安全验收。

本轮 LCOS 后端流程保持原数据隔离与 Core 真值归属；Playwright 流程要求真实操作；React 规则使我们区分组件不挂载与依赖不打包，保留共享 runtime，而不是删掉模块掩盖崩溃。

## 下一步建议

只推进一条可验收的源码回收链：选原 Canvas/Library 与 2–3 个本地工具，提取/重命名/模块化所需组件，做自己的主题和交互，再接 LCOS 数据与持久化。每轮保留真实操作对照。先做出可编辑、可维护的局部工程，再决定是否值得扩大到整个前端；不以整包反编译当开工门槛。
