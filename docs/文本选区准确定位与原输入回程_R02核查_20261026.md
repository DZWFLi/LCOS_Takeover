日期：2026-10-26。状态：**只读核查完成，下一轮完整施工；本轮未改产品、未开真实页面、未调用模型或服务写接口。**

## 结论

问题是三段未接完整，不是缺一个跳转按钮：**真实选区的位置没生成；现Viewer不消费文本位置；原引用芯片回读只带版本不带位置。** 同版本多次摘录、显式切版本、同版切位置也必须一起处理，否则会“看似能跳，实际跳错”。

推荐保原 draft 的唯一材料/版本引用，把定位作为该引用的**可选多值GUI来源元数据**。单处可直接定位，多处借原Viewer现有动作 / More列出摘录位置，选择后仍在同一正文内定位。原输入和原Reader返回owner继续负责回程，不新建阅读窗、来源窗或第二输入。

**不缺新的Core API。** 现Core准确版本/原文件字节、唯一Viewer请求、原输入回程都足够。本次需要lab定位helper、现Viewer/正文消费、原只读源码的精确source-transform接缝。不能只给ref多塞一个locator就宣称闭环。

## 原CT能用什么，不能硬套什么

原采用稿源码：[course-api-base-url-CifxI1ia.js](<E:/Codex 项目/LCOS夺舍计划_20261013/reference/tapnow-installed/resources/web/assets/course-api-base-url-CifxI1ia.js>)。实际AST已精确读到：

- `CT=d.memo(({markdown,className}) => div.canvas-text-markdown → 原uW({skipHtml:true,components:jX,children:markdown}))`。
- `jX={a:LX,img:OX}`；普通p/li/heading/pre等仍是ReactMarkdown实际DOM标签，a/img自有renderer保留。
- 当前[原Viewer导出接缝](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/native-material-viewer-transform.mjs:111>)把原CT给`parts.TextBody`；[正文槽](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-reading.tsx:78>)真实挂此CT。

所以不能把GEN1的`data-line`直接当当前DOM已有，更不能用视觉换行数冒充Markdown原行号。新选区可用确定的**正文UTF16 offset + 所选exactQuote**；旧`text:l2-l5`要回源，则在原CT可选rehype扩展中保留原AST position的源行属性，仍由原CT渲染，保skipHtml、a/img和排版。

## 建议的最小完整策略

### 1. 同一正文位置helper

新增lab纯helper，统一生成和消费地址：

- 只索引当前`.lcos-reader-measure`的真实文本节点，排除button/script/style/aria-hidden；沿[既有正文索引语义](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/ui/professional/readerTextRanges.ts:5>)，为block之间使用确定分隔符。
- Range必须完整属于该Root；前后选、跨inline格式、重复句子、emoji都基于DOM真实位置，不能`indexOf(selectedText)`随便取第一处。
- 显式导出lab类型：既有`kind:selection`的结构子类型，含可选定位元数据（UTF16 start/end/exactQuote），不改变Core reference key或增加实体类型。用户标签仍是标题/摘录，内部坐标不披露。
- 重开同一project/artifact/revision，重建相同正文索引，边界合法且quote相符才构建Range/高亮/滚到原处；不符给原正文内具名状态，不搜索第一处当成功、不换Current。
- 旧lines使用真实源行属性；旧仅章节label若唯一可定位，重复/缺失说明无法唯一定位。原无locator续读照旧。

### 2. 准确引用/传输/多摘录

局部正文同时供给“摘录到输入”、Copy、drag同一确版payload。Viewer cite使用本次选区payload的locator，不能继续拿进入Reader时的旧locator。

原draft材料引用仍按原`draftReferenceKey`唯一。可选GUI元数据保存此版本的多处位置，重复同一位置去重；新增B时保A，不覆盖、不制造两个语义材料引用。原chip打开时：

- 仅一处：沿原openReader的sourceLocator进入该准确位置。
- 多处：同一原Viewer保当前确版正文，在原动作/More列明确摘录位置供选择；不擅自默认A或B，不弹另一个窗口。
- 取消某份材料引用沿原remove；清掉它的随附GUI位置，不影响别的版本/材料。输入切换/返回沿原parked draft保元数据，不建平行草稿store。

当前[快照泛型](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/composer/referenceSnapshot.ts:18>)保留对象字段；[原addEntitiesToDraft](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/lcosReferenceState.ts:183>)会直接忽略已有同版本ref，故需要lab内明确的GUI metadata合并适配，保原准入、顺序、引用key和返回值语义。不能指望已有去重方法自动合并它。

### 3. 显式定位与原续读的优先级

显式准确locator优先，未带locator走原同版本续读。位置失败保正文并说明；不能拿续读位置冒充定位成功。依赖必须包含locator，同版A→B也要更新。

延迟字体/图片布局变化仅由同一次定位的DOM恢复适配处理；用户wheel/pointer/key后取消自动修正，不迟到抢滚动或焦点。可以复用[原恢复取消语义](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/professional/readerScrollRestore.ts:1>)，不新增滚动真值或独立位置store。

用户显式改到另一个revision时清除这份旧locator/候选位置的应用，不能把旧offset/lines套到新正文；原引用地址、来源trail和历史版本记忆仍保留。重回原确版来源时再用它原来的地址。

### 4. owner / 原输入回程

保现Viewer `isCurrent`、Abort、canvas/API/project和原inputReturn。摘录同步准入仍核inputKey + messageId + continuationOperationId；原同稿文字在caret处插入，引用准入失败不写部分摘录。

原chip异步inspect也捕获message/op，不能只比inputKey（[其定义不包含message/op](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/composer/composerInputJourney.ts:4>)）。关闭/改输入/新消息/换项目后旧GET不打开新页。正文局部Root回调代替全局第一个`.lcos-reader-measure`查询。

## 必须同批保留的具体反例

1. 同一版本选A、再选B：原ref仍1个，来源位置有A/B，两项各自能到准确重复句，不能B回A。
2. 从带定位的历史版本切当前版本：新正文不套旧offset；原历史来源再打开仍准确。
3. 同一版本A来源→B来源：React key没变仍应用B，旧restore被释放。
4. 选区跨Reader chrome/另一份正文：不造坐标、不向另一输入摘录；原普通复制功能仍在。
5. 原inputKey相同但message/op已换：迟到inspect/cite不抢新消息；关Viewer/换现场/换项目同样拒绝迟到。
6. 同版本记忆scrollTop在另一处：显式定位胜出；无locator重开才续读；非法/缺失位置不给假成功。
7. 源文本有相同标题/相同句子、粗体/链接、列表/表格/代码、CRLF、emoji：不靠首匹配或视觉行号猜。
