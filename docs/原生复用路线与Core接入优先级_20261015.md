## 本轮补充核查：缩放、游标、Drop／Rail 与 Assembly 融合

### GEN2 动态文字不能简化成一个字号参数

- 画布 zoom：TapNow 原 viewport／手势继续拥有相机，编辑器与浮层从同一个 viewport 读数，不挂第二 ReactFlow Provider。
- 原生节点 LOD：`useNodeLOD` 按屏幕投影宽度控制 full／minimal；它与 LCOS 信息密度不是同一个开关。
- LCOS 信息密度：`useLcosDensity` 读取世界尺寸、zoom、DPR 和交互阶段，交给现有稳定密度算法；保留迟滞与编辑优先级，不能缩小就把正在编辑的正文隐藏。
- 文本尺寸：原 `useTextAutoSize` 在拖框时计算字号、结束后锁定字号；输入只按既有宽度和字号调整内容高度。它操作原 TextNode／QuestionNode 的 style 模型，不能直接套到 TapNow note／Gen1 Markdown 后就称接好；文字框宽度重排也不等于整段字号一起放大。
- 导航游标不是鼠标光标皮肤。原呈现组件有 near-edge／edge／arrival，定位目标与相机由既有导航链负责；游标叶子自己不持久化、也不拥有相机。基本定位随文本／Assembly 两批接入，原 Color Pin／地图钉的持久语义不由游标 CSS 替代。

进一步核实：Core 持久化的是 ColorPin definition 与 membership，目标为既有 view／entity／surface，不是地图钉世界坐标；边缘位置由原相机和几何投影。依据为原 GN2 `apps/local-core/src/routes/color-pins.ts` 与 `huabu/apps/web/src/lcos/pin/LcosColorPinProvider.tsx`。本轮读取的夺舍 `core-protocol-router.ts` 尚未注册 ColorPin／Railway 路由，需核对并补实际支持的薄映射，不能把前端已有组件称作 Core 经营链已经接通。

源码依据：原 GN2 `huabu/apps/web/src/hooks/useTextAutoSize.ts`、`src/hooks/useNodeLOD.ts`、`src/lcos/nodes/useLcosDensity.ts`、`src/lcos/navigation/LcosSpatialCursorMark.tsx`（后三处同属 `huabu/apps/web`）。夺舍已有 `lab/native-density-transform.mjs` 只替换原 viewport 查询依赖；`lab/pilot/native-text-ui.tsx` 已有原 viewport 到中性呈现输入的接缝。源码存在、旧接缝存在，不等于 56111 已完整接入。
