## 结论

**这项工作不能只放行“用于当前对话”按钮。** 当前原 Composer、普通任务内容读取和续聊附加上下文，均没有贯通完整混合 Scope。删掉前端拒绝，会把“看起来已经引用”变成“发送时失败”，或借旧路径悄悄漏掉成员。

## 怎么接：最小完整方案

### 原界面保持原流程

1. “用于当前对话”以一个原 Scope 地址加入**原 Composer 显式引用列表**，显示 Scope 名称；用户仍能移除、重新查看、返回输入。
2. 芯片查看沿已经接通的原 Library／Scope／集合预览栈，不新增查看窗口。原 [referenceItems](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/composer/LcosComposerHost.tsx:540>) 已有统一芯片；其 [onOpen](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/composer/LcosComposerHost.tsx:549>) 目前只接材料，需要把 Scope 查看接回原入口。
3. 沿原输入所有者保留草稿、光标、接收对话、message／continuation 身份及引用顺序。读取期间换输入、换项目或发送状态变化时，不把结果塞进其他消息。

### Core 补同一份完整读取

- 从精确 Scope 和其实际 Presentation 出发，读取 `memberViewIds` 与 `memberEntityRefs`；集合使用 canonical collection membership，不把集合冒充旧 Scope。
- 结果保留原容器层级、成员顺序和来源路径。循环引用保留一个可说明的回指，不能递归死循环，也不能因全局去重把其他分支抹掉。
- View 使用其实际版本；相同材料的不同明确版本分别保留。Collection Artifact 成员按实际 Current 读取时，要在同次取用记录中固定其实际读到的版本，不能重试时悄悄换版。
- 附注读取实际正文和更新时间；对话通过原身份链读取实际已链接历史，完整处理分页；Run 只读取任务内容、状态和已有产物来源，不派发、重试或同步执行；Workspace 读取实际工作集成员，不把相机／布局等内部实现当用户内容。
- 缺失、跨项目、重复身份、身份链断开、读取中变化与超额度均作为明确失败返回，原成员和输入保留。不能自动省略、自动摘要或换用“差不多”的内容来声称全文完整。
- 普通任务 manifest 与续聊附加上下文消费同一读取结果，并保留原 Scope 地址和成员来源。续聊现有文件证据表达需能准确记录真实异构成员及当次读取，不能给 Note／Run 填假文件身份。
- 复用原失败重读、原消息确认和任务提交所有者；未知结果只能核对原请求，不能自动重发。
