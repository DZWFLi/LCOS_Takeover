# 原画布引用点取接线审查

结论：原功能没有缺少草稿控制器，缺的是当前原生画布的指针接线。不能只把按钮变成选取态；应沿原 `createReferencePickRecognizer`、原输入 owner、原有序引用队列接回。新增独立专项已执行真实原函数，11 组通过；真实页面闭环仍由本批原页验证确认，不能用这份隔离结果代替。

## 保住的原行为

- Ctrl / Command 点取；显式点取只属于当前输入。Shift 保持选择优先。原词法中 Ctrl+Alt 仍是 Ctrl 点取，普通 Alt+左键不接管。触摸、笔、右键、次指针、编辑器与 resize/handle 保原 owner。
- 引用在 pointerup 发生；移动超过 4px、取消、输入改变、发送中都不能写草稿。点取完成只吞一条对应 trailing click，不冻结一整段画布时间。
- 按下时捕获精确 View / Revision。仅 descriptor/cache 刷新不能偷偷换成最新版本，也不应拒绝仍有效的原版本；实际 occurrence 身份改变仍取消。本轮审查发现 adapter 曾强制比较 captured 与新 cache 版本，已反馈施工代理，当前源码已改为实体身份核对。
- 原生来源准备与后续已绑定材料仍沿同一原有序队列。慢来源没有占位引用，后面的材料不能抢跑；队列里的已绑定材料也必须受宿主寿命保护。
- 文本、caret、原选择、材料及 Core 真值都不因点取改变。失败继续有提示；不通过删除入口掩饰没接通。

1. 原“从画布添加引用”→真实图片命中→原 draft strip 出现精确引用，普通与续聊 owner 都验证；不发送模型。

4. 原错误提示实际可见、可访问；`Failed to fetch` 等原始异常不得直接披露。此隔离专项只证明正确出口调用，未声称整套提示已实屏通过。
5. 刷新、切现场、关闭输入或组件卸载后无迟到引用、无 preparing 残留；原右键携带与 Drop 仍可用。
