# 原新建会话接线：本地验证回执

结论：原 Composer 的新建请求已接上原创建、绑定动作和同栏选中流程；本地定向 8 组通过，既有 Scope 接线 8 组回归通过。目前未调用模型，真实页面与真实回复待新 Host 启动后验证。

## 已落地

- 原 Header 的“新建对话…”继续进入原会话选项；仅空白新建、精选上下文新建触发这次自动连接。
- 原请求被接受后，读取同一个 operation，消费 Core 已公布的动作和当前 revision，执行创建、重新读取、绑定、再次读取。
- 同时确认首次请求来源、新会话 ID 与原会话不同、外部会话证据和绑定步骤完成，再沿原页面选中地址切到新会话。
- 连接中、未确认和失败提示放在原右侧对话栏；“核对连接／重试连接”沿同一原请求恢复。
- 未知状态不会重新创建，创建回包丢失也不自动补发。关闭、切现场或切对话后，迟到结果不能把用户拉回旧目标。
- 原会话、人工历史、Scope 成员和原输入提交逻辑保持原 owner。
- 原新建控件从本源已存操作派生临时忙碌：连接未开始、进行中和结果未知期间不能另建第二个请求；已确认绑定、明确失败或确认取消后解除。
