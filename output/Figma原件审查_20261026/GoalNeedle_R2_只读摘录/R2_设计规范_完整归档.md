# LCOS Gen2｜Workflow Goal Needle R2：一行字的语义刻度

> 日期：2026-10-10  
> 交付：可交互独立 HTML（真实浏览器 DOM/CSS/JS），不使用 AI 生图。  
> 范围：**只重新设计工作流画布上的目标过程组件**，不包括桌面 Pet，不新建详情页，不修改 Gen2 GitHub 生产代码。

## 0. 这轮定下来的设计判断

上次的设计失败，不是因为圆点不够漂亮，而是因为把五个阶段、执行者、工具、来源、产物重新排成了**两列文字清单**。即便拿掉背景板，信息占地仍像一张拆开的卡片。

R2 改为一件画布原生、独立存在的 **Goal Needle / 语义刻度**：

- **静息**：只有一行目标名称及 `02/05` 确认阶段数；下面只留五个状态节点和五个阶段物种小图形。没有阶段名，没有副标题，没有功能按钮矩阵，也没有包住组件的卡片壳。
- **指向**：只让当前命中的节点唤醒一块 **222px 宽、133px 高**的近场透镜。标题+状态占一行；执行者、工具、Skill 使用微图标+简短名字组成一行；输入与输出只留不同实体造型+数量；不展示段落。
- **深入**：点击来源文件夹或结果纸片，**在同一块透镜内部延展**小量真实材料索引，不再另弹一个大窗。详细内容仍交给既有 Reader / Professional Window。
- **退出**：移动开未固定透镜或按 Esc 收起，回到原节点；不移动相机、不更改选择或业务进度。

**视觉关键词**：安静、聚焦、低占地；图形先于标签；原位显影先于页面展开；物件身份不因状态切换而改变。

## 1. 和 R1.1 有什么实际区别

| 判断点 | R1.1 旧问题 | R2 确定做法 |
|---|---|---|
| 默认阶段名称 | 每个阶段常驻文字，组成列表 | 完全收掉五条标签，只有顶部一行目标名 |
| 状态 | 完成、进行中仍附带文本 | 珠点的填充、轮廓和符号负责传达 |
| 当前关注 | 第三阶段单列文字、Actor 标签分散 | 当前节点只增加微光同心圆与阶段物种图标 |
| Hover | 先短提示，点击又展开宽详情 | Hover 即一块紧凑透镜，点击只固定，不突变成另一套页面 |
| 工具/Skill/执行者 | 独立罗列、多行描述 | 同一行三个微身份，缺数据不造假 |
| 来源与结果 | 多块类似纸卡，易混淆 | 来源是**带耳文件夹**，结果是**叠层纸片**；数量代替常驻名称 |
| 占地 | 视觉曾拉出很宽的无壳详情 | 近场透镜常态 **222×133px**，只有点击材料才增高 |

## 2. 精确几何和视觉文法

### 2.1 组件本体（世界坐标）

| 部分 | 设计值 | 目的 |
|---|---:|---|
| 物件参考宽度 | 200px | 一行标题和阶段序数能读清，零背景板 |
| 物件参考高度 | 约 254px | 不占用横向空间 |
| 顶部常驻文字 | 13.5px / 单行省略 | 顶部仅一行信息 |
| 进度数字 | `02 / 05`，10px 等宽 | 表示明确已确认的阶段数，不冒充精确百分比 |
| 阶段行命中高度 | 39px | 视觉节点小，但点击热区不小 |
| 珠点视觉尺寸 | 已确认 22px；未来 16px | 状态层级靠形态和面积表达 |
| 阶段垂直中心距 | 41px | 足够区分，又不拉成大流程图 |
| 主脊线 | 1.5px | 背景刻度而非强烈装饰 |
| 悬停透镜宽度 | 222px（屏幕像素） | 缩放画布时仍保留阅读能力 |
| 悬停透镜高度 | 133px（标准示例） | 限两行信息+来源结果计数 |
| 详情层的最小材料展开 | 最多 118px 可滚内容 | 避免大面板；详细内容跳回原件 |

### 2.2 状态不是靠颜色单独区分

| 状态 | 颜色 | 图形符号 | 行为 |
|---|---|---|---|
| 已确认 | 柔绿 | 实心 ✓ | 静态，无伪庆祝 |
| 正在推进 | 深青 | 同心环 + 中心点 | 微弱呼吸，**不自动推进阶段** |
| 等待复核 | 低饱和琥珀 | 暂停符 ∥ | 不呼吸，等待真实回执 |
| 受阻 | 陶红 | 警示符 | 保留失败事实，不涂成完成 |
| 尚未开始 | 灰绿 | 空心环 | 无动作 |
| 证据缺失 | 灰绿 | 虚线空心环 | 明确区别于尚未开始 |

另一个外圈的图标表示**阶段职能**（目标、材料、生成、复核、留存）。它与状态珠点分工，不将类型与进度混成一套颜色。

### 2.3 信息展开是“两行半”，不是一张资料卡

标准 Hover（实际 DOM 约 222×133）：

```text
 ●  合成方案                   进行中
 ───────────────────────────
 ●● Glyth   🔧 Figma    ◇ 视觉预演
 [文件夹 03] [叠纸 02]      ▰▰▣▱▱
```

- 第一行：**命中什么 / 处于什么状态**，不重复整条目标标题。
- 第二行：**谁执行 / 用什么工具 / 哪个 Skill**，用图标及三个短字段，无描述段落。
- 第三行：**输入有几个 / 输出有几个**，文件夹和纸片不同形态、不同低饱和材质；右侧五段小光点只是阶段索引。
- 来源或结果图标点击后，同一块浮层内部出现一小截条目。条目只能代表具有身份的来源/产出，没有证据就写“暂无记录”。
- 气泡与节点通过短横线+贴边缺口保持空间连续；到画布边缘时翻到左侧显示，不远距离浮游。

### 2.4 缩放密度（LOD）

- **近景（≥96%）**：一行标题、五种状态与五个阶段职能小图形。Hover 屏幕级可读。
- **中景（72–96%）**：一行标题与五个状态仍在，非活动阶段的职能图形退去。
- **远景（低于72%）**：保留状态串珠，标题收起，变成纯视觉刻度。
- 浮层为 screen-space，不跟随世界缩放成不可读微字；组件自身的平移/缩放只在独立 HTML 模拟，正式由 Huabu owner 管理。

## 3. 核心交互细节（不仅是框架）

1. **Rest → Hover**：只有当前命中的一颗珠点改变局部几何。延展 222px 小透镜，全部信息仍挂在原阶段身份上；Hover 本身不选中、不更改 Core。
2. **Hover → Pin**：点击阶段把透镜固定；再次点击同一阶段收起，Esc 也可收起。详情条目可继续交互，不会因为指针离开珠点而瞬间闪退。
3. **Inspect Sources / Results**：点击文件夹数目或叠纸数目，透镜向下露出当前类别的 2–3 条可选材料。切换类别收回上一个列表，避免并排列表。
4. **Return**：示例点击条目只提示“尚未接真实 Focus”。正式装配按原 `sourceRef/resultRef` 返回既有画布对象或 Reader，不制作第二份来源副本。
5. **Keyboard**：Tab 可进入阶段、上下方向键切阶段、Enter 固定、Escape 收起；Reduced Motion 下禁用呼吸、位移动画。
6. **异常态**：等待/失败采用不同珠点与色阶；未知数据不猜 Tool 或 Skill，不为了凑满三种徽标制造虚构信息。
7. **避免遮挡**：悬浮内容与画布节点没有新的 Camera/Selection owner，浮层左右翻转并限制在当前 viewport 内；此样机实现边界避让，正式环境要接 Huabu safeRect/occupiedRects。

## 4. 数据边界与实际代码复用

本轮属于**外观设计原型**，不是生产代码施工：

- **沿用设计语言**：Gen2 `soft-underlight.css` 的浅雾面、底部漫射而非全边霓虹的光学思路；已有 Goal Trace / Context Temporal Rail 的来源语义。
- **来源/结果组件目标**：正式施工优先对接已存在 `RareFolderComponent.tsx` 的来源小型呈现与现有材料/结果阅读器；R2 HTML 的迷你文件夹、纸片目前是 CSS 视觉部件，并**不冒充**真实 React donor 的运行结果。
- **只读展示**：阶段状态必须来自既有 Core/用户确认的进展记录。`ExecutionItemV1` 的单次 Run 状态不等于 Goal 阶段状态。没有确认的阶段记录，不要根据聊天文字估算百分比。
- **统一身份**：Tool / Skill / Source / Result 作为源对象引用的展示，不新增第二套 Goal 数据库、Window owner、Drop 状态机或存储。
- **目前未做**：未调用 Gen2 API、未提交 GitHub、未在生产画布运行 Huabu NodeWrapper/Camera/Selection/Focus；HTML 自身的拖动、缩放只是体验模拟。

## 5. 本轮实测

- 浏览器：Chromium，Python Playwright，因本会话没有可用的交互式 Browser 插件而使用本地 Playwright + `/usr/bin/chromium`。
- 三档尺寸：`1440×900`、`1060×760`、`390×844`。
- **验证通过**：首屏渲染、Hover 显影、222px 小透镜视口内避让、点击固定、来源 3 条/结果 2 条切换、Escape 收回、切换进行中/等待/失败/完成/未知示例、深色主题、阶段键盘上下导航、缩放 LOD、拖动组件、回到初始画布、右缘自动翻边、Reduced Motion、无 JavaScript 页面错误。
- 实际截屏位于包内 `preview/`（它们是浏览器实际渲染截图，**不是 AI 生图**）。
- **限制**：示例记录不是用户项目进度；材料点击会给出尚未接真实 Focus 的提示，而非谎称成功定位。运行在浏览器模拟环境，不等于已通过 Gen2 / Electron 实机集成测试。

## 6. 下一步在正式 Gen2 里怎么接

先把这一套**无卡片组件本体与小透镜**视觉通过，再用薄显示 Adapter 读取真实 `Goal/Stage` 关联投影接入 Huabu 画布。此时只需要替换本样机里的 `S[]` 数据与局部交互壳，不迁入示例 Camera、Mock Store 或手写布局层。真正需要验证的是“缩远 → Hover → 选阶段 → Focus 源材料 → 回到同一阶段 → 收起”，而不是用另外一张精修截图冒充功能完成。

**设计一句话**：一颗珠点只说“我在哪”；靠近它，才知道“我用了谁、什么和哪些材料”；打开材料，才去真实的工作现场。
