# 集合跨 Dock：真实 GUI 交付（2026-10-20）

结论：集合可以作为一个完整对象右拖到 Main / Context / Workflow，复用同一集合身份，不拆散成员、不搬走来源，也不要求先挑目的地。

## 实际验证

测试只写 `isolated-node-carry-20261020` 合成数据，浏览器地址 `http://127.0.0.1:56241`；未启动 Provider / Run，未注入 Drop store。

- Main 集合右拖 Context：目标保存一个集合载体；来源坐标和可见性保留；不自动切换现场。
- 重复拖 Context：复用已有载体，没有新增投放 POST。
- Main 集合右拖 Workflow：首次真实 POST 已成功但故意丢弃响应，只用 GET 读回确认，没有再次 POST。
- 进入 Context / Workflow：原生 Gallery 显示完整的两个成员。其中一项为新建的独有正文，目标画布从未有它的独立节点；直接从集合打开正文成功。
- 刷新目标现场：集合 ID、载体 ID、成员保持，不把成员展开成一堆节点。
- Workflow 的集合回投 Main：GET 复用 Main 原载体，来源不动，不自动导航。

最终脚本 `scripts/native-surface-collection-browser.mjs`：6 项真实路径断言通过，pageerror 为 0。原生外部统计请求被本地阻断、部分现存接口 501 仍单独记在 console/network 中，不将其算成已修。

## 剩余与回退

- Reader 的 Esc 关闭有间歇性失败，已交 Reader owner。最终集合测试通过既有“返回”按钮退回 Gallery，不能据此声称 Esc 已修好。
- 当前画布空白投放分支已补齐，34 项定向测试及六模块 strict 检查通过；真实“库集合 → 画布空白”待本轮隔离 runtime 交还后继续，不与本报告已验证的跨 Dock 路径混算。
- 回退只撤上述适配层的集合分支/接收注册，不删除已有集合数据，不改用户画布坐标。
