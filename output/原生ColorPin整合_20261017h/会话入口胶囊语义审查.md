# 会话入口胶囊 · 阅读语义审查

结论：**这是确实存在的语义接错，文件读取成功不能算阅读功能完成。** 本次材料是 Core 导入服务自动创建的会话入口文件，普通 Artifact viewer 把内部入口说明当成正文展示了。真实两条消息就在同一 Core，可读；不能靠删除 hash/来源段落补救，也不能把一个冻结文件版本悄换成最新会话。

本轮仅读源码、已有截图/事实与 8 次 loopback GET；没有改产品/数据/用户正文、没有启动浏览器/模型、没有构建或重启。前一批 Run 报告已补“未验真实根窗口遮挡、旧 Stage/表单未退役”的边界。

## 2. 生产 owner 为什么会生成这个文件

真正采用的是选中只读 [conversation-import-service.ts:1123](<E:/TRAE项目/LCOS0.1收口/LCOS_GEN2_GUI_RECOVERY_20260926/apps/local-core/src/conversation-import-service.ts:1123>)。`#parseAndPersist` 把真实消息写 `conversation_messages` 后，调用原 `createTextArtifact` 建入口文件；其 body 明确只有来源/消息/章节/hash/入口说明。

[同源 :1164](<E:/TRAE项目/LCOS0.1收口/LCOS_GEN2_GUI_RECOVERY_20260926/apps/local-core/src/conversation-import-service.ts:1164>) 最后仅将 `conversation_artifact_id`、`conversation_view_id` 写回 session。**没有保存 entry ArtifactRevision/FileRecord → 导入消息快照的准确关联。** `createTextArtifact` 实际返回 revisionId/fileRecordId，但调用方未保存这两项。

当前 [原 Pile 未投影成员入口](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-pile-ui.tsx:457>) 正确核同项目成员，然后对没有准确 Canvas View 的 Artifact 请求通用 viewer；:472 不带 revision/View。通用 [viewer:217](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-viewer.tsx:217>) 只按 Artifact/Revision/MIME 选择文件，没有“会话入口”的语义分派，所以字节正确、产品含义错误。

不能用 `managed:true`、markdown 类型、标题、正文正则或 Artifact ID 前缀分类：这些都可能是普通用户材料。也不能因 Artifact 关联会话就抹掉后来用户编辑的某个版本。

## 4. 历史版本为何不能直接跳“当前对话”

原 session 的消息表会被 `reserveContinuationPrompt / appendContinuationTurn` 继续追加，[import service:309](<E:/TRAE项目/LCOS0.1收口/LCOS_GEN2_GUI_RECOVERY_20260926/apps/local-core/src/conversation-import-service.ts:309>) 及后续方法均用同一个 session。sourceContentHash 指向首次导入原文件，**不是当前所有消息的版本号**。export/messages 与 collaboration-timeline 都读当前表，不接受准确 import revision。

已有 [inspectContextSource:550](<E:/TRAE项目/LCOS0.1收口/LCOS_GEN2_GUI_RECOVERY_20260926/apps/local-core/src/conversation-import-service.ts:550>) 会从原 source_path 读原导入 bytes、校验既有 sourceContentHash，并识别未读媒体；但只返回完整性/媒体种类，不返回冻结 messages，且没有现成 HTTP snapshot reader。这个保护应保留，不能绕成“把当前 timeline 截几条就当首次导入”。

因此显式 revision/View、用户此前选中并记住的 Reader revision、Run/引用冻结 revision 都必须保持原准确文件。当前仅凭 session 的 Artifact 关联，**无法证明某个任意 Revision 就是自动胶囊版本**；更不能通过 revision ID 字符串拼接、时间接近、最早一行或正文 hash 段落推断。

## 5. 可施工的最小正确接法

### A. 先把当前阅读的含义接对

1. 在中央 material read resolver（不是每个 Pile/Library caller 各写一遍）用真实 session/identity GET 解析 entry 关联；普通 Artifact 完全走现 exact viewer。缺失/多重/跨项目关联如实读失败或让用户选准确对象，绝不按标题猜。
2. 已确认 entry 的默认“阅读会话”应读取真实 messages，用已导出的原 **U5 + `projectNativeChatMessages`** 或同一受控消息 renderer；不把 capsule markdown 当正文。纯查看不 register/link、不创建节点、不执行 Run、不发送、不改当前 Composer receiver。
3. 最窄的回程可继续用**现原 Viewer 的受控 body slot**显示 U5 只读内容，原 Gallery/Library 的已有返回位置不变；不新开对话窗。不整挂 `ConversationContent`，它带 waiting/review/发送相关动作。若选择原右栏呈现，则必须先补同一个 route 的 inspect-only + 原 Gallery/Library 返回 owner，不能让画廊遮挡右栏或调用 auto-open Composer 偷换 target。
4. UI 要明确区分“阅读会话内容”和“查看入口文件的此版本”。对已给定/记住 revision 的请求，不能自动把内容换成当前 timeline；当前会话只能作为明确的另一个用户动作打开，并说明是当前会话。入口文件和用户编辑版本都保留，不 regex 删段落、不归档/隐藏 Artifact。
5. 窄注册原 Core 已有 projection/messages/export GET（同项目/session 校验、原客户端与路径保护），消息按真实 seq/ID 分页。U5 保原消息全文；非 user/assistant 角色沿真实只读活动/内容槽，不伪装助手回复，未读媒体明确保留能力缺口。

### B. 再补准确的导入历史版本

- 对未来导入，在**现 import owner**保存其已经拿到的 `entry artifactId/revisionId/fileRecordId + session/sourceContentHash` 准确 provenance，可复用原 session 的 `originMeta` 或现可用的规范 provenance 位置；不加表、hash、保存队列或第二消息真值。字段是否落 originMeta 由 owner 核原语义后确定，不把本文建议当已落合同。
- 在同一 `ConversationImportService` 增只读“首次导入消息”读取：复用原 parser/原 source bytes 与既有完整性校验，保持原导入顺序及去重规则，核对原 session/message 身份；**不能调用会写表/建 Artifact 的 `#parseAndPersist` 来做阅读**。不混入后来 continuation。缺原始来源/校验失败/媒体不完整要明确失败。
- 旧 entry 没有 revision→import snapshot 证明时，不回填猜测。可明确阅读“首次导入历史”（按原 source 身份）或“当前会话”，但不能把它们冒充指定 Artifact Revision；旧准确文件仍可查看/下载。

本次没有实现上述产品分派，也未建立历史 snapshot 能力；这两块必须继续登记，不以换一个标题或遮住 capsule 正文结案。

## 6. 必须实际验证的几条链

1. 本夹具 entry 从原 Gallery 打开，显示真实两条消息→返回同 Gallery/成员；0 materialization/0 POST/0 Composer owner 变更。
2. 普通用户 markdown 即使写了一样的“来源/hash/入口”文字，仍完整原样阅读；仅相同标题也绝不分类。
3. 明确旧 revision/View、Run 冻结引用、Reader remembered revision 不跳最新 timeline；entry 用户编辑 revision 不被吃掉。
4. 首次导入后真实追加消息，导入历史与当前会话严格不同；无法核对 snapshot 时不伪造成功。
5. 未 linked 的 imported session 仍可只读，不为阅读创建 ConnectedConversation；foreign/模糊多匹配拒绝。大于 50/200/250 消息与 tool/system/附件分别验完整性。
