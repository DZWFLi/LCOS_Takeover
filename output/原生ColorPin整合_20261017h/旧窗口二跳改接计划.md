# 旧窗口二跳改接 · 最小施工方案

结论：四处仍是实际入包的旧 `openWindow` 调用。**三处已有准确的原右栏 dispatch 可接，一处集合→集合尚缺原 Library 精确选择入口。** 直接改三个函数名只能去掉新目标窗，不能同时宣称原集合回程、旧表单和恢复窗口已经迁完。

本轮只读源码、读取当前构建 provenance、在内存运行正式 source transform；仅新增本报告。没有产品修改、构建、候选请求或 Core 写入。入包调用仍不等于已实屏触发的故障。

后续限定源码施工已将 Run 重试 caller 接原右栏，见[旧任务重试改接施工](./旧任务重试改接施工.md)。该批尚未构建/候选实屏，不覆盖下方最初审查事实；Collection 三处与旧表单迁移仍未动。

## 3. 返回、草稿、请求：已有的与缺的

### 原右栏任务链已经有的

[nativeChatTaskRoute / nativeChatBackRoute](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-task-route.ts:16>) 保存 `tasks/task/conversation` 的 UI 地址栈，重复打开当前同 Run 不再压栈。[native-chat-ui.tsx:311](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-chat-ui.tsx:311>) 已正式挂 NativeTaskDetail，`onOpenRun` 将重试新任务压到当前任务后面；原标题按钮负责返回。

新任务详情继续复用 [performRunWorkAction](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-task-detail.tsx:197>)、fresh review、CAS、unknown 后显式读取，不为迁窗重新执行 mutation。原旧 Run 的 `nextRunId` 也来自同一动作 owner；点击查看不应再 POST。

但这个栈存的是地址：旧 Run 的 `answer/options/mustVerify/stopConfirm` 在旧 body 的局部 state，**不会因为换 dispatcher 自动搬过去**。不能 unmount 后假称输入全保留。正常已落地 NativeTaskDetail 的 retry 路径已有栈，旧 body 的恢复路径则需要把准确 `runId + inputRequest.requestId` 的未提交表单交给同一个受控内容 owner；正在提交的旧 controller 不能被粗暴关闭并另开第二 writer。保留旧记录直至迁移完成，不清 windows 掩盖缺口。

### 会话读取不能偷换输入 owner

[select():30](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-chat-ui.tsx:30>) 换 receiver 会 `closeComposer()`；接着 [auto-open effect:245](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-chat-ui.tsx:245>) 可为所查看会话 `openComposer`。shell 的 [openComposer:455](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/shell/lcosShellStore.ts:455>) 仅同 receiver 或其已存在 pending send 保 message/continuation；跨 receiver 不能当成原输入的同一请求。

因此给**现有 request/route** 加可选 `inspect` 与准确返回地址即可：读取时保留 shell `composerTarget/prompt/caret/conversationSendAttempts/reference owner`，只隐藏输入，不重新 openComposer；返回原输入时复用 [capture/restoreNativeLibraryInputReturn](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-library-contexts.tsx:72>) 的同 project/Canvas/API/inputKey/message/continuation 核对。它只恢复**仍属同一个 target** 的焦点与 caret，不会替代码复活已经被换掉的 target。旧用户请求/unknown 仍归原 owner，不因“浏览会话”被 ack、重发或改 receiver。

这是源码行为边界，本轮未启动候选复现，不列成新增实屏故障。

### Viewer 已经有的回程，不要重做

[requestNativeMaterialView](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-viewer-port.ts:26>) 只接受准确 Artifact 地址，可带 revision/View/returnId/composerOriginKey/legacyReturnWindowId。NativeTaskDetail 已传真实 returnId 和 draft revision，不能改成 Current。

shell `openReader` 已由 [reader source transform](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/native-material-reader-source-transform.mjs:25>) 委托原 Viewer；Viewer 正常关闭时底下 native 任务 route 保持，另复用原 input-return。已有 legacyReturnWindowId 会在 [viewer close:357](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-viewer.tsx:357>) 识别旧 task/conversation 地址转 native；**这里没有 collection 回程分支**。不能再把这四处 window 调用与已拦的 openReader 混算成同一种故障，也不能把 collectionId 伪装 Artifact。

## 4. Collection 只补原页精确选择，不新建页

已与 Library owner 核对：当前没有 `requestNativeCollectionView`。`lcos-native-open-library` 只携项目/输入来源，无法精确打开某 Collection；原 `Zp` 的 `C(true)` 是行内局部 Popover owner。

最窄新增的应是**一条读取地址委托**（命名可用 `requestNativeLibraryCollectionView`，这是建议，当前未实现）：

1. 把 `{projectId,collectionId}` 交给已挂载 jF 原 Library owner。原 wt 仍负责打开/关闭；沿同一 Core Collection/原 Library viewdata 读取准确条目，未加载分页时也按 ID 读取，不按标题匹配、不造 Assembly 行、不先投影 Canvas。
2. 将已确认的准确请求传给原 sF/Zp；命中原行身份后由原行 owner 打开自己的 TS Popover。已有 Core Collection 内容槽继续负责完整成员与不可用项，不挂旧 CollectionWorkViewBody，也不新添管理窗。
3. 子集合在同一个 Library 读取路径保留父 Collection/成员位置/原搜索与展开状态；返回交回原 Zp/原列表。传给原右栏的任务/会话可携这份 UI 返回地址。仅已有准确 pile/carrier 时才可委托原 Gallery；没有 carrier 的集合仍能纯读取，0 materialization。
4. 若从旧窗口恢复地址进入，原页确认接管后才退役**准确那个**来源 presentation；不要一次清掉全部旧 windows，也不能以 dispatch 的 `true` 作为接管完成回执——当前 boolean 只说明同项目地址合法并发出了事件。

不新增全局材料/会话 store、保存队列或 ProjectTruth；返回地址留在现有原页/原右栏 UI 生命周期内。无法恢复的旧局部表单或旧 layout 原样记账，不能用“关闭了旧窗”冒充功能完成。

## 5. 最小实施与验证顺序

1. 现 `native-task-route-source-transform` 追加两个 exact TSX owner；确认 Collection 接到 selected source，4 个目标调用移除、其余 reader/动作/读取分支不变。旧 Run 重试先接同原栈的 source Run 地址。
2. 原 Chat route 增 inspect/外部返回语义；原 Library owner 增准确 Collection 选择/返回 seam。现有三个 dispatch 复用，不另造一套 Chatbox。
3. 实际原组件测试四条按钮→准确目标→原返回：同项目/foreign、同 Run 重复点、child Collection 循环/缺失成员、分页未加载、项目/Canvas/API 中途切换、迟到读取都要保持原身份。打开与返回断言 **0 mutation/0 Run dispatch**。
4. 保留真实 Composer prompt/caret/inputKey/message/continuation/pending send/ref owner；查看其他会话再返回不重发、未变 target；旧 Run 问题 ID 变化不得把旧回答写进新问题。新任务/结果核对仍用既有 controller 与 draft revision。
5. 统一构建后原鼠标/键盘逐条实屏。来源→原容器→动作→返回都过，才能把对应旧入口记为已迁；旧 Stage 12 类 body 和其余 4 处入包 caller 仍需各自处理，不能用本四处计划宣称全区退役。
