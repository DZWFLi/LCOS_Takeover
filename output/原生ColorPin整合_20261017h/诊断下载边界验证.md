## 做了什么

独立启动两个随机端口 `127.0.0.1` HTTP fixture，用 fresh Chrome 直接加载当前 [renderer-diagnostics.js](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/renderer-diagnostics.js>) 原脚本。真实 Playwright 鼠标点链接内的 `span`，实际 Chrome `download` 事件后 `saveAs`，再读盘比较完整 UTF-8 Buffer。没有 `dispatchEvent`、伪造 download 事件、修改产品脚本或注入替代 guard。

第二 origin 的 Blob 同样由真实页面 `URL.createObjectURL(new Blob(...))` 创建。所有拒绝项均收到原脚本实际发出的 `navigation-blocked` 遥测，而不只观察浏览器自己拒绝协议。

| 动作 | 实际结果 |
| --- | --- |
| 同源 Blob + 非空 `download` | 真下载 1 份，中文文件名准确，字节完全相同，`download.failure() = null`。 |
| 同一 Blob 无 download / 空值 / 纯空格 | 均拦截，页面未跳转，下载数仍 1。 |
| 第二 loopback origin 的真实 Blob + download | 拦截；没有放宽成所有 Blob。 |
| remote HTTP / HTTPS + download | 均拦截；没有上游网络请求。 |
| data / javascript / 未知协议 / file + download | 均拦截；javascript 副作用未执行。 |
| window.open 的 remote / local Blob / foreign Blob / data / javascript / 未知协议 | 均返回 null，没有额外窗口；下载特例未扩到 window.open。 |
| 原同源 HTTP window.open | 真 popup 正常加载，再由脚本关闭。 |
| 原 remote fetch / 同源 fetch | remote 仍拒绝并发原遥测；同源 `/ping` 正常返回。 |

另有浏览器级远端 abort 兜底，但严格断言 `remoteRequests.length === 0`：通过证据来自产品 guard 在请求前阻断，并非兜底替它遮住失败。原遥测 URL 仍去掉 query。

## 边界

- 本测试证明当前 diagnostics 脚本在真实 Chrome 中的下载/导航边界；**不替代完整 Pin 菜单→读取→导出流程的候选实屏验收**。
- 仅 fixture `/api/events` 在本地收集遥测，无真实数据或业务写入；候选请求 0、Core 写入 0、模型 0、外网请求 0。
- 本子线程仅新增测试与本报告/证据；产品源码由根线程修改。测试完成后 Chrome 与两个 fixture server 均已关闭，结果 JSON 的 `closed` 为 true。
