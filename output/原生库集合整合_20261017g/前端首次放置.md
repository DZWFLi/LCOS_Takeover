首放请求：

```text
GET  /api/lcos/canvases/:canvas/collections/:collectionId/projection
POST /api/lcos/canvases/:canvas/collections:project
     { collectionId, position?: {x,y} }
```

GET 状态是 `absent | partial | present`，明确区分 Presentation 接收与空间绑定。partial 不会走盲重投。显式释放点原样保留；按钮默认沿现有可见空位/原落点 helper。默认可见空位使用保守的 250×244 占位 hint（原 preset 为 250×146），最终以真实 carrier/renderer measurement 为准，不宣称精确尺寸合约。

旧 `native-collection-placement.ts` 适配同一严格读回与原 pile；原已有几何 owner 同时兼容既有 legacy body 和新 pile，未删历史/成员保护。

## 必须继续核对

1. **未知状态的 Popover 关闭/重开**：当前 `needsCheck` 在详情组件，卸载会丢；原请求仍在途且新 GET 暂 absent 时，会再次露首放按钮。实际组件与真实 Core peer 均已复现这种前端重投窗口。backend 唯一许可保住“不二造载体”，但这不等于 UI 保留了原未知提示。按 root 决定本轮不塞 Symbol/Map/伪 Drop attempt；该 UX 限制明确保留在册。
2. **旧 Assembly Collection caller**：旧顺序为先 Assembly 接收，再投影。旧候选 first-place 原本报 501，没有已通过旧链被本轮删掉的证据。最终 backend 已支持“已接收、无 binding 且无准确载体 echo”的合法首次投影，并以原 CREATE 同写 echo/原锁内双查防二造；前端兼容 `presentation_received:true + absent`，真实 Core peer 通过。原旧 Assembly body 的完整用户入口仍未迁回原 Library，不能据此销账；旧 caller 的整页拖放也没有本分项通过声明。
3. **整页**：候选由 root 统一构建；原目录/行/TS 首放、原 Gallery、刷新同载体、真实预览关开/失回执、最终尺寸/遮挡仍以本轮 GUI 报告为准。
4. **集合引用**：原 `toRunReference` 没有 Collection 类型，续聊只接 Artifact/View。当前保留用户输入并说明打开成员材料后引用；没有冒充 Scope 或换用 Current。Context/Workflow 既有输入归属与恢复不动。
