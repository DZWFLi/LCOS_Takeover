## 真实执行抓到并修的断点

1. native 模式 `collections:project` 原来直接 501；原库本身也完全没有 Collection 行，旧测试的预置载体不能替代普通用户首投。现已一起接通。
2. 正式代理缺少原 Core Collection POST producer，整页准备第一份合成集合就报 `CORE_OPERATION_NOT_CONNECTED`。现已注册原 canonical create/createFromMembers，保留原成员事务、跨项目和参数验证。
3. 新 scoped port 最初未按原 executor 预分配 CREATE ID，真实创建没有返回 NodeID。修为沿用原 createId，不修改只读原件。
4. 两笔在途投影遇到第一笔 CREATE 成功／binding 失败时，可重复创建孤儿。原 CREATE 现在同命令保存既有 `lcos_collection_ref`；原 Canvas 锁内读取并核确切来源／binding，阻止第二次 CREATE。没有新账本或身份猜测。
5. 中间“只许 Assembly applied 投影”的方案会挡住合法同集合 Main→Context；已撤回，最终用上述原载体 echo 区分合法首投与已创建未绑定。
