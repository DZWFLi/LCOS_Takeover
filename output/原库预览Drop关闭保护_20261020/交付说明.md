## 真实原因与最小处理

原 `page-Da_DfwiK.js` 的 `Zp → pr` 实际调用 `index-BAQXnPag.js` 中的 `IQe`（export `a1`）。关闭有四条入口：Pointer outside、Focus outside、Hover leave、其它 Popover 打开。最后都回到受控 `Zp.onOpenChange → C(false)`，导致预览目标卸载。

因此只禁止普通外点并不够；拖动途中其它悬浮层打开也会让目标消失。

```text
原 IQe 关闭请求
→ 未传可选槽：原逻辑
→ 真实已注册 LCOS Scope 预览：读取同一 Drop store

  → 普通空闲点击/结束后：原逻辑
```

Esc、显式关闭、Popover Root 原 onOpenChange 未增加拦截。语义拖动未越过容差时，仅识别已有右拖/Alt 触发及原库 draggable 行作为来源，不开启另一份 drag 状态。普通左键点画布、控件不受保护；点击另一行仍由原 peer-open 关闭上一预览。

Gen1 的 `UnifiedExecutionComposer.tsx:156–166` 是顶部浮层普通外点退出，并没有可直接搬来解决此处 peer-open 的现成特殊分支。本次复用当前 `semanticCarryTriggerFromPointer` 和唯一 Drop store，而非杜撰“旧实现已覆盖”。
