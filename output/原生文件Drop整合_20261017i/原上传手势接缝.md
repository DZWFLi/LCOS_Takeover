## 上传器不是“回包已透传”

原 course `EO`（30254…31635）是共享 hook，调用 index `DFl`（719846…720317）和原 `Tor/Nxt/Mor/Jir`。`EO` 同时把真实进度投到原 TransferPanel；没有新队列、任务 store 或上传窗口。

本轮找到并补了两处不能只看接口文档发现的断点：

1. 原 index `Jir.completeUpload`（698946…700072 的类内）只 `await`，不返回结果。
2. 原 `Mor.upload`（712200…714889）也丢弃 complete 回包，再由 `Zrt`（711954…712200）手拼 `fileInfo`。原字段没有 `artifact_kind/FileRecord/lcos_ref`。

现在只让同请求返回真实回执，再把它合进同 `Zrt` 的结果。必须同 file_id / filename / size / 规范 MIME / exact URL 且有完整 Core 身份才采用。原 `already_uploaded` 没有 Core 回执时不补假字段；非图片文件不会回落成 URL 图片。

## 格式与载体

| 文件 | 原画布前门 | i 轮 Core 导入分类 | 展示边界 |
|---|---|---|---|
| PNG/JPEG/WebP | 原图片上传 / image factory | image | 原链保留 |
| MP4/MOV、MP3/WAV/M4A | 原包有 video/audio factory；原 audio 还接受 flac/aac/ogg/wma | 已接后端准入格式才导入，kind=other | 本轮统一原 Text 框只读文件面；不冒称原播放、解码、转录全已接 |
| TXT/MD/CSV/HTML | 原媒体前门过滤 | markdown | 上传未确认时只读候选文件面；确认后去掉候选 marker / transport，确版 View 回原 PURE 阅读。不能因 Text 外观声称 View 已可编辑；见下方补记 |
| JSON/YAML/XML | 原媒体前门过滤 | other | 文件面 → 精确 FileRecord 阅读能力；不猜解析语义 |
| PDF / PPTX | 原媒体前门过滤 | pdf / presentation | 原框文件面；阅读能力按原 Viewer 实际支持，不能拿导入成功当完整翻页编辑 |
| DOCX/XLSX/ZIP | 原媒体前门过滤 | other | 真实名称、格式、大小与查看 / 下载；不把二进制转字符串 |
| 旧 DOC/PPT/XLS、URL/webloc、其他未知格式 | 无对应 Core single-PUT 文件准入 | 不承诺导入 | URL 是独立 producer，未偷走文件上传路径 |

浏览器只做入口识别；最终 MIME、UTF-8、容器、大小验证由原 Core 上传 owner 完成。原包自带 world/GLB 能力不等于本地已接，不扩大该承诺。
