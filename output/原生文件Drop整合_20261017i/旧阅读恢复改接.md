## 为什么没有收到事件就关旧窗

实际链仍是 [lcosShellStore.ts:357](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/huabu/apps/web/src/lcos/shell/lcosShellStore.ts:357>) `setProject` → 原 `readProfessionalWindowLayout`/同tab缓存 → Stage。原 [requestNativeMaterialView](<E:/Codex 项目/LCOS夺舍计划_20261013/lab/pilot/native-material-viewer-port.ts:26>) 仅派发事件；它不证明Core内容、版本、FileRecord或原Viewer已打开。

而且原Viewer session是内存状态。如果收到事件就 `closeWindow`，既有layout订阅会把磁盘Reader地址一起删掉，刷新无法续读。此轮保留既有记录：

1. `setProject`只给实际恢复的reader记录附瞬态provenance，JSON不写该标记；没有新地址表、router或layout版本。
2. 原Stage reader分派的恢复分支改成委托leaf，稳定路径不再挂整 `ArtifactReaderBody`。非恢复路径与明确未能安全接管的恢复状态保留原body。
3. 原Viewer照常执行project/Artifact/revision/FileRecord/bytes/MIME/解码。仅这条成功路径产生ready proof。
4. Stage直接订阅同一个原 `wa.getState/subscribe`。**ready proof与实际phase=open、同requestKey、同来源记录及同Project/Canvas/API同时成立**，才投影掉对应Stage展示。只从展示列表退场，底层windows/windowRegions/layout内容不变。
5. 用户关闭原Viewer时，原 `finishClose`/session=null回调再调用原Stage `close(reader)`。phase=closing不是删除来源记录的证据。原返回窗口、源节点与同输入回程仍归原方法，不在新helper重写一份导航。

这不是只加 `hidden/minimize`：稳定恢复路径的旧Reader body没有挂载，实际字节由现原Viewer owner读取/展示，原生命周期有真实open/closed确认。也没有用“发true”冒充接管。

## 地址与保护怎样保留

| 情况 | 当前行为 |
|---|---|
| 显式历史版本或draft revision | 原请求保revision/locator，仍由现resolver读准确FileRecord。不存在/不可读就失败，绝不退Current。draft revision可读和“本地未存编辑稿”是不同事情。 |
| 未指定版本 | 继续现Viewer/Reader最后阅读版本规则，没有另写新版本选择器。 |
| 原输入/引用草稿/光标 | 委托带composerOriginKey；现Viewer沿原输入捕获机制，关闭复用原Stage回程；不复制旧prompt回写、不发送任务。输入身份不符保原路径。 |
| 原来源与返回窗口 | 保readerSource.nodeId、准确sourceCanvas、sourceLocator、returnToWindowId。关闭直接调原Stage close(reader)，不拼一个“类似返回”。 |
| 初始loading/读失败/error Viewer达到open | 没有成功proof就不退Stage展示、不消费地址；原处反馈/同版本显式重读保留。 |
| 迟到GET / 换Project、Canvas或同Canvas换API / 来源记录替换 | owner/current核对失败，不采纳晚到proof、不关闭别的reader记录。 |
| 当前已有原阅读/编辑session | 不抢占；稳定恢复body等待原session结束，不挂第二Viewer。 |
| 原node关联的pending/unknown、后来queued稿、已知导图本地draft | 不当普通Core Current读取吞掉；保原body和地址。该body一旦进入保留分支，不因为后来pending标志清了就自动卸载其局部状态，需新的明确来源/阅读意图。 |
| 跨现场来源 / 无法从当前准确node API证明本地状态 | 第一阶段保原恢复body，未宣称跨现场阅读/返回全部迁完；不会拿当前Canvas冒充来源Canvas。 |
| 刷新/同tab项目切换 | 原layout记录仍在，由原持久化/缓存恢复；不是新resume ledger。**本轮检查真实layout读写与地址不变，没有真实浏览器reload验收。** |
| 用户明确关闭已接管Viewer | actual finishClose才消费准确source一次，并走原close/return。原wa closing动画期间地址仍在。 |
