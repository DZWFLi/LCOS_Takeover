# 原续聊来源与目标身份修复（2026-10-22）

结论：原 Core 续聊 owner 的来源／目标分离已补齐；真实 SQLite 与原 Service／Adapter 的 9 组本地回归通过。这份报告只证明本地状态与身份行为，真实 Host／模型发送、GUI 由主任务继续验收。

## 改了什么

- 新增 lab/native-core-live-continuation-transform.mjs；沿原采用源码变换，不改参照 lcos、不另建发送服务。
- 原 journal JSON 与只读 Projection 增加可选 requestConnectedConversationId，记录首次请求来源；绑定后的 connectedConversationId 继续表示实际目标。旧记录没有该字段，仍走旧比较。
- blank_new、selected_context、native_full_fork 默认生成独立 Core thread，原 Core bind 事务生成新 ConnectedConversation 与 canonical session，不复用手工来源历史。
- 原幂等比较保留 project、provider、mode、contextInheritance、checkout、explicit thread 与 orderedReferences；新记录按首次请求来源匹配，因此绑定后原请求仍幂等，第二来源 ID 会冲突。
- continue_existing 只接受原 canonical session.originMeta 与 ConnectedConversation 一致的完整外部身份；没有证据或 thread 不符，在领取副作用前明确 unsupported。它只走原 continueExisting，不以 createSession 冒充恢复。
- bind 回执必须匹配原已确认外部身份；新建返回已有 canonical 对话身份会拒绝绑定。原 SQLite CAS、事务、lease、原 hash 与 unknown 不重发逻辑保留。
- 原 compose 仅为 HostTransport 提供可选 HUABU_HOST_TIMEOUT_MS：合法正整数且最多 180 秒；缺省或非法仍为原 10 秒，不增加重试。
- 原 HostTransport.probe 只有成功列出 Host 会话且明确配置非空 spawn recipe 时，才声明 createSession 的 adapter_declaration；没有创建会话、没有 POST。Host 离线或无 recipe 继续 unknown。continue／attach 不放宽。
