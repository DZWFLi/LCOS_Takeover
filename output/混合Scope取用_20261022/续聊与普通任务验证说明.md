## 实际检查的行为

- 一个 Scope 引用完整带入两层集合、附注、已链接对话、Run 的指令／状态／已有产物、Workspace 工作集；保留同材料两个明确版本及循环回指，不混入未选附注或相机。
- 对话按分页完整读取，续聊覆盖 205 条；归档来源必须可核对。历史附件只有明确原 Revision 时才能读取，不能换用 Current。
- 缺成员、缺历史归档、归档 hash 不符、历史含不支持媒体、未匹配或未定版附件、二进制材料、超额度，均整体失败。
- 普通任务失败发生在原 manifest 写入与 Run 创建之前；成功只停在 `created`／`planned`，派发次数为 0。
- 续聊失败时不附加半份内容、不发送 prompt；已完整读取的内容在原 journal 内保留，重试不能换成更新正文。
- 已发送的同 messageId 不重复发送；重开 SQLite 后复用原 attachment，已确认附加事实不会被一次后续读取失败抹掉。
- 旧 SavedContextId 使用完整 Scope 读取；空 Presentation 不回退到范围全集。原 Artifact 明确版本、原 View、无 Scope 的原 Collection 及缺版本拒绝均保留。
- 聚合正文沿原 untrusted-context 包裹，成员正文的“保留／锁定”仍进入原 lockedElements。

## 受控边界

测试中的 Project／Receiver／Continuation journal，以及普通 manifest／Run／dispatch／Recipe 都经过真实 Core 类和 SQLite 所有者。异构 Scope 的成员图与对话分页来源是明确注册的受控读口；材料文件真实写入本工作区 `.runtime/`，按现有 Revision hash 校验。测试不声称这些受控图已是产品真实存储。

Host 与 ACP 逻辑使用原源码变换后的实际纯函数；没有连接或创建外部 provider 会话。实际 Host 启动编译与浏览器全过程仍以主任务证据为准。

## 本轮复现与修复

- 实际采用源码已有 Collection 扩展，最初按复制参照定位的 seam 拒绝构建。现变换识别实际版本并保留原 Collection／文件读取逻辑。
- 附加失败的未知结果按原 adapter 保留 `outcome_unknown`，没有为了测试改弱分类。
- 普通任务测试代理最初缺 getNote，已补测试适配器；产品源码未因此修改。
- 新 Scope JSON 最初让原“保留：品牌名”提取失效。已保留失败报告并由主任务修复原 lockedSource 输入，最终断言通过。

## 普通任务最终正文消费点核对

结论：完整 Scope 确实进入原 Core 生成的任务 prompt；没有在 manifest.references 的 Artifact 列表处被过滤掉。

RunRecipe 是原只读任务元数据投影，保存 contextManifestId 和有序引用，不是正文分发所有者。实际正文路径如下：

1. [RuntimeApplicationService.contextPrompt](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/runtime-application-service.ts:336>) 读取该 Run 已持久化 manifest 的 canonicalJson，交给原 compileContextPromptV1。
2. [renderItem](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/context-prompt-serializer.ts:90>) 无条件保留 orderedItem.content，不要求 Artifact ID；dynamicItems 保留没有 Artifact ID 的 Scope。SavedContext 则按原 stableItemIdentities 进入 stablePrefix。
3. [RuntimeAdapter.materialize](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/runtime-adapter.ts:603>) 使用同一原编译器，将完整 contextManifest 和 compiledContextPrompt 放入 runtime-input-pack，Bridge envelope 引用该 runtimeInputPackPath；没有只取 references。
4. [原 context-prompt HTTP 处理器](<E:/Codex 项目/LCOS夺舍计划_20261013/lcos/apps/local-core/src/routes/runs.ts:122>) 返回同一 runtimeApplication.contextPrompt 结果，供 executor 的原 get_lcos_run_context 读取。

只读查到的原 Bridge ACP 实现 [HuabuAcpRunExecutor._load_compiled_prompt](<E:/OS开发/LCOS_LIGHT_BRIDGE_ACP_RUN_20260920/tools/light-bridge-kernel/src/lcos_bridge/providers/huabu_acp.py:153>) 从 input pack 读取 compiledContextPrompt.stablePrefix 与 dynamicTail，并按现有 hash 校验后直接拼接；[execute](<E:/OS开发/LCOS_LIGHT_BRIDGE_ACP_RUN_20260920/tools/light-bridge-kernel/src/lcos_bridge/providers/huabu_acp.py:121>) 将这份完整字符串放入原 ACP prompt 的 text。没有把它转换成仅 Artifact 列表。

这是原 Bridge 源码消费约定的只读核查；本实验 Bridge 仍隔离，没有启动、派发或宣称完成真实 provider 执行。

已在原普通任务测试补 actual application.contextPrompt 断言：普通 Scope 的 dynamicTail 包含集合、附注、对话、Run 指令／产物、两版材料和锁定文字；未选 N2 不出现。SavedContext 的完整 Scope 进入 stablePrefix，dynamicTail 不重复它。

消费点核对阶段普通任务 7 组通过：[2026-10-22T13-13-59.759Z/report.json](普通任务原Manifest/2026-10-22T13-13-59.759Z/report.json)。同目录 created-run-manifest.json 增加实际 compiledContextPrompt，便于读回整份最终输入。
