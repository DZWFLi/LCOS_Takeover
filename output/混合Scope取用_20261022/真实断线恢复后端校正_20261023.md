## 修复了哪些真实缺口

### Host 没 appId 时读不到 owner

原 daemon hello 没有填写 sessionProfile.appId，原 Host 却只按该字段找线程，因此真实在线连接可能只返回 transport ID，缺少 native 与 thread。

现在原 AcpAgentClient 只读暴露其原 connection 的 transport ID；原 registry 按 exact agentlet／transport／当前 connection 对象唯一查找原 owner。原 projectSession 从该 owner 投影 native 与 thread。缺失、关闭、多个 owner 或 appId 冲突时不猜身份。

没有另建 owner、映射、数据库或 API。

### 断线了，Core 仍显示能发送

原 canSend 只读 journal bind 与全局发送声明；它不能证明目标仍在线。

现在原 CollaborationProjection 将具体目标传给原 compose 的只读 probe，使用同一个 HostTransport 每次读取该原目标，核对当前 native／transport／thread 与连接状态。断线或不一致时只降该目标 canSend；可信原连接的 canResume 保留。界面原因只显示“会话已断开，请重新连接”等简洁文案，不带 Host、namespace、ID 或原始异常。

### 同 ID 新桥误用旧 client

原 LiveAgentletConnection 断开时，旧 ACP client.isClosed 可能尚未同步。仅比较 ID 会把旧 client 当成新桥 owner。

现在原 client.isConnectedTo 检查同一个 connection 对象、connected 状态和未关闭。原 ensureAcpSession 在原 handle 失效时关闭旧 client，再进入既有 priorSessionId 恢复；原 spawn cache 也只复用相同 connection 对象。同 ID 换桥会重新经过原 prior 恢复端口，不能当成缓存命中。

原 daemon 仍优先 session/resume，必要时 session/load；找不到原 native 就明确失败，不 fallback session/new。
