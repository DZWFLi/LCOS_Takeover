# 真实 Host → Core 回执只读核查（2026-10-23）

结论：本轮普通续聊与整份 Scope 发送通过原 Host HTTP 响应回到 Core，不依赖 Core 回调。真实启动前先接对 Host token、agentlet、spawn recipe 与 namespace 即可；不能把“配置了 Core callback”当作普通续聊已成功。

## 启动必需条件

- Host 56321 与 Core 56311 为两套 loopback origin。Core 应使用 Host 的 HUABU_HOST_URL／HUABU_HOST_TOKEN／HUABU_AGENTLET_ID／HUABU_AGENTLET_SPAWN_COMMAND／HUABU_AGENTLET_SPAWN_CWD／HUABU_HOST_TIMEOUT_MS。
- 目前 Host token 的工作区路径为 .runtime/isolated-live-continuation-host-20261023/connection-token.json；结构为 { connectionToken: string }。Host launcher 私下赋给 HUABU_CONNECTION_TOKEN，Core 使用同一值作为 HUABU_HOST_TOKEN。此报告没有读取或输出 token 值。
- Core 原端口每次启动可能变化。GET http://127.0.0.1:56311/api/surface-core/status 的 data.core.origin 是当前原 Core origin；只读核查时为 http://127.0.0.1:64015。不要硬编码旧端口。
- 当前 facade 与 runtime-composition 没给 createLocalCoreServer 配 apiToken，因此没有“现成 Core API token 文件”可安全取用。Host token 与 Core API token 是不同身份，不能互相冒充。

## 哪种请求才需要回调

原 continuation-transport.route.ts 只有带 runCorrelation 的 ACP permission_request 才调用 forwardAcpPermissionRequestToCore，发送到原 Core /runtime/provider-events，并在 Host 要求 LCOS_CORE_URL 与 LOCAL_CORE_API_TOKEN 非空。

普通 continuation/create、continue、attach、prompt 的实际回执直接沿原 Core → Host HTTP 请求返回。普通续聊没有 runCorrelation，不需要上述回调配置。

若后续接 Run permission，LCOS_CORE_URL 应指向 status 读到的原 ephemeral Core origin；56311 facade 没开放 /runtime/provider-events。token 还需要沿原 Core apiToken 配置对齐。当前 Core 未配置 apiToken，原 server 不核对 Bearer；这不能被写成“已经配好了认证回调”。

## Qwen 的嵌入上下文识别

只读取工作区安装的程序，不读账户 profile：

1. Qwen chunks/acpAgent-5XER3TGL.js 的 initialize 返回 agentCapabilities.promptCapabilities.embeddedContext: true，同时声明 loadSession 与 resume。
2. 实际使用的原 daemon dist/session-bootstrap.js 保留完整 initializeResult；dist/ws-client.js 将其放进 sessionProfile.session。
3. 原 ACP session.ts 的 seedFromRecord 读取该声明；Host supportsEmbeddedContext 精确检查 agentCapabilities.promptCapabilities.embeddedContext === true。

静态链路兼容；仍要实际 live owner 的初始化结果确认，不能把程序声明当成已经发成功。

## 运行时注意

- attach/send 的原 Adapter 成功 receipt 包含 provider、agentletId、externalSessionId、transportSessionId、threadId，但没有 runtimeScope 字段；create/continue receipt 才有。验证脚本不能强求不存在的字段，也不能给回执补造值。sendPrompt 入参实际仍带 runtimeScope。
- Host owner 按 exact agentlet/thread/native session 绑定；Scope attach 必须存在该 live owner 且支持 embeddedContext，不能只凭 Host 在线放行。
- 原 daemon bootstrap 每步默认 90 秒；本轮 Host 与 GUI 的显式较长超时仍要保持对齐。超时后按原 unknown 核对，不重新创建或发送。
- 底层 ACP client 无 notifier 时有旧自动选择行为，但本轮实际 continuation wrapper 会提供默认 notifier 并明确取消权限请求；普通续聊实际按 fail-closed 执行。
- 本轮只做源码、程序包与端口只读核查，没有启动服务、没有创建会话、没有发模型、没有修改原 OS 或私人账户。
