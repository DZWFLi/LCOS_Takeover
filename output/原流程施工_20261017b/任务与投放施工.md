# 任务、会话与确版投放施工

结论：任务、会话的二跳 caller 已接同一原右栏；材料投放已走真实 Core View → Workspace membership → 原投影 producer → 原 O8 发布读回。完整迁移还没结束，原标题/历史菜单、任务行和部分操作内容仍偏离原 TapNow。

本报告只覆盖本 agent 的施工。第三工作区源码可写；原 GN2、原 0.1、厂商 reference 只读。未执行模型、未派发任务、未改 SQLite、未触碰未知进程。

## 投放的真实边界

- 只接原图和文本载体。PDF、音视频、3D 没伪装成文本节点；原查看能力保留，投放缺口仍登记。
- 历史 Revision 没 View 时由 Core 创建额外确版 View。未用 Artifact Current 顶替；源文件不可用、元数据版本不符、草稿、归档或来源 View 改指向都拒绝。
- O8 回填保留当前与历史帧已有节点、编辑、几何、选择、连接，不用整份 GET 覆盖现场，不调用 addNodes 或 URL 导入。
- 新普通材料仍是显式 Core 操作的 canonical 回填；**尚未接一次原 Canvas Undo 同步撤销新 Core View/membership**。不能写成 Drop/Undo 已全部拉齐。
- 正常重复点击曾一次被“读取期间现场或编辑变化”拒绝；旧版重跑通过。client 比较了 ReactFlow `measured`，现已按原桥 editableState 去掉该渲染测量字段，真实位置/尺寸/样式/正文保护仍有测试；最新 loss 场景重复按钮幂等通过。
- **可见区无完整空位时，目前静默采用最小重叠候选，仍会压旧卡或 dock。** 已保留两个失败报告，不能用有空位的通过覆盖。后续应接原空间放置/定位流程，给用户可恢复的结果；本批未继续临时扩算法。
- 生产侧如在 View/membership 成功、spatial producer 未完成时断开，GET 会报告 partial，client 不擅自重写；显式修复部分回执的完整用户流程仍需后续接入。

## 仍偏离原 TapNow 的会话/任务项

| 项 | 原入口/页面/操作/返回 | 当前偏离 | 应接位置与保留能力 |
| --- | --- | --- | --- |
| 标题选择与会话历史 | 原 `wM` 标题与历史按钮 → `xM` 历史列表 → 选会话 → 同右栏返回消息 | `native-chat-ui.tsx:289` 的自写 header/details 取代了原布局/菜单；是用了原框架，并未融合原标题流程 | 受控抽取原 `wM`/`xM` view，列表投影 Core 会话；保留选择、空态、加载、返回和原焦点行为，不挂厂商云 hooks |
| 新会话 | 原历史/标题区的新建动作 → 新对话空态/输入 → 正常回历史 | 当前“画布助手”只切换 UI 地址、关闭旧 Composer 后打开 delegate 输入，不是原新会话动作的明确映射 | 先核对 Core 新会话与发送语义，再委托原动作；缺命令应直说，不能点击后假报创建 |
| 更多菜单 | 原 `wM` 菜单 → 原菜单操作 → 原消息页 | `native-chat-ui.tsx:297` 仍是 HTML details，自写刷新和放到画布；焦点/键盘/关闭层级尚未替换为原菜单 | 使用原 menu/dropdown owner，仅把准确 Core 回调放动作槽；保留刷新与真会话投影，不以移除能力当融合 |
| 任务入口和任务行 | 原右栏标题工具区 → 原列表/行布局 → 详情 → 原返回 | 当前额外 ClipboardList 按钮 + `NativeRunList` 自写 oreo 行/重新读取；功能可用不等于原排版融合 | 复用原受控 header/list row/content slot，Core list/controller 继续保留；逐项核对原是否有对应任务列表，不能杜撰原页面 |
| 任务详情 | 原右栏受控内容 → 详情/产物/材料 → 返回任务或会话 | 现在消除了整页 GN2 RunWorkViewBody，但 `NativeTaskDetail` 仍有自写 details/操作组，尚未逐项对齐原行密度/边距/焦点 | 保留真实 RunReview/decision/retry/CAS/unknown owner，再迁原受控布局；精确产物 candidate draftRevisionId 不可降为 Current |
| 等待输入/结果/恢复内容 | 原消息单滚动区内的活动/操作内容 → 回消息 | 当前已用单个原 U5，活动保持 timeline 顺序，但 WaitingInputSection、ArtifactReturnSection、RecoverySection 仍沿 GN2 内容实现 | 不拆成多个滚动 owner；逐项迁原活动/操作外观，保持等待输入、审查和恢复全部真实能力 |
| 停止提示 | 原消息区停止入口 → 一层确认/未知恢复 → 原会话 | 本批补安全流程，确认外观仍局部自写 | 后续以原 transient/dialog view 承载同一 handler；不可删新确认或自动重发未知 cancel |
| 会话放到画布 | 原会话菜单 → 投放 → 原画布/消息 | 已有真实 Conversation producer/O8；未知结果暂提示刷新核对，未做普通材料这一套明确只读恢复动作 | 复用原菜单和确切会话身份，补完整 readonly 核对；不要重复 create/绑定 |
| 任务输入中的内部默认标题 | 原材料/文字行 → 阅读内容 → 返回 | 本次真GUI见 `Note note-feedback-view`、`Note note-project-mvp-boundary`。来自 Core manifest 自动标题（`context-manifest-service.ts:341/345`），TaskDetail 原样展示 | 只在 view 投影中把已确认的自动标题转为有内容线索的笔记名称，正文和真实 identity 保留；不能删笔记掩饰披露 |

这些是剩余布局/流程项，不宣称都是已复现 bug；原功能的精确视觉 owner 仍需逐项拆解后施工。
